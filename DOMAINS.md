# Домены редиректора: подготовка, переключение, вывод из оборота

Памятка по разделу **Настройки → Домен редиректора** в панели.

Главное, из чего всё следует: **рефка запекается в сайт при его создании**.
Поменяв домен в панели, ты меняешь только то, какие ссылки панель отдаёт для
новых сайтов. Уже созданные сайты держат ту ссылку, что была у них при
генерации, и живут, пока жив их домен. Поэтому домены не «меняются», а
**накапливаются**: в любой момент в работе несколько, и по каждому идёт свой
трафик.

---

## 1. Подготовка домена заранее

Домен готовится **до** того, как понадобится. Смысл пула в том, чтобы в нужный
момент осталось нажать одну кнопку, а не искать свободный домен и настраивать
DNS в спешке.

1. **Завести зону в Cloudflare** — в том же аккаунте, где остальные: иначе на
   него нельзя будет повесить воркер, когда он выйдет из оборота.
2. **A-запись на сервер**, проксированная (оранжевое облако):
   `A  @  135.181.228.60  (Proxied)`
   Плюс `A  www  135.181.228.60  (Proxied)`, если нужен и `www`.
3. **SSL/TLS → Full.** Режим «Full (strict)» потребует валидный сертификат на
   origin; «Flexible» ломает https между Cloudflare и сервером.
4. **Проверить, что домен отвечает** — до добавления в пул:

```
curl -s -o /dev/null -D - "https://НОВЫЙ-ДОМЕН/go/dorgen_engine?s=proverka.test/ru" | grep -Ei "^HTTP/|^location:"
```

Ожидается `302` и `location` на оффер. Если `404` — не доехал `.htaccess` или
слаг не существует; если `521`/`522` — не отвечает origin; если ошибка
сертификата — не тот режим SSL.

5. **Добавить в пул**: Настройки → Пул доменов → поле внизу → «Добавить в пул».
   Можно вставить хоть `https://domain.top/go/` — сохранится `domain.top`.

Домен лежит в пуле без трафика, в колонке «Состояние» будет «мало данных» —
это нормально.

## 2. Переключение на другой домен

Кнопка **«Сделать текущим»** в строке домена. Что происходит:

- панель начинает отдавать рефки на этом домене (`Выгрузить рефки (CSV)`,
  раздел «Кампании», блок с примером ссылки);
- записывается момент переключения — по нему панель потом проверит, что новый
  домен начал получать трафик;
- всё остальное не меняется: кампании, офферы, преленды, постбеки.

**Переключение само по себе ничего не переносит.** Чтобы новые сайты пошли на
новый домен, ссылку надо отдать дор-движку:

- либо **⬇ CSV** в строке домена → список `слаг → ссылка` → в движок;
- либо скрипт `tools/smena-refok.js` по брендам: `OLD` — домен, с которого
  уходишь, `NEW` — новый. Прогнать по всем панелям движка, где есть бренды.

Через час загляни в пул: у нового домена в «Сейчас/час» должны появиться клики.
Если их ноль, панель прямо напишет, что ссылки, похоже, не доехали до движка.

---

## 3. Как читать мониторинг

| колонка | что показывает |
|---|---|
| **Клики (7 дней)** | сколько живых кликов пришло на этот домен за неделю |
| **Сейчас/час** | клики за последний час |
| **Обычно/час** | средний час этого же домена за неделю |
| **Состояние** | сравнение двух предыдущих колонок |

Состояния:

- **ок** — последний час не ниже 70% от обычного;
- **проседает** — ниже 70%;
- **просел** — ниже 40%;
- **молчит** — за час ни одного клика при том, что раньше трафик был;
- **мало данных** — обычный час меньше 5 кликов, сравнивать нечего.

Пороги грубые намеренно: ночью трафик падает у всех доменов сразу, и это тоже
даст «проседает». Поэтому состояние — это повод посмотреть, а не команда
переключаться. Если просел **один** домен, а остальные в норме — дело в нём.
Если просели все — это общий спад трафика.

## 4. Вывод домена из оборота

Домен, который перестал приносить трафик, убирается кнопкой **«убрать»** в его
строке. Что надо знать:

- **текущий домен убрать нельзя** — сначала переключись на другой. Иначе панель
  осталась бы без домена для рефок;
- удаление из пула **не трогает сайты**. Те, у кого в рефке запечён этот домен,
  продолжают на него ходить. Пул — это список для панели, а не настройка сайтов;
- поэтому **не убирай домен, пока по нему идут клики**. Пока строка не
  обнулилась, это твоя единственная видимость: сколько трафика ещё завязано на
  этот домен и сколько ты потеряешь, если погасишь его совсем.

Порядок вывода:

1. переключиться на следующий домен и раздать новые рефки движку;
2. старый домен оставить **живым** — сайты на нём работают;
3. по желанию повесить на него `cloudflare/worker-redirector.js` с переменной
   `TARGET` = текущий домен и маршрутом `старый-домен/go/*`: тогда переходы со
   старых сайтов доедут до живого домена и сохранят статистику. Маршрут именно
   `/go/*` — под `/*` попадёт `postback.php`, и постбеки начнут теряться;
4. когда «Клики (7 дней)» по нему дойдут до нуля — убрать из пула и гасить
   домен совсем.

---

## 5. Чего делать не надо

- **Не удалять зону домена в Cloudflare, пока по нему идёт трафик.** Это
  мгновенно убивает все сайты, где он запечён.
- **Не вешать воркер на `/*`.** Только `/go/*`: постбеки партнёрок редиректить
  нельзя, они приходят один раз.
- **Не менять домен панели вместе с доменом рефок.** Панель, постбеки и API
  могут жить на своём адресе сколько угодно — он в ссылках на сайтах не
  участвует. Чем реже меняется адрес постбека, тем меньше поводов трогать
  кабинеты партнёрок.
- **Не удалять домен из пула «чтобы не мешался».** Пропадёт строка мониторинга,
  и ты перестанешь видеть его трафик.

```
[ ] новый домен: зона, A-запись проксированная, SSL Full
[ ] curl на /go/СЛАГ отдаёт 302
[ ] добавлен в пул
[ ] «Сделать текущим»
[ ] CSV рефок выгружен / smena-refok.js прогнан по брендам
[ ] через час: «Сейчас/час» по новому домену не ноль
[ ] на старый домен (при необходимости) повешен worker-redirector, маршрут /go/*
[ ] старый домен остаётся в пуле, пока его клики не обнулятся
```
