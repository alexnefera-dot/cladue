# Запуск на VPS (работает 24/7, без проблемы «сна»)

Ставим инструмент фоновой службой на ваш Linux-сервер. Он крутится постоянно,
сам поднимается после перезагрузки, а вы открываете интерфейс со своего
компьютера через защищённый SSH-туннель. **Наружу на домен ничего не
выставляется** — ваш API-ключ xmlstock остаётся закрытым.

## 1. Залить папку на сервер

С вашего мака (замените `ПОЛЬЗОВАТЕЛЬ@IP` на данные VPS):

```bash
cd ~/Downloads
scp -r xmlstock-serp ПОЛЬЗОВАТЕЛЬ@IP:~/
```

Или через файловый менеджер панели — залейте папку `xmlstock-serp` в домашний
каталог. Папки `.venv` и `output` заливать не нужно.

## 2. Установить службу (одна команда на сервере)

Зайдите на сервер по SSH и выполните:

```bash
ssh ПОЛЬЗОВАТЕЛЬ@IP
cd ~/xmlstock-serp
bash deploy/setup.sh
```

Скрипт сам создаст окружение, поставит зависимости и зарегистрирует службу
`xmlstock-serp` (спросит пароль sudo для установки службы). Порт по умолчанию —
`5050`, только на `127.0.0.1`. Свой порт: `PORT=8090 bash deploy/setup.sh`.

## 3. Открыть интерфейс у себя

На своём маке (окно не закрывать, пока пользуетесь):

```bash
ssh -N -L 5050:localhost:5050 ПОЛЬЗОВАТЕЛЬ@IP
```

Затем в браузере: **http://localhost:5050**

Мониторинг при этом идёт на сервере независимо от того, открыт туннель или нет —
можно закрыть браузер и мак, прогон продолжится. Загляните позже, чтобы забрать
срезы (кнопка «скачать все .zip») — они лежат в `~/xmlstock-serp/output/`.

## Управление службой

```bash
sudo systemctl status  xmlstock-serp     # состояние
sudo systemctl restart xmlstock-serp     # перезапустить
sudo systemctl stop    xmlstock-serp     # остановить
journalctl -u xmlstock-serp -f           # живые логи
```

> После перезапуска службы идущий мониторинг придётся запустить заново из
> интерфейса — но уже снятые срезы в `output/` и кэш дат регистрации
> (`output/whois_cache.json`) сохраняются, так что RDAP по known-доменам
> повторно не дёргается.

## Публичный адрес на поддомене (ISPmanager)

Если хотите не туннель, а нормальный URL `https://monitor.вашдомен.ru` — вот
порядок. Сначала **включаем пароль** (адрес публичный → его найдут боты по
CT-логам, а внутри ваш API-ключ), потом отдаём поддомен в прокси.

### 1. Включить пароль у приложения

Пароль встроен в приложение и включается переменной окружения — nginx для этого
трогать не нужно. Перезапустите установку с паролем:

```bash
cd ~/xmlstock-serp
AUTH_PASS='придумайте-длинный-пароль' bash deploy/setup.sh
```

(логин по умолчанию `admin`; свой — `AUTH_USER=имя AUTH_PASS=... bash deploy/setup.sh`).
Теперь на `127.0.0.1:5050` приложение спрашивает логин/пароль.

### 2. Поддомен + SSL в ISPmanager

1. **WWW → WWW-домены → Создать**: `monitor.вашдомен.ru` (у существующего домена
   заведите A-запись/поддомен на этот сервер — ISPmanager обычно делает сам).
2. **SSL-сертификаты → Let's Encrypt** → выберите `monitor.вашдомен.ru` → выпустить.
   Дождитесь «действителен» и включите редирект на HTTPS.

### 3. Проксирование на приложение

В ISPmanager 6: **WWW-домены → выберите `monitor.вашдомен.ru` → «Изменить»** →
включите **«Проксирование» (Proxying)** и укажите адрес:

```
http://127.0.0.1:5050
```

Сохраните. Готово — откройте `https://monitor.вашдомен.ru`, введите логин/пароль.

> Если пункта «Проксирование» в вашей версии панели нет — не редактируйте
> сгенерированный конфиг напрямую (ISPmanager перезапишет). Пришлите мне версию
> ISPmanager (или скрин настроек домена), и я дам файл для
> `/etc/nginx/vhosts-resources/monitor.вашдомен.ru/*.conf` — эту папку панель
> подключает и не затирает.

### Сменить/убрать пароль потом

```bash
AUTH_PASS='новый' bash deploy/setup.sh      # сменить
sudo systemctl edit --full xmlstock-serp    # убрать строки Environment=AUTH_* и сохранить
sudo systemctl restart xmlstock-serp
```
