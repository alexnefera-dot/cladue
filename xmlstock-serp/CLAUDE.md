# CLAUDE.md — xmlstock-serp

Контекст проекта для Claude Code (и любого разработчика). Прочитай это целиком, прежде чем менять код — здесь вся «история» решений, чтобы не переоткрывать уже понятое и не повторять ошибки.

---

## 1. Что это за проект

**xmlstock-serp** — локальный инструмент (веб-панель) для анализа сетей казино-**дорвеев** в рунете. Владелец — **не технарь**, работает по пошаговым инструкциям. Запускает **локально на macOS**, также деплоит на **свой VPS** (скрипты и инструкция — в `deploy/`, реквизиты сервера даёт владелец отдельно).

Назначение: собирать позиции дорвеев в Яндексе, проверять индексацию, редиректы, живость доменов, WHOIS/возраст, и — ключевое в последнее время — **проверять блокировку доменов в РФ** (ТСПУ/DPI).

**Стек:** один файл бэкенда `app.py` (Flask, ~200 КБ, ~210 функций, ~60 роутов) + один шаблон `templates/index.html` (ванильный JS, ~137 КБ, поллинг прогресса). Без сборки, без фронт-фреймворков.

## 2. Как запустить

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt          # Flask, requests, openpyxl
# для браузерного режима редиректов (Playwright) — один раз:
.venv/bin/pip install playwright && .venv/bin/python -m playwright install chromium
.venv/bin/python app.py
```
Откроется в браузере сам; по умолчанию порт **5050** (на macOS 5000 занят AirPlay), есть автоподбор свободного порта (`_free_port`). Windows — пути `.venv\Scripts\...`.

Переменные окружения: `NO_BROWSER=1` — не открывать браузер при старте (для тестов); `PW_CHROMIUM_PATH` — путь к Chromium для Playwright.

## 3. Архитектура и соглашения

- **Весь бэкенд в `app.py`.** Паттерн на каждую вкладку: in-memory стор задач (`JOBS`/`Lock`/`Event`/`Thread`), роуты `run` (старт фонового потока) → `status/<job_id>` (поллинг) → `cancel` → `download` (XLSX/CSV через openpyxl/csv). Фронт раз в 1–2 c дёргает `status`.
- **`APP_BUILD`** — строка-маркер сборки (вверху `app.py`, рядом с `app = Flask(...)`), отдаётся в `/api/version` и показывается в подвале страницы. **Правило: меняешь `app.py` — обнови `APP_BUILD`** (короткая метка на русском). Это единственный способ для владельца убедиться, что он перезапустил сервер с новой версией. `templates/index.html` подхватывается без перезапуска (TEMPLATES_AUTO_RELOAD), а `app.py` — только перезапуском.
- **`output/`** (в `.gitignore`) — кэши и история на диске: `whois_full_cache.json`, `launches.json`, `rkn_domains.txt`, `block_snapshot.json` и выгрузки. Переживают перезапуск. При переносе проекта код едет без них (кэши пересоздаются), историю копировать вручную при желании.
- **UI — на русском.** Тексты, подсказки, вердикты — по-русски. Владелец читает подвал («сборка: …») и колонки.
- **Держим single-file** `app.py` + single `index.html`. Не раздроблять без веской причины.
- **Тесты:** мок `requests`/`socket`/`ssl` + Playwright (Chromium из `/opt/pw-browsers/chromium-*/chrome-linux*/chrome` или `PW_CHROMIUM_PATH`). Перед коммитом: `python3 -c "import ast; ast.parse(open('app.py').read())"` + мок-прогон затронутой функции; для фронта — Playwright со слушателем `pageerror` (JS-ошибки).

Общие хелперы: `url_host`, `registrable_domain` (eTLD+1, эвристика + `_TWO_LEVEL_SLD`), `is_subdomain`, `clean_host`, `_split_unique`, `clamp`.

## 5. Блок-чек РФ — доменные знания (критично, не переоткрывать)

**Как РФ блокирует казино-домены:** DPI на оборудовании **ТСПУ** у операторов смотрит поле **SNI** в TLS ClientHello (имя домена открытым текстом) и, если имя в списке, **рвёт (TLS reset) или тихо дропает (таймаут)** соединение. **Блок по ИМЕНИ домена, не по IP** — один IP (Cloudflare) отдаёт и заблокированные, и рабочие домены; менять IP/хостинг бесполезно, спасает только новое имя. Доказано: на одном IP одновременно 🔴 и 🟢 домены; при ротации IP вердикт держится.

**Блокировка часто ВЕРОЯТНОСТНАЯ** — рвётся не каждое соединение, а часть (60–90%). Один заход = монетка. Поэтому:

- Проверка идёт **через РФ-прокси** (иначе ТСПУ на пути нет и всё «доступно»). Прокси в настройках вкладки.
- **Мульти-прогон** (поле «Прогонов», 1–5): каждый домен гоняется N раз, вердикт по большинству + «блок X/N» (`_aggregate_passes`). Крайности (0/N, N/N) стабильны, середина флапает.
- **Ханипот прокси** (`_proxy_rf_warn`, `_PROXY_HONEYPOT` = rutracker/rutor/nnmclub): если заведомо заблокированные сайты открываются через прокси — прокси **не за ТСПУ** (дата-центр/утечка), показываем крупный баннер «верить нельзя». Контрольный признак плохого прокси: домен из реестра РКН «открывается».
- **База (прямой заход)** `_base_probe`/`_annotate_base`: если через РФ не открылось — пробуем напрямую (без прокси, с текущего канала). Жив напрямую, но режется в РФ → подтверждённый бан; мёртв и там и там → вердикт `dead` (не РФ-блок). Колонка «База».
- **Дифф прогонов** `_compute_changes` (`block_snapshot.json`): после каждого полного прогона показывает, что изменилось — 🔴 новые баны / 🟢 выпали в рабочие / ⚫ умерли. Сравнение по статусу banned/working/dead; odd/cancel не учитываются.

**Движок:** `check_block` (диспетчер) → `_block_via_proxy` (через прокси) или `_check_block_local` (локально). Вердикты: `ok` / `sni` (DPI: reset или silent-drop) / `ip` / `page` (заглушка оператора) / `dns` / `dead` / `odd` (неясно/виноват прокси). Хелперы: `_doh_resolve` (глобальный IP через dns.google), `_proxy_control_ok` (нейтральный сайт через прокси — не винить прокси зря), `_tcp_ok`, `_tls_sni_ok` (нейтральный контрольный SNI `_NEUTRAL_SNI`), `_http_blockpage` (`_BLOCKPAGE_MARKERS`). Реестр РКН: `_rkn_load_list` качает `antizapret.prostovpn.org/domains-export.txt` (кэш сутки), `_rkn_registry` — локальная проверка; это **справка**, на вердикт НЕ влияет.

**ГЛАВНАЯ ГРАБЛЯ (уже чинили):** «доступен» — только чистый **2xx по https**. Если DPI рвёт https, нельзя падать на голый http и считать 403/любой ответ за 🟢 — это ложный зелёный. При срезанном https вердикт остаётся `sni`. 403/4xx/5xx по https (Cloudflare режет IP прокси/капча) → `odd`, а не зелёный.

## 6. Редирект-чекер — механика (критично)

Цель: показать **всю цепочку** редиректов дорвея, включая их **домен-редиректор** и финал.

- **HTTP-режим** (`resolve_redirect`): HTTP 3xx (requests сам, из `r.history`) + клиентские meta-refresh/простой JS (`find_client_redirect`, `_META_REFRESH_RE`, `_JS_LOC_RE`). Обфусцированный/таймерный JS **не разворачивает** — для него нужен браузер.
- **Браузерный режим** (`_browser_resolve`, Playwright): открывает в Chromium и **ждёт, пока URL замрёт** (`_settle_page`, quiet 3 c в пределах бюджета «Ожидание») — ловит ВСЮ цепочку, а не первый хоп. Все навигации главного фрейма пишутся через `_attach_nav`.
  - **Клик «Вход»/«Регистрация»** (`_try_click`, слова в `_CLICK_WORDS`): большинство дорвеев редиректят только по клику. Включён по умолчанию; срабатывает, только если сайт сам не редиректнул.
  - **Новая вкладка (popup):** клик часто открывает казино в новой вкладке — ловим через `page.on("popup")`, вешаем слушатель сразу, досматриваем её цепочку.
  - **chromewebdata** (`chrome-error://`) — это **НЕ домен**, а страница-ошибка Chromium: финальная навигация после редиректора упала. `_is_error_url` их фильтрует; `_attach_fail` (requestfailed) ловит реальный URL упавшей навигации — показываем его с пометкой «не загрузилось (гео/UA-защита)», финальный хоп жёлтый ⚠. Это не ошибка редиректа, «Редирект: да» сохраняется.
- Строка: `_redir_row` — `hops` (хосты по порядку), `hops_count`, `final_failed`, `note`. Фильтр «Только поддомены» (`only_subdomains`) по умолчанию ВКЛ — выкидывает корневые домены (нужно для дорвей-воркфлоу из «Сбора ТОП»); если список обычных доменов — показываем «пропущено N корневых» и просим снять галку.

## 7. Как добавлять фичи (чек-лист)

1. Бэкенд в `app.py`, фронт в `templates/index.html`, тексты на русском.
2. **Обнови `APP_BUILD`** на короткую метку.
3. Прогон долгих операций — фоновым потоком + поллинг статуса; XLSX/CSV в download.
4. Тесты: `ast.parse`; мок-прогон функции; для UI — Playwright + `pageerror`.
5. Коммить осмысленными сообщениями (Conventional Commits) в свой git-репозиторий.
6. Отдать владельцу оба файла и в 1–2 строки: что изменилось + «замени файлы, перезапусти, в подвале сборка …».
7. Владелец не технарь — объясняй кратко, по шагам, без жаргона; инструкции копипастом.

## 9. Журнал сборок (свежие → старые)

`финал-не-chromewebdata` (редирект: реальный упавший финал вместо chromewebdata) · `клик-вход-новая-вкладка` (клик Вход/Регистрация + popup) · `редиректор-вся-цепочка` (браузер ждёт всю цепочку) · `редирект-фильтр-видно` (видно пропуск корневых) · `цепочка-редиректов` (все хопы) · `дифф-прогонов` (изменения с прошлого прогона) · `ханипот-мультипрогон` (валидация прокси + N прогонов) · `строгий-вердикт` (403/http больше не «доступен») · `база-и-прокси` (колонка База) · `реестр-антизапрет` (список РКН с antizapret).

Главный вывод по блок-чеку для владельца: домены режет ТСПУ по SNI, часть — вероятностно; «в сервисах ок, а у юзеров нет» потому что проверять надо из РФ. Менять надо имя домена, не IP.
