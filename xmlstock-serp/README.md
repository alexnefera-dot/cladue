# XMLStock SERP — выгрузка ТОП выдачи и трекер позиций

Локальный инструмент с интерфейсом в браузере для работы с живой выдачей Яндекса
(и Google) через API [xmlstock.com](https://xmlstock.com). Три вкладки:

1. **Сбор ТОП** — вставляете пачку запросов (200–300 шт.), получаете
   **ТОП-N результатов по каждому ключу** и выгружаете в **XLSX / CSV**.
2. **Трекер позиций** — вводите ключи и свои домены (свои ключи под каждый домен),
   скрипт снимает выдачу несколько раз с интервалом и показывает **среднюю
   позицию** ваших сайтов; можно снимать Live и XML одновременно для сравнения.
3. **Индексация (site:)** — вводите список доменов, скрипт через `site:домен`
   собирает **все проиндексированные URL** каждого сайта и выгружает в XLSX / CSV.

Данные обрабатываются у вас на компьютере и отправляются только в API xmlstock.

---

## Возможности

**Вкладка «Сбор ТОП»**
- Пачка запросов разом, дубликаты убираются автоматически.
- ТОП-N (1–50) по каждому ключу: позиция, URL, заголовок, домен.
- Параллельные запросы + ретраи с экспоненциальной паузой при ошибках лимита.
- Прогресс в реальном времени, лента обработки, список ошибок, кнопка «Остановить».
- Выгрузка:
  - **XLSX** — два листа: `results` (по строке на результат) и `wide` (ключ + URL-ы в ряд);
  - **CSV** — `query;position;url;title;domain` (UTF-8 + BOM, открывается в Excel двойным кликом).

**Вкладка «Трекер позиций»**
- До ~10 ключей и список ваших доменов (можно с `www`/`https://`, поддомены засчитываются).
- N снятий выдачи с заданным интервалом (по умолчанию 10 раз раз в 4 мин).
- Глубина поиска топ-30/50/100 — чтобы находить позиции и за пределами 10-ки.
- По каждой паре ключ+домен: **средняя позиция** (по снятиям, где сайт найден),
  лучшая/худшая позиция, «нашли N/M» и позиции по каждому снятию.
- Живое обновление таблицы, обратный отсчёт до следующего снятия,
  переподключение после перезагрузки страницы, выгрузка XLSX/CSV.

**Вкладка «Индексация (site:)»**
- Список доменов; по каждому через оператор `site:` (или `host:`) собираются все
  URL из индекса Яндекса — с постраничным листанием (плоская выдача `mode=flat`).
- Показывает оценку Яндекса «найдено» и число реально собранных URL, есть
  предпросмотр списка и выгрузка **XLSX** (листы `urls` + `summary`) / **CSV**
  (`domain;url;title`).
- Автоматически использует **Яндекс.XML** (до 100 URL за запрос, всего до ~1000
  на домен — это лимит Яндекса).

## Установка

Нужен Python 3.9+.

```bash
cd xmlstock-serp
python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

```bash
python app.py
```

Откроется браузер на `http://127.0.0.1:5000` (если нет — откройте вручную).

## Как пользоваться

Сверху — общий блок доступа (User ID, API key, движок, регion), он используется
обеими вкладками. **User ID** и **API key** берутся в кабинете xmlstock (раздел API)
и сохраняются только в вашем браузере.

Выбор **движка**:
- `Яндекс` — путь `/yandex/xml/`. Живая выдача это будет или XML-лимиты,
  определяется тем, какие лимиты пополнены в вашем тарифе xmlstock;
- `Google` — путь `/google/xml/`;
- `Свой URL…` — если в вашем кабинете другой адрес эндпоинта, вставьте его точно.

### Вкладка «Сбор ТОП»

1. Задайте **регион** (`lr`, например `213` — Москва), при необходимости домен и устройство.
2. Вставьте запросы — по одному в строке.
3. Нажмите **«Запустить сбор»** и дождитесь завершения.
4. Скачайте **XLSX** или **CSV**.

### Вкладка «Трекер позиций»

1. Заполните **блоки «домен + его ключи»**: в каждом блоке один домен (можно
   `www`/`https://`, можно несколько через запятую) и его ключи — по одному в
   строке. Для двух проектов с разными семантиками нажмите «+ Добавить домен» и
   заполните второй блок. Каждый домен снимается **только по своим ключам**;
   одинаковые ключи между блоками запрашиваются один раз.
2. Настройте **глубину** (топ-30 по умолчанию), **число снятий**, **интервал**
   (в минутах или **часах**) и **устройство** (десктоп/мобайл — Live по умолчанию
   десктоп). Итоговое время прогона показывается под полями.
3. (опц.) Включите **«Снять Live и XML вместе»** — для каждого ключа снимется и
   живая выдача, и Яндекс.XML, в таблице появится колонка «Источник» для сравнения
   (запросов тратится ×2).
4. Нажмите **«Запустить трекер»**. Таблица обновляется вживую и сгруппирована по
   домену: по каждому ключу видно среднюю позицию, лучшую/худшую, «нашли N/M» и
   позиции по снятиям. Если выдача между снятиями не меняется — покажется
   подсказка (вероятно кеш xmlstock или стабильный топ; увеличьте интервал).
5. В любой момент можно скачать **XLSX/CSV** (даже по ходу прогона) или нажать «Остановить».

> Зачем несколько снятий: позиции в Яндекс.XML колеблются из-за рандомизации
> выдачи — среднее по нескольким снятиям даёт устойчивую оценку. Живая выдача
> (Live) стабильнее и может кешироваться сервисом, поэтому снимать её каждые
> несколько минут смысла мало — для динамики растягивайте интервал на **часы**
> (на практике 5–8 раз в день). Прогон идёт в фоне; можно закрыть вкладку и
> вернуться — страница переподключится к идущему трекеру.

> **Ошибки лимита (RPS).** Если xmlstock начинает отдавать ошибки лимита,
> уменьшите «Параллельно» (например до 2–3), а на «Сборе ТОП» — добавьте «Паузу»
> (0.2–0.5 сек) в блоке «Дополнительно».

## Про эндпоинт

У xmlstock **разные адреса** для живой выдачи (Live) и официального Яндекс.XML:

| Движок | URL | Особенности |
|--------|-----|-------------|
| Яндекс — живая выдача (Live) | `https://xmlstock.com/yandexlive/xml/` | как видит пользователь; **≈10 результатов на запрос** (за глубиной листаются страницы) |
| Яндекс — XML | `https://xmlstock.com/yandex/xml/` | официальный Яндекс.XML; до 100 за запрос; дешевле, но выдача может отличаться |
| Google — живая выдача | `https://xmlstock.com/googlelive/xml/` | живая выдача Google |
| Google — XML | `https://xmlstock.com/google/xml/` | Google XML |

> Что использовать — зависит от того, какие лимиты пополнены в вашем аккаунте
> xmlstock. Если адрес в кабинете отличается — выберите **«Свой URL…»** и вставьте точную ссылку.

Запрос формируется так:

```
{endpoint}?user=USER&key=KEY&query=ЗАПРОС
  &groupby=attr=d.mode=deep.groups-on-page=N.docs-in-group=1
  &lr=213&page=0
```

Для Live глубина набирается перелистыванием `page=0,1,2…` (по ~10 результатов на страницу).

Ответ разбирается как **Яндекс XML** (`response → results → grouping → group → doc →
url / title / domain`); есть запасной разбор JSON. Если у вашего тарифа адрес или
формат отличается — выберите **«Свой URL…»** и вставьте точную ссылку из кабинета.
