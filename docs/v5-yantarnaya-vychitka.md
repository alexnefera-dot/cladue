# Янтарная мастерская — комплект по двум чек-листам

Первый комплект, написанный по обоим спискам сразу: постраничному (пятнадцать
пунктов) и комплектному (шесть величин, которые складываются по семи файлам).
Оба печатает генератор задания перед каркасом, оба раскладывались на бумагу до
первой фразы.

**Маска:** янтарная мастерская, ракурс — янтарщик.
**Рефрен:** «веду по слою».
**Каркас главной:** восемь укрупнённых H2.
**Приёмка:** `profil-v5-B.json`, комплект принят, семь страниц из семи по 100 %.

---

## Что дал второй список

Прошлый комплект вывел шесть страниц из семи на 100 % с первого захода — и не
прошёл приёмку: шинглы 9,14 % при пороге 3,5 %, ссылок с главной 18 при норме
26–40, терминов 74 при 119, бренда 20 при 35. Все четыре величины постраничный
список не видит по устройству.

В этот раз они были выписаны до письма и попали в норму без единой правки:

| Комплектная величина | Прошлый комплект (после доводки) | Этот (сразу) |
|---|---|---|
| Шинглы с соседями | 9,14 % → чинилось переписыванием | **2,85 %** |
| Объём суммой | 85 % → доводился | **99 %** |
| Профильные термины | 53 % → доводились | **91 %** |
| Внутренние ссылки | 69 % → доводились | **100 %** |
| Бренд латиницей суммой | 20 → доводился до 37 | **37** |
| Опорные формулы на главной | 21 при потолке 16 | **17** |

Первая строка — главная. Формы разделов были расписаны до письма и разведены
против соседних комплектов: таблица отчислений в приз, эмодзи-список признаков
плюс нумерованная процедура, разбор секунд прозой, таблица трёх граф анкеты,
трёхчастка входа прозой, таблица условий подарка, таблица отбоя заявки.
Совпадение с ближайшим соседом вышло 2,85 % без единой переписанной строки.

## Где список всё-таки не спас

Одна страница из семи потребовала настоящей переработки — `slots`, 37/43 на
первом замере. Оба промаха ровно там, где чек-лист **был напечатан, а я его
недочитал**:

- **пункт 15, особое для типа.** На `slots` рынок называет игры поимённо: цель
  `games_named` 3, `names_uniq` 3, а доля H3, начатых вопросительным словом, —
  ноль. Я написал страницу без единого названия и с тремя вопросительными
  заголовками из пяти.
- **жанровое правило «таблица ОДНА».** Я поставил две — сравнение версий и
  закрытие «стоит / не стоит», — и получил шесть строк данных при норме три.
  Пришлось разбирать сравнение версий прозой, а таблицу закрытия расширять с
  двух колонок до трёх ради `table_cols`.

Вывод простой и неприятный: список работает, только если читать его целиком, а
не первые четырнадцать пунктов.

## Мелочи, которые стоили по одному проходу

- **Водность против прилагательных.** На `registracia` первая правка сбила
  водность с 36,1 до нормы, но подняла прилагательные до 13,5 при потолке 12,25.
  Эти два поля тянут в разные стороны: служебные слова убираются
  содержательными, и половина содержательных оказывается определениями.
- **Тошнота на короткой странице.** `bonus` на 390 словах дала 28,7 при потолке
  21,75 — четыре повтора «подарок» и «ставка» на такой длине уже перебор.
  Чинилось синонимами ниши: бонус, вейджер, вращение, потолок спина.
- **Раздел, открытый абзацем.** Все восемь H2 главной открывались абзацем,
  100 % при норме 66,7–83,3. Два раздела переставлены так, чтобы начинаться
  списком и таблицей.
- **Повтор роли в H3.** Слово «Риски:» стояло первым на пяти внутренних из
  шести — 60,0 % при потолке 60. Роли переименованы (цена отказа, ловушка,
  умолчание, оборот, обрыв, исключение), стало 20,0 %.
