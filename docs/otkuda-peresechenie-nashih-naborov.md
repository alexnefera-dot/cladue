# Откуда берётся пересечение наших наборов

Замер: сорок последних наборов (711–750), страницы всех двенадцати типов,
та же чистка и те же шестисловные шинглы, что считает приёмка
(`engine/instrumenty/shingle.php`). Пересечение — доля от меньшей страницы,
как в `priyomka-v5.php:311`.

## Приёмка смотрит не на среднее, а на худшего соседа

| тип | пересечение, медиана по всем парам | худшая пара |
|---|---|---|
| main | 14.5 % | 24.0 % |
| bonus | 4.5 % | 17.1 % |
| registracia | 4.6 % | 16.8 % |
| app | 5.1 % | 18.9 % |
| zerkalo | 4.4 % | 18.3 % |
| vhod | 4.9 % | 14.1 % |
| slots | 4.0 % | 11.2 % |

Порог у bonus — 17.4, у остальных коротких типов 18.5–20.5. Медиана втрое
ниже порога у всех типов, кроме main. Валит набор не общий уровень похожести,
а одна пара: приёмка берёт максимум по соседям, и достаточно одного соседа,
с которым страница сошлась.

## Три пятых совпавшего текста худших пар — блок FAQ

Разбор совпавших шинглов по зонам страницы (зачин до первого h2, тело каждого
раздела по своему h2, блок «Честные ответы на вопросы»), медиана по двенадцати
худшим парам каждого типа:

| тип | FAQ | разделы | зачин | общих вопросов у худших пар |
|---|---|---|---|---|
| zerkalo | 64.1 % | 36.5 % | 0 % | 1.6 |
| app | 62.1 % | 36.7 % | 0 % | 1.6 |
| bonus | 60.5 % | 39.5 % | 0 % | 1.4 |
| promo | 60.0 % | 34.6 % | 0 % | 2.6 |
| registracia | 59.6 % | 40.4 % | 0 % | 1.7 |
| slots | 49.0 % | 49.9 % | 0.6 % | 2.1 |
| news | 39.8 % | 59.7 % | 0 % | 1.7 |
| vhod | 37.6 % | 59.2 % | 0 % | 1.2 |
| info | 24.1 % | 75.1 % | 0 % | 1.3 |
| main | 21.0 % | 76.4 % | 0 % | 1.4 |

Верхняя пара bonus разобрана до конца: 731 ↔ 744, пересечение 17.1 %,
171 общий шингл. Из них **161 (94.2 %) — блок FAQ**, десять — раздел
«Промокоды на сегодня», ноль — остальные четыре раздела и зачин.

Среднее число общих вопросов FAQ по *всем* парам bonus — 0.27, и пар с двумя
и более общими вопросами всего 5 %. Но именно эти 5 % и становятся «худшим
соседом»: пара с двумя общими вопросами несёт 120–160 общих шинглов на
тысячу, то есть сразу 12–16 % пересечения, а приёмке больше ничего и не надо.

Пара FAQ — это вопрос плюс ответ на 60–100 слов. Одна такая пара весит как
десяток-полтора фраз прозы. Поэтому совпадение двух пар из пяти перевешивает
всё остальное содержание страницы.

## Зачин до первого h2 не повторяется вовсе

Ноль во всех строках таблицы — не округление. Зачин собирается из текстов h2
самой страницы (`v5ZachinStranicy`), а набор разделов у двух наборов разный,
поэтому дословных шестисловных совпадений он не даёт.

## Состав разделов пересечением почти не управляет

Пересечение против числа общих H2 у страниц bonus (все 780 пар сорока наборов):

| общих H2 | пар | пересечение, медиана | максимум |
|---|---|---|---|
| 1 | 132 | 4.4 % | 12.7 % |
| 2 | 346 | 4.4 % | 16.9 % |
| 3 | 269 | 4.7 % | 17.1 % |
| 4 | 32 | 5.1 % | 11.4 % |

Медиана не растёт: от одного общего раздела до четырёх разница 0.7 пункта.
Максимум растёт, но и он даёт 16.9–17.1 % только там, где к общим разделам
добавился общий FAQ.

Это объясняет, почему написание трёх новых разделов bonus (с семи до десяти,
общих разделов у пары стало 1.87 вместо 2.66) уникальность не сдвинуло вовсе.
На полных 186 парных сидах провалы уникальности bonus 65.1 → 67.7 %
(McNemar p = 0.66), на непрерывной величине пересечение 18.02 → 17.61 %
(p = 0.38). Разделы не были главной причиной.

(Промежуточный счёт на первых 107 сидах показывал 69.2 → 62.6 %, и эту цифру
я назвал вслух прежде времени: McNemar давал по ней p = 0.4, то есть прямо
говорил, что знак ещё не определён. На полной выборке знак сменился.)

## Что из этого следует

Рабочий пул FAQ у bonus — 97 пар «по существу» из 123 (фильтр
`v5ObshchayaOsnova`), на страницу идёт пять. За сто наборов использовано
68 различных вопросов из 97. Отбор уже запрещает повтор вопроса внутри набора
и одну тему внутри блока, но ничего не говорит о том, **из какого прежнего
набора пришли выбранные пары**: потолок на прошлый набор в `$взять` общий,
пять кусков на владельца, а страница собирается из сотни кусков — для FAQ он
не срабатывает почти никогда.

Дешёвая правка на виду: держать для пар FAQ отдельный, жёсткий потолок —
не больше одной пары от одного прежнего набора. Тогда исход «сошлись двумя
вопросами с одним соседом» закрывается механикой, а не удачей. Проверять
нужно парным замером на тех же сидах.

Дорогая правка — писать новые пары FAQ, как писался сухой пул: пул в сто пар
на пять мест и сто наборов повторов не избежит.
