# ТЗ: Панель управления рабочими процессами (morol.casino)

Версия: 1.0 · Дата: 2026-06-10 · Статус: утверждено как основа для разработки

---

## 1. Цель

Единая внутренняя панель для управления рабочими активами и процессами: проекты, домены, серверы, прокси, документация, сервисы генерации контента, справочная информация, задачи и алёрты. Доступ — только для команды, через вход по паролю.

## 2. Зафиксированные решения

| № | Вопрос | Решение |
|---|--------|---------|
| A1 | Стек | Чистый PHP 8.2 + SQLite, без фреймворков и composer-зависимостей. Деплой по FTP на morol.casino |
| A2 | Вход | Страница логина (логин + пароль) + PHP-сессия. Пользователи хранятся в БД, заводит админ через панель |
| A3 | Роли | admin / manager / viewer, права как в §4. Viewer — только просмотр |
| B | Этапы | Этап 1: Проекты, Домены. Этап 2: Серверы, Прокси. Этап 3: Доки, Сервисы, Инфо. Этап 4: Notion-задачи, дашборд, алёрты |
| C4 | Проект | Поля зафиксированы + добавлено поле «Ответственный» |
| C5 | Домен | Базовые поля + добавлена «Заметка». Хостинг/NS — не добавляем |
| C6 | Категории проектов | Одна таблица «Проекты» с фильтром по категории + быстрые «чипсы» категорий над таблицей. Отдельных пунктов меню нет |
| D7 | Язык интерфейса | Русский |
| D8 | Лог действий | Да, лёгкий лог (кто, что, когда — без diff'ов) |
| D9 | Экспорт CSV | Да, в каждом табличном разделе |

## 3. Архитектура и ограничения среды

- **Хостинг:** shared-хостинг, деплой — заливка файлов по FTP. Никаких build-шагов, миграционных CLI, cron-демонов как обязательного условия.
- **PHP 8.2**, только стандартные расширения: `pdo_sqlite`, `session`, `json`, `mbstring`.
- **SQLite** — один файл базы. Файл лежит **вне веб-корня** (например `../data/app.sqlite`); если структура хостинга не позволяет — в каталоге `data/` с запретом доступа через `.htaccess` (`Require all denied`).
- **Схема БД** создаётся автоматически при первом запуске (idempotent `CREATE TABLE IF NOT EXISTS` + таблица `schema_version` для будущих миграций).
- **Структура файлов** (ориентир):

```
/public            # веб-корень (или корень сайта)
  index.php        # роутер (один входной скрипт, ?page=...)
  assets/          # css, js (без CDN-зависимостей, всё локально)
/app
  config.php       # пути, настройки
  db.php           # подключение PDO, инициализация схемы
  auth.php         # сессии, проверка ролей, CSRF
  helpers.php      # экранирование, csv-экспорт, лог
  pages/           # по файлу на экран: projects.php, domains.php, ...
/data
  app.sqlite       # база (закрыта от веба)
  backups/         # бэкапы базы
```

- **Без JS-фреймворков.** Серверный рендеринг, минимальный vanilla JS (фильтры, подтверждение удаления, чипсы категорий).

## 4. Пользователи и роли

### 4.1. Аутентификация

- Страница входа: логин + пароль. Пароли — `password_hash()` / `password_verify()` (bcrypt).
- Сессия PHP: cookie `HttpOnly`, `SameSite=Lax`, `Secure` (если HTTPS). Регенерация ID сессии при входе.
- Защита от перебора: после 5 неудачных попыток с одного IP — блокировка входа на 15 минут (учёт в таблице `login_attempts`).
- Время жизни сессии — 7 дней неактивности, затем повторный вход.
- Выход — кнопка «Выйти» в шапке.

### 4.2. Матрица прав

| Действие | admin | manager | viewer |
|----------|:-----:|:-------:|:------:|
| Просмотр всех разделов, переход по ссылкам | ✔ | ✔ | ✔ |
| Экспорт CSV | ✔ | ✔ | ✔ |
| Создание / редактирование / удаление записей во всех разделах | ✔ | ✔ | — |
| Управление пользователями (создать, сменить роль/пароль, деактивировать) | ✔ | — | — |
| Просмотр лога действий | ✔ | — | — |

- Права проверяются **на сервере** при каждом действии (не только скрытием кнопок).
- Пользователя нельзя удалить физически — только деактивировать (чтобы лог оставался читаемым). Нельзя деактивировать последнего активного админа.

## 6. Модель данных

Общее: у всех сущностей `id INTEGER PRIMARY KEY AUTOINCREMENT`, `created_at`, `updated_at` (ISO-8601, UTC). Внешние ключи включены (`PRAGMA foreign_keys = ON`).

### 6.1. `users`

| Поле | Тип | Описание |
|------|-----|----------|
| login | TEXT UNIQUE | логин |
| password_hash | TEXT | bcrypt |
| name | TEXT | отображаемое имя |
| role | TEXT | `admin` / `manager` / `viewer` |
| is_active | INTEGER | 1/0 |

Первый админ создаётся автоматически при первом запуске (логин/пароль из `config.php`, при первом входе принудительная смена пароля).

### 6.2. `projects` (Этап 1)

| Поле | Тип | Описание |
|------|-----|----------|
| name | TEXT | имя проекта |
| category | TEXT | `slots` / `brand_main` / `dorgen` / `spine` / `none` (Слоты / Brand Main / Dorgen / Spine / Без системы) |
| status | TEXT | `active` / `paused` / `archived` (Активен / Пауза / Архив) |
| system_name | TEXT | название системы |
| system_url | TEXT | URL системы |
| gsc_url | TEXT | ссылка на Google Search Console |
| webmaster_url | TEXT | ссылка на Яндекс.Вебмастер |
| owner_id | INTEGER FK→users | **Ответственный** (кто из команды ведёт), nullable |
| notes | TEXT | заметки |

### 6.3. `domains` (Этап 1)

| Поле | Тип | Описание |
|------|-----|----------|
| name | TEXT UNIQUE | доменное имя |
| registrar | TEXT | регистратор |
| renewal_date | TEXT (date) | дата продления |
| auto_renew | INTEGER | автопродление 1/0 |

| project_id | INTEGER FK→projects | привязка к проекту, nullable |
| notes | TEXT | **заметка** |

При удалении проекта у его доменов `project_id` → NULL (домены не удаляются каскадно).

### 6.4. `servers` (Этап 2)

## 7. Описание экранов

### 7.0. Общий каркас

- Шапка: название панели, меню разделов, имя пользователя + роль, «Выйти».
- Все таблицы: сортировка по клику на заголовок, поиск-фильтр по тексту, кнопка «Экспорт CSV» (выгружает текущую выборку с учётом фильтров, UTF-8 с BOM — чтобы открывался в Excel).
- Кнопки «Добавить / Редактировать / Удалить» видны только admin/manager. Удаление — с подтверждением.
- Формы: серверная валидация, сообщения об ошибках по-русски, после сохранения — возврат в список с flash-сообщением.

### 7.1. Вход

Логин, пароль, кнопка «Войти». Ошибка — общее сообщение «Неверный логин или пароль» (без уточнения, что именно неверно). Сообщение о временной блокировке после 5 неудач.

### 7.2. Проекты (Этап 1)

- Над таблицей — **чипсы категорий**: «Все · Слоты · Brand Main · Dorgen · Spine · Без системы» (с количеством в каждой). Клик — фильтр таблицы.
- Дополнительно фильтры: статус, ответственный; текстовый поиск по имени.
- Колонки: Имя · Категория · Статус · Система (имя — ссылка на URL) · GSC (иконка-ссылка) · Я.Вебмастер (иконка-ссылка) · Ответственный · Домены (число, ссылка на отфильтрованный список доменов) · Заметки (обрезаются).
- Форма: все поля из §6.2; «Ответственный» — выпадающий список активных пользователей.

### 7.3. Домены (Этап 1)

- Колонки: Домен · Регистратор · Дата продления · Автопродление (да/нет) · Статус · Проект (ссылка) · Заметка.
- Подсветка строк по дате продления: **красный** — до продления ≤ 7 дней или просрочен, **жёлтый** — ≤ 30 дней (только для доменов без автопродления; с автопродлением — нейтральная пометка).
- Фильтры: статус, проект, «истекают в ближайшие 30 дней»; поиск по имени.
- Форма: поля из §6.3; «Проект» — выпадающий список.

### 7.4. Пользователи (Этап 1, только admin)

Список: логин, имя, роль, активен, дата создания. Действия: создать, сменить роль, сбросить пароль (admin задаёт новый), деактивировать/активировать.

### 7.5. Лог (Этап 1, только admin)

Таблица: дата · пользователь · действие · объект · описание. Фильтр по пользователю и типу действия.

### 7.6. Серверы и Прокси (Этап 2)

Стандартные CRUD-таблицы по полям §6.4–6.5, та же подсветка по `paid_until`, что и у доменов.

### 7.7. Доки (Этап 3)

Не таблица, а **страница кнопок**: категории как секции, внутри — крупные кнопки-ссылки на Google Docs (открываются в новой вкладке). Управление (добавить/изменить/порядок) — отдельный режим для admin/manager.

### 7.8. Сервисы (Этап 3)

Таблица по §6.7: Название · Проект · Результаты / Ключи / Промпты (три кнопки-ссылки) · Заметки.

### 7.9. Инфо (Этап 3)

Список страниц по категориям (Инструкции / Глоссарий), просмотр страницы, редактирование для admin/manager.

### 7.10. Дашборд, Задачи, Алёрты (Этап 4)

- **Дашборд** (станет главной страницей): счётчики по проектам/доменам, ближайшие продления, последние действия из лога, задачи из Notion. До Этапа 4 главная — раздел «Проекты».
- **Notion-задачи:** read-only список задач из Notion API (база/фильтр задаются в настройках), переход по ссылке в Notion. Токен — в `config.php`, не в репозитории.
- **Алёрты:** домены/серверы/прокси с продлением ≤ N дней. Канал доставки (Telegram-бот / email / только баннер в панели) и механизм запуска (hosting-cron или «poor-man cron» при заходе в панель) — уточняются при старте этапа.

## 8. Этапы и порядок сдачи

| Этап | Состав | Критерий сдачи |
|------|--------|----------------|
| 1 | Каркас, вход, роли, пользователи, Проекты, Домены, лог, CSV | Панель развёрнута на morol.casino, команда работает в ней |
| 2 | Серверы, Прокси | CRUD + подсветка оплат работают |
| 3 | Доки, Сервисы, Инфо | Разделы наполнены реальными данными |

Каждый этап — отдельная ветка/PR, деплой по FTP после приёмки.

## 9. Нефункциональные требования

- **Производительность:** до ~5 одновременных пользователей, до ~10 тыс. записей суммарно. Страница списка — < 500 мс на shared-хостинге. Никакой оптимизации сверх индексов по FK и фильтруемым полям не требуется.
- **Совместимость:** актуальные Chrome/Firefox/Safari, адекватное отображение на мобильном (таблицы со скроллом, формы — в столбик).
- **Кодировка:** UTF-8 везде. Даты в БД — UTC, отображение — в часовом поясе из `config.php` (по умолчанию Europe/Moscow).
- **Надёжность:** при ошибке БД — человекочитаемая страница ошибки, детали — в лог-файл `data/error.log`, не на экран (`display_errors = Off`).

## 10. Безопасность

1. Все SQL-запросы — только prepared statements (PDO).
2. Весь вывод — через `htmlspecialchars()` (хелпер `e()`).
3. CSRF-токен на каждой форме и на POST-удалениях; запросы изменения данных — только POST.
4. Проверка роли на сервере для каждого экшена.
5. Файл БД, бэкапы и логи недоступны по HTTP (вне веб-корня или `.htaccess deny`).
6. Заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, базовый CSP (только self).
7. **Секреты (пароли серверов, токены) в заметках не хранить** — в полях notes хранятся только несекретные данные; доступы — во внешнем менеджере паролей, в панели только ссылка/метка. Notion-токен и FTP-доступы не коммитятся в git (`config.php` — в `.gitignore`, в репозитории — `config.example.php`).
8. Принудительный HTTPS-редирект, если хостинг даёт сертификат.

## 11. Бэкапы

- Кнопка в разделе админа: «Скачать бэкап базы» — отдаёт копию `app.sqlite` (через `VACUUM INTO`, чтобы файл был консистентным).
- Автокопия: при первом заходе в панель за сутки — копия базы в `data/backups/app-YYYY-MM-DD.sqlite`, хранится последние 14 копий (без зависимости от cron).
- Восстановление: заменить файл базы по FTP — документируется в README.

## 12. Критерии готовности (Этап 1 — приёмка)

1. Вход по паролю работает; без сессии любой URL панели редиректит на логин.
2. Admin создаёт пользователя-manager и пользователя-viewer; manager может создавать/править/удалять проекты и домены; viewer видит всё, но не видит кнопок изменения, а прямые POST-запросы от него отклоняются.
3. CRUD проектов со всеми полями (включая «Ответственный») и чипсами категорий с фильтрацией.
4. CRUD доменов со всеми полями (включая «Заметку»), привязкой к проекту и цветовой подсветкой сроков продления.
5. CSV-экспорт из обоих разделов открывается в Excel без кракозябр и учитывает активные фильтры.
6. Лог фиксирует входы и все создания/изменения/удаления; виден только админу.
7. Файл базы недоступен по прямому URL.
8. Бэкап скачивается кнопкой и открывается как валидная SQLite-база.
9. Всё развёрнуто на morol.casino заливкой файлов по FTP, без дополнительных шагов настройки кроме прав на каталог `data/`.
