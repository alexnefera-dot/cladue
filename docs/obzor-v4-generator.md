# Генератор обзорной страницы, версия v4-obzor-1

Слепок метода, которым сделаны двадцать две версии `donor-2` в
`samples/v3-final/singles`. Всё, что здесь записано, выведено из провалов, а не
придумано заранее: каждый пункт когда-то стоил переписанной страницы.

---

## Что входит в версию

| Файл | Роль |
|---|---|
| `engine/data-v4/obzor-profile.json` | 55 целей коридора, 11 приёмов, структура, список ловушек движка |
| `engine/priyomka-obzor.php` | приёмка одной командой: параметры + приёмы + уникальность |
| `engine/priyomy-obzor.php` | счётчик приёмов вёрстки (чего 55 полей не видят) |
| `engine/sobrat-obzor.php` | сборка страницы из прозы и спецификации варианта |
| `engine/zamer-obzor.php` | замер 55 полей против эталона |
| `engine/overlap.php` | пересечение по шинглам |
| `engine/data-v4/primer-varianta.json` | образец спецификации варианта |

Запуск приёмки:

```bash
php engine/priyomka-obzor.php samples/v3-final/singles/donor-2-b3
```

Три шлюза подряд, код возврата 0 только когда пройдены все три. Раньше они
звались тремя разными скриптами, и один из трёх регулярно забывался.

## Порядок работы

1. **Снять карточку эталона.** `zamer-obzor.php /dev/null <эталон> main "Феникс" "Fenix"` —
   слева нули, справа цели. Бренд обязателен: у эталона имя написано словом, у
   нас плейсхолдер, и без пары «ru/en» счётчик видит имя с одной стороны и
   выдаёт разрыв в четыре поля на ровном месте.
2. **Посчитать распределение абзацев до письма.** 61 абзац при среднем 52,3 и
   σ 29,3 раскладывается как 4×12 + 22×30 + 25×55 + 10×110 слов. Без этого
   `paragraphs`, `words_per_para`, `para_spread` и `para_short` правятся по
   очереди и ломают друг друга.
3. **Разложить тонкие доли на точные дроби.** `table_uniq_pct` 33,3 — это
   две разные шапки на шесть таблиц. `anchor_once_pct` 92,9 — это пятнадцать
   ссылок на четырнадцать разных текстов. Структура строится вокруг этих
   дробей, а не подгоняется после.
4. **Написать прозу с маркерами** приёмов, собрать `sobrat-obzor.php`.
5. **Гнать приёмку до нуля замечаний.**

## Порядок разделов — воронка, а не перестановка

```
официальный сайт → регистрация → зеркало → преимущества →
бонусы по валюте счёта → провайдеры и автоматы → отзывы → вопросы
```

У эталона это именно воронка. `Planner` из v3 порядок перемешивает — для
этого жанра он неверен, и три версии, собранные по его перестановкам
(`donor-2-p1..p3`), читаются как каталог, а не как обзор.

## Одиннадцать приёмов, которых 55 полей не видят

Замечание «как будто два разных мира» оказалось точным. Приёмочный шлюз
проходится целиком на странице, где нет ни одного приёма образца:

| Приём | Эталон | Почему поля молчат |
|---|---|---|
| Карточки автоматов | 12 | лежат в `<div>`, а `NicheLexicon::prose()` читает только `<p>` и `<li>` — **семнадцать упоминаний студий у самого эталона движок считает как 0** |
| Отзывы с именем, возрастом, стажем, звёздами | 6 | `reviews_rated` ищет `schema.org/Comment` либо «Имя / дата / оценка» |
| Звёзды ★☆ | 30 | U+2605 входит в диапазон эмодзи: **30 из 36 значков в теле эталона — это звёзды отзывов**, а в заголовках эмодзи нет ни одного |
| Плашки над H3 | 18 | не меряются вовсе |
| Таблицы ×3 по валютам ₽/$/€ | 6 | отсюда `table_uniq_pct` 33,3 — от переключателя валют, а не от произвольной пары шапок |
| Формула заголовка «бренд + ключ» | 7 | `head_brand_pct` у донора 43, и `brand_in_h` закрывается распределением по H2 и H3 |

Обложка карточки автомата у эталона **текстовая** — код вроде `FIRE 777`, а
не картинка. Вариант с одной общей картинкой на все двенадцать (`donor-2-s1..s4`)
и вариант с текстовой обложкой (`donor-2-b1..b3`) оба проходят счётчик.

## Ловушки движка

| Поле | Чем ловит |
|---|---|
| `anchors` | это не теги `<a>`, а словоформулы из `PageMetrics::ANCHORS` |
| `opener_name` | объявлено с `decimals=1`, поэтому 1 против 0 — уже провал; зачин не должен начинаться «Бренд — …» |
| `opener_key` | ищет «официальн» в первых 50 словах — блок `<style>` сверху выбивает окно |
| `faq_pairs` | заголовок, кончающийся «?», засчитывается парой; вопросы прячут в `<details><summary>` |
| `faq` | «?» в теле; `<summary>` в него не попадает — `Parser::BLOCK_TAGS` не знает `details` |
| `emoji_inline` | смотрит только `<li\|p>`; значки в `<div>`, `<td>` и заголовках свободны |
| `imperatives` | `\b\w+(йте\|ите)\b` — «сайте» считается, «проверьте» нет |
| `ty` | матчит `\b\w+(ешь\|ишь)\b` — «лишь» считается |
| `h3_colon_pct` | считает и `:`, и `—` |
| `words` | движок вырезает только `<script>`; текст `<style>` попадает в замер |

Отсюда правило: **блок `<style>` дописывается в конец фрагмента.** Сверху он
роняет `opener_key` в ноль и сдвигает `brand_first_third` с 34 до 22.

## Уникальность

Порог 6% по шести словам, инструмент `overlap.php`.

Провал случался **пять раз подряд на одном и том же** — на переиспользовании
собственных формулировок между версиями. Против эталона было 0,00%, между
своими — до 32,65%. Схема повторялась: пишу вторую версию, беру за основу
структуру первой, «слегка меняю» формулировки, получаю 15–30%.

Второй источник обнаружился на `s2`–`s4`: **общий CSS.** Одинаковый блок
стилей даёт около 14% сам по себе, потому что попадает в измеряемый текст.
У `b2` и `b3` он же дал 6,7% при уже разведённой прозе.

Развести версии удаётся пятью способами разом:

1. **угол подачи** — обзорный, сравнительный, пошаговый, разбор возражений,
   по срокам, по ошибкам, по деньгам, по типам игрока, по регламенту;
2. **числа** — свой набор порогов, потолков, множителей и процентов;
3. **синтаксис** — какой конструкцией строится предложение;
4. **имена классов** — `kv-`, `mt-`, `rg-`, `rv-`, `ar-`, `pg-`;
5. **порядок свойств в CSS** — иначе один шаблон стилей выдаёт себя.
