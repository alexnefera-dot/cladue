# Генератор v4: как он устроен и почему так

Три комплекта до этого писались руками. Дальше их пишет конвейер, а руки
остаются на том, чего конвейер не умеет.

## Запуск

```bash
# новый комплект: маска берётся первая свободная из пула
php engine/generator-v4.php --комплект=kran-1

# конкретная маска
php engine/generator-v4.php --комплект=kran-1 --маска="портовый кран"

# только две страницы, три попытки на каждую
php engine/generator-v4.php --комплект=kran-1 --только=main,slots --попыток=3

# прогон конвейера без вызовов модели: промпты собираются, замер идёт по
# уже лежащим файлам. Токены не тратятся.
php engine/generator-v4.php --комплект=chas-1 --маска="часовая мастерская" --сухой
```

Ключ: `ANTHROPIC_API_KEY` в окружении либо `engine/.anthropic-key` (в `.gitignore`).

## Шесть шагов

| шаг | скрипт | что делает |
|---|---|---|
| 1 | `zadanie-v4.php` | семь промптов из профиля: цели с допусками, каркас, разметка, школа бренда, граф, занятые срезы соседей |
| 2 | `realize.php` | один вызов модели на страницу |
| 3 | `dovodchik-v4.php` | механическая доводка счётных величин |
| 4 | `priyomka-v4.php` | замер страницы против профиля |
| 5 | бриф на правку | что мимо и на сколько — обратно писателю, `--mode=fix` |
| 6 | `priyomka-komplekt.php` | межстраничное: срезы, шинглы, каннибализация, граф, смещение, разметка |

Принят комплект — маска и срезы отмечаются занятыми в `engine/data-v4/maski.json`,
следующий прогон возьмёт свежие.

## Задание собирается из замера, а не из головы

Всё, что приёмка потом проверит, в промпте названо числом. Не «пиши как донор»,
а:

```
## Числа, которые проверит приёмка
  водность %                29.1    (допуск ±7.28)
  слов в абзаце             31.75   (допуск ±7.94)
  H3 на один H2             2.9     (допуск ±0.8)
  …

## Разметка
  выделений <strong>      67   полоса 54–90   без выделений: 0 донор(ов) из 34
  H3 с двоеточием         40.5 %   полоса 35.9–51.4 %
  эмодзи-маркеров         35   полоса 21–96
```

Строка «без выделений: 0 доноров из 34» стоит там не для красоты. Пока цель не
названа цифрой, писатель систематически недобирает: первый комплект вышел
75 % донорского объёма, 38 % ссылок и ноль выделений. Разброс у донора широкий,
и это читается как «можно меньше» — хотя страницы без выделения у него нет ни
одной. Медиана говорит, куда целиться; доля нулей — обязателен приём или нет.

## Граница между скриптом и писателем

Проведена по одному признаку: **трогает ли правка форму слова**.

Доводчик правит сам:

- **эмодзи-маркер** — символ в начале ячейки таблицы; соседние слова не меняются;
- **ol / ul** — тег списка, если пункты начинаются с глагола в повелительном;
- **бренд** — плейсхолдер вставляется рядом с опорным словом («касса `%brand%`»)
  и снимается оттуда же; существительное на плейсхолдер не заменяется.

Возвращается писателю брифом:

- **ключевая плотность** — замена «машина» → «слот» ломает падеж;
- **выделение `<strong>`** — где ставить, решает смысл фразы, а не счётчик;
- **двоеточие в H3** — метрика считает и двоеточие, и тире, так что обмен
  разделителя её не двигает: нужен новый заголовок;
- **объём и абзацы** — разнести абзац значит потерять отсылку «то же самое»;
- **регистр и сленг** — реплика, севшая в служебную строку, читается как сбой.

### Почему граница именно здесь

В августе всё перечисленное во второй группе один раз попробовали сделать
пакетным проходом. Счётчики сошлись с донорскими: ключи вышли на донорский ранг,
сленг на 0,46 при норме 0,52, короткие абзацы на 13,9 % при 16,5. Приёмка
показала 24/24, 15/15, 9/9 и «комплект принят».

В тексте при этом было:

```
«Второй регистрация ничего из этого не копирует»
«счётчик оборота по действующей бонус»
«она подтягивается к лицензия»
«Откройте профиль на сайте и указать личный ящик»
```

и, хуже точечных ошибок, переставленные предложения: «С доменом то же самое…»,
а следом отдельным абзацем — «Леток охраняют плотнее прочего потому, что он
один». Отсылка «то же самое» осталась без антецедента. Плюс реплики в служебных
строках: «Десять обращений, которые приходят к оператору. Звучит душно, но иначе
никак».

**Шлюзы этого не поймали: они считают, а не читают.** Тексты пришлось откатывать
целиком. Отсюда правило конвейера: править регуляркой можно только то, что
физически не может испортить согласование. Всё остальное — брифом, писателю,
с явным перечнем запретов в самом брифе.

## Пул масок

`engine/data-v4/maski.json`:

- `пул` — десять масок со словарём: портовый кран, типография, метеостанция,
  хлебопекарня, скалодром, железнодорожный пост, оранжерея, лодочная станция,
  кофейная обжарка, переплётная;
- `срезы_запас` — по три свободных среза темы на каждый тип внутренней страницы;
- `занято` — что уже израсходовано; пополняется автоматически после приёмки.

Маска — не украшение, а механизм уникальности. У 36 донорских сайтов нет
пересечений по шинглам именно потому, что каждый придумал свой предметный мир,
а не переписал чужие слова. Синонимизация даёт то же самое дороже и хуже.

## Что генератор пока не закрывает

Поля, где наши значения ниже донорских и правка требует писателя, а не разметки:

| что | наши | донор |
|---|---|---|
| ранг «слот» | 1353 | 82 |
| ранг «лицензия» | 1110 | 154 |
| сленг на 100 слов | 0,05 | 0,52 |
| абзацы ≤10 слов | 3,7 % | 16,5 % |
| страдательный залог | 1,67 % | 0,63 % |

Всё это должно попадать в текст при написании — то есть уходить в промпт
`zadanie-v4.php`, а не доделываться после. Числа в промпте уже стоят; проверить,
берёт ли их писатель, можно будет на первом живом прогоне.
