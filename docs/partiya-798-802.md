## Джекпоты: правка держится, но вскрылся второй путь

| | 793–797 (до правки) | 798–802 |
|---|---|---|
| мельче миллиона, на набор | 1.60 | **0.20** |
| равен выигрышу, на набор | 0.80 | **0.20** |
| «джекпот» на 1000 слов | 3.79 | 3.67 |
| «куш» на 1000 слов | 1.19 | **1.25** |
| пар «джекпот + сумма» | 59.0 | 55.6 |

Полоса NEW100: 0.21 и 0.23 случая на набор, «джекпот» 3.30, «куш» 1.86, пар
36.9 при дециле 8…67. По обоим нарушениям партия встала ровно на корпусный
уровень; по «кушу» мы всё ещё ниже доноров, по «джекпоту» выше — разрыв
сократился, но не закрылся.

Единственный джекпотный случай партии пришёл **не по тому пути, который
правлен**:

```
nabor-802 [registracia]
  Джекпот: максимальная сумма в сети достигла 92к рублей, но шанс поймать —
  доли процента.
  …в удачной серии поднял 92к…
```

Подмены «куш» → «джекпот» здесь нет. В пулах есть шаблон, который сам
ставит слово «Джекпот» рядом с прорезью `{СУММА}` — а `{СУММА}` отдаёт сумму
героя, для которой потолок вне джекпотного раздела миллион. Таких шаблонов в
пулах около тысячи, и у всех та же беда в запасе: шаблон называет джекпот, а
число берёт из банка историй.

Правильное решение — то же, что сработало на именах: прорезь, стоящая в
предложении со словом «джекпот», должна разрешаться из банка джекпотов, а не
из сумм героя (переписать `{СУММА}` → `{ДЖЕКПОТ}` на лету, как виджет
переписывает `{СУММА}` → `{СУММА_ГЕРОЯ}`). На пять наборов это 0.2 случая,
то есть ровно корпусный уровень, — поэтому класс не regression сегодняшней
правки, а отдельный следующий круг.
