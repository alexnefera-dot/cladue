# Дефекты оформления: что найдено и как чинится

Рабочий список для тех, кто правит стили комплектов. Каждый пункт: что видно, где вылезает,
из-за чего, чем чинится, чем проверить. Файл дополняется по мере находок.

Движок: `scripts/oform/` — `temy7.php` (таблица тем), `stili7.php` (CSS под блоки),
`kartinki7.php` + `grafika7.php` (рисованная графика), `razmetka.py` (сборка блоков из плоского текста).

---

## 1. Налезает текст в карточке слота

**Что видно.** В витрине слотов название игры идёт в две строки и наезжает на «RTP 96.39%»,
провайдер уезжает под постер. Читать невозможно.

**Где вылезает.** Только в темах со значением поля `слот` = `компакт` — это примерно треть
комплектов (259 из 777 отданных). В темах `картинка` и `градиент` карточка вертикальная,
там проблемы нет.

**Из-за чего.** Две причины, вторая — следствие первой.

1. В `stili7.php` есть слой «по структуре» — правила для комплектов без классов, по голым тегам:

   ```css
   div:has(>article+article){display:grid;grid-template-columns:repeat(auto-fit,minmax(215px,1fr));gap:12px}
   article{background:var(--карта2);border:1px solid var(--рам);padding:14px}
   ```

   Витрина слотов — это `<div class="slots-grid">` с детьми `<article class="slot-card">`,
   то есть под селектор она подходит. Правило перебивает собственную сетку компактной витрины
   (`.slots-grid{display:grid;gap:10px}` — одна колонка) и раскладывает карточки в четыре
   колонки по ~235 px.

2. Компактная карточка свёрстана как широкая строка:

   ```css
   .slot-card-inner{display:grid;grid-template-columns:64px 1fr auto;gap:14px;align-items:center}
   ```

   В коробке 235 px постер (64) и правая часть (`auto` — RTP и кнопка, ~139) съедают всё,
   и средняя колонка `1fr` получает **0 px**. `.slot-info{min-width:0}` разрешает ей схлопнуться
   до нуля, текст рисуется поверх соседей.

**Как убедиться.** В браузере у `.slot-card-inner` смотреть вычисленное
`grid-template-columns`: в сломанном виде это `64px 0px 139.438px`.

**Чем чинится.**

1. Слой по структуре — только для блоков без классов, чтобы он не спорил со стилями компонентов:

   ```css
   section:not([class]), aside:not([class]) { … }
   article:not([class]) { … }
   div:not([class]):has(>article+article) { … }
   ```

   То же самое для остальных правил этого слоя: `div:not([class]):has(>button+button)`,
   `div:not([class]):has(>span+span)`, `article:not([class]) h3`.

2. Компактную карточку — на flex с переносом, чтобы колонка не могла схлопнуться в ноль,
   а правая часть уезжала вниз, когда места мало:

   ```css
   .slot-card-inner{display:flex;flex-wrap:wrap;gap:10px 14px;align-items:center;padding:10px 14px}
   .slot-poster{flex:0 0 64px}
   .slot-info{flex:1 1 120px;min-width:0}
   .slot-footer{flex:0 0 auto;margin-left:auto}
   ```

3. Длинное слово без пробелов не должно вылезать за карточку:
   `.slot-name{overflow-wrap:anywhere}` — в обоих вариантах карточки.

**Чем проверить.**

```bash
NODE_PATH=/opt/node22/lib/node_modules node scripts/oform/верстка.js <папка выдачи>
```

Скрипт открывает каждую страницу и ищет текст, который не влезает в свою коробку: коробка
шириной меньше 24 px с текстом внутри или `scrollWidth` больше `clientWidth` при видимом
переполнении. На сломанном комплекте — 7 страниц с бедой, `H3.slot-name` шириной 0 при
нужных 82 px; после правки — ноль.

## 2. Белый текст на светлой карточке внутри секции с картинкой

**Что видно.** «Прогрессивные джекпоты» и «Последние выплаты» не видно совсем: белые буквы
на белой подложке. Раньше то же самое было с названиями слотов.

**Где вылезает.** В светлых палитрах, когда способ вставки картинки — `фон` (`k7-fon`),
и внутрь такой секции попал блок со своей подложкой.

**Из-за чего.** `.k7-fon` красит весь текст внутри в белый — это верно для текста поверх
картинки. Но блоки со своей подложкой (`.jackpot-strip`, `.payout-feed`, `.slots-dashboard`,
`.faq-section`, `.hero-value`, `.slot-card` и другие) рисуются на `var(--карта)`, а в светлой
теме это почти белый. Белое на белом.

**Чем чинится.** Собрать список блоков с подложкой в одну переменную и вернуть им цвета темы
внутри `.k7-fon` — сам блок, его текст, приглушённые подписи и акцентные числа:

```css
.k7-fon :is($карта){color:var(--тек)}
.k7-fon :is($карта) :is(p,h2,h3,h4,li,td,th,span,div,summary,strong,em,b,i){color:inherit}
.k7-fon :is($карта) :is(.slot-provider,.slot-rtp,.faq-answer,…){color:var(--тус)}
.k7-fon :is($карта) :is(.slot-rtp-value,.jackpot-cell-amount,.payout-row-amount,a){color:акцент}
```

Правило `color:inherit` нужно, потому что `.k7-fon p{color:#e7e9f2}` бьёт по абзацу напрямую,
а наследование от контейнера такому правилу проигрывает.

**Чем проверить.** Тот же `контраст.js`. До правки — 2 комплекта из 3 в партии; после — ноль.

## 3. Абзац вылезает за край блока

**Что видно.** Строка выходит за рамку карточки на два-три десятка пикселей.

**Из-за чего.** В тексте попадаются узкий неразрывный пробел (`U+202F`) и неразрывные дефисы
(`U+2011`): «Система фиксирует IP‑мульти‑логин» — для браузера это одно длинное слово,
которое некуда перенести.

**Чем чинится.** На обёртке комплекта: `overflow-wrap:break-word`.
Плюс `overflow-wrap:anywhere` на названиях слотов — там слова бывают длиннее карточки.

**Чем проверить.** `верстка.js` ловит это как «текст шире коробки»: ширина 1027 при нужных 1056.

## 4. Узкая колонка сайта-хозяина

**Что видно.** Карточки слотов налезают друг на друга: название переносится на несколько строк,
поверх него рисуются «RTP 97.5%» и кнопка «Играть».

**Где вылезает.** Комплект стоит не на всю ширину, а в узкой колонке чужого шаблона —
двухколоночная раскладка, на карточку остаётся 230–420 px. При проверке на 1100 px всё ровно.

**Из-за чего.** Стили писались под широкую страницу, а медиазапрос в такой колонке не срабатывает:
`@media` меряет окно, а не колонку. Окно широкое — правила для узкого экрана не включаются.

**Чем чинится.** Запрос по ширине самого блока, а не окна:

```css
$sc{container-type:inline-size;overflow-wrap:anywhere}

@container (max-width:560px){
  $sc table{display:block;overflow-x:auto;max-width:100%}
  $sc .slot-footer{margin-left:0;width:100%;justify-content:space-between}
  $sc .slots-grid{grid-template-columns:1fr}
  $sc .hero-value-grid,$sc .value-pillars-grid,$sc .stats-grid,$sc .jackpot-strip-grid{grid-template-columns:1fr}
  $sc .k7-vrezka{float:none;width:auto;margin:0 0 16px}
}
```

`overflow-wrap:anywhere`, а не `break-word`: только `anywhere` уменьшает минимальную ширину блока,
иначе длинное слово не даёт колонке сжаться.

**Чем проверить.** `верстка.js` теперь гоняет каждую страницу на двух ширинах, 1100 и 420 px
(третьим аргументом можно задать свои через запятую). До правки на 420 px вылезали заголовки
с неразрывными пробелами и таблицы внутри списков; после — чисто на 1100, 560, 420 и 360.

## 5. Надпись на кнопке «Играть» цветом кнопки

**Что видно.** Розовая пилюля без текста: надпись есть, но её не видно.

**Где вылезает.** Там же, где дефект 2 — витрина слотов внутри секции с картинкой-фоном.

**Из-за чего.** Правило из дефекта 2 возвращало цвет темы всем блокам с подложкой, и в списке
восстанавливаемых был селектор `a` — под него попала и кнопка `.slot-play-btn`. Из-за `:is()`
он оказался специфичнее, чем правило самой кнопки, и покрасил надпись акцентом — тем же цветом,
каким залита кнопка. Контраст 1.0.

**Чем чинится.** В восстановлении цвета ссылок брать только ссылки без класса:
`a:not([class])`. Кнопки со своим классом оставляют свои цвета.

**Чем проверить.** `контраст.js` этого не ловил: он пропускал элементы с текстом короче
13 символов, а «Играть» — шесть. Порог снижен до двух символов.

## 6. Бейдж RTP на карточке слота цветом самой карточки

**Что видно.** Зелёная (или чёрная) пилюля «High» / «Medium» в углу постера слота без текста:
надпись есть, но она того же цвета, что и подложка. Контраст 1.3–1.5.

**Где вылезает.** Витрина слотов внутри секции с картинкой-фоном — там же, где дефекты 2 и 5.
На партии 21 сентября задело 165 комплектов из 186.

**Из-за чего.** То же правило из дефекта 2, но другая его строка. Блокам с подложкой
возвращается цвет темы, а их содержимому — `color:inherit`, и в списке наследующих тегов
стоит `div`. Бейдж — это `div`, поэтому он брал цвет карточки вместо своего
`color` из `.slot-badge-high`. У правила выше специфичность, так что собственный цвет бейджа
не срабатывал.

**Чем чинится.** Бейджи исключаются из наследования:
`:is(p,h2,…,div,…):not([class*=slot-badge])`. Приём тот же, что в дефекте 5: элемент
со своей заливкой не должен попадать в общее восстановление цвета.

**Чем проверить.** `контраст.js` ловит это сам — искать в отчёте класс `slot-badge`.

## 7. Ячейка таблицы схлопывается в узкой колонке

**Что видно.** В колонке шириной около 420 px ячейка со словом «Подробнее» сжимается
до 20 px: слово рвётся по буквам в вертикальный столбик.

**Где вылезает.** Любая таблица, когда комплект стоит в узкой колонке хозяина
(`@container (max-width:560px)`).

**Из-за чего.** У обёртки комплекта стоит `overflow-wrap:anywhere` — иначе длинные URL
рвут вёрстку. В таблице это разрешает браузеру сжать колонку до одной буквы, чтобы
уместить всю таблицу в ширину.

**Чем чинится.** В том же контейнерном запросе ячейкам даётся `min-width:6.5em`. Таблица
там и так `display:block;overflow-x:auto`, поэтому лишняя ширина уходит в прокрутку,
а не ломает страницу.

**Чем проверить.** `верстка.js` — причина «коробка схлопнулась».

## 8. `<pre>` вылезает за край списка

**Что видно.** Команда в блоке кода уезжает за правый край пункта списка и за край комплекта.

**Из-за чего.** У `pre` по умолчанию `white-space:pre`: строка не переносится, а
`overflow-wrap` на неё не действует.

**Чем чинится.** `pre` получает `white-space:pre-wrap;overflow-wrap:anywhere;overflow-x:auto`.

**Чем проверить.** `верстка.js` — причина «текст шире коробки».

## 9. Быстрая ссылка проглотила целый раздел

**Что видно.** В блоке «По этой теме» подпись ссылки длиной в абзац, а сама плашка
сжата в 12 px.

**Из-за чего.** Не стили, а сборка блоков. В исходном фрагменте `<a>` не закрыт перед
таблицей: `<p><a href="/app"> <h3>Чек‑лист в таблице</h3> <table>…`. `razmetka.py` собирал
из этого быструю ссылку, и в подпись уходил весь раздел.

**Чем чинится.** Подпись быстрой ссылки длиннее 90 символов — признак незакрытого `<a>`:
кусок оставляется как есть, в быструю ссылку не превращается.

**Чем проверить.** `верстка.js` — причина «коробка схлопнулась» на `SPAN.ql-text`.

## Уже закрытые дефекты (на случай, если в вашей копии их ещё нет)

Четыре способа сделать текст нечитаемым, все найдены на живых комплектах и закрыты.

| Что было | Из-за чего | Чем починено |
|---|---|---|
| Чёрный текст в таблицах на тёмном фоне | Комплекты — фрагменты без `<!DOCTYPE>`; в quirks-режиме таблицы **не наследуют** `color`, браузер ставит чёрный | `table`, `th`, `td` получают `color:var(--тек)` явно |
| Акцент не читается на своём фоне (контраст 2.2–2.4) | Светлота акцента была фиксированной (56 % на тёмных темах, 42 % на светлых), а контраст зависит от тона: жёлто-зелёный на светлом фоне и синий на тёмном проваливаются | Светлота подбирается расчётом, пока контраст с фоном не дотянет до 4.5 (`v7Светлота` в `temy7.php`) |
| Белый текст на светлой кнопке (контраст 1.67) | `background:акцент;color:#fff` при светлом акценте | Цвет надписи выбирается по яркости самой кнопки: белый или `#111316` (`v7НаЦвете`) |
| Белые заголовки слотов на светлой карточке | Внутри секции с картинкой-фоном все `h2/h3` красились в белый, включая названия слотов на своих светлых карточках | Карточки внутри `.k7-fon` держат свой цвет: `.k7-fon .slot-card,.k7-fon .slot-name{color:var(--тек)}` |

**Чем проверить:**

```bash
NODE_PATH=/opt/node22/lib/node_modules node scripts/oform/контраст.js <папка выдачи>
```

Открывает каждую страницу, для каждого текстового узла берёт вычисленный цвет и первый
непрозрачный фон выше по дереву, считает контраст по WCAG. Ниже 3.5 — в отчёт.

## Как добавлять сюда новые дефекты

1. Снимок или комплект, на котором видно.
2. Найти, в каких темах вылезает: поле темы в `темы.md` рядом с комплектом
   (`палитра`, `заголовок`, `форма`, `слот`, `картинки`).
3. Смотреть вычисленные стили в браузере, а не исходный CSS: чаще всего виноват не сам блок,
   а правило, которое его перебивает.
4. Дописать пункт по тому же шаблону: что видно → где вылезает → из-за чего → чем чинится →
   чем проверить.
