# Проверка и очистка комплекта HTML-страниц

Файл для отдельного чата, который занимается **только проверкой и чисткой**
готовых страниц. Ничего про то, как эти страницы пишутся, тут нет и не нужно.

---

## 1. Что на входе

Папка с HTML-фрагментами — телами страниц, без `<html>`, `<head>`, `<body>`.
Одна страница — один файл, имя файла соответствует адресу страницы.

**Состав комплекта не фиксирован.** Часто встречается шаблон из семи файлов:

```
main  app  bonus  registracia  slots  vhod  zerkalo
```

но это **один из вариантов**, а не правило. Комплект может быть длиннее или
короче, с другими именами и другим набором разделов. Ориентироваться надо не на
список имён, а на то, что лежит в папке: набор файлов задаёт множество
допустимых адресов, и всё остальное проверяется относительно него.

Имя площадки в тексте всегда подставляется переменными, не литералом:

```
%brand_name_en%   латиницей
%brand_name_ru%   кириллицей
%domain_name%     домен
%date%            дата
```

## 2. Что проверяем

### 2.1 Ссылки

- **Битые.** Каждый `href="/x"` обязан разрешаться в существующий файл папки.
  Ссылка на корень `/` — это главная страница комплекта.
- **Форма адреса.** Внутренние ссылки — только вида `/имя`, без расширения,
  без `../`, без якорей и параметров, если не оговорено иное. Главная лежит по
  корню `/`, а не по `/main` или `/index`.
- **Внешние ссылки.** По умолчанию их быть не должно: разворачивать в текст,
  а не удалять вместе с содержимым.
- **Пустые и мусорные.** `href=""`, `href="#"`, `javascript:`, `href` без
  текста внутри — всё это убирать.
- **Обратные ссылки на главную.** Если задано ограничение, лишние
  разворачивать в текст, а не вырезать.
- **Дубли перечня ссылок.** Один и тот же абзац-перечисление, вставленный
  дважды, — частая беда после повторного прогона скрипта. Проверять на
  идемпотентность.

### 2.2 Переменные и имя площадки

- В каждом файле есть хотя бы одна переменная.
- Литерала имени площадки в тексте нет ни в каком виде.
- **Имя, приросшее к слову.** Маска `\bName\b` не берёт `Namemirror.com` и
  `Namealt.net` — нужна вторая маска `\bName(?=[A-Za-z])`.
- **Схлопывание после подстановки.** Замена литерала порождает
  `%brand_name_en% Casino` и `%brand_name_en% %brand_name_en%` — обе
  конструкции свернуть отдельным проходом.
- **Как найти литерал автоматически.** Частота латинских слов с заглавной
  минус стоп-лист: провайдеры (`Playson`, `Evolution`, `NetEnt`, `Belatra`…),
  названия игр, форматы (`PDF`, `KYC`, `AML`, `VPN`), платёжные системы,
  юрисдикции (`Curacao`, `Malta`, `Kahnawake`). Что осталось в верхушке — оно
  и есть имя площадки.

### 2.3 Разметка

Белый список тегов:

```
p h2 h3 ul ol li table tr td th blockquote strong a
details summary div dl dt dd
```

`div` допустим только внутри FAQ-разметки schema.org. Атрибуты — только `href`
у `<a>` и `itemprop`/`itemscope`/`itemtype` у FAQ. Всё прочее — снимать.

- **Заголовки:** `h1`→`h2`, `h4`/`h5`/`h6`→`h3`. После схлопывания проверять,
  не встали ли два `h3` подряд.
- **FAQ** приводить к одному виду: `details` + `summary itemprop="name"` +
  `div itemprop="acceptedAnswer"` + `div itemprop="text"`.
- **Осиротевшие `<li>`** вне `ul`/`ol` — обернуть.
- **Пустые блоки:** `<p></p>`, `<ul></ul>`, `<blockquote></blockquote>`.
- **Двойная обёртка цитаты:** `<blockquote><p>…</p></blockquote>` —
  развернуть внутренний абзац.
- **Титульная заглушка** в первой строке вида `<p>Казино %brand_name_ru%.</p>`
  — остаток шаблона, убирать.

### 2.4 Эмодзи

Два разных правила:

- в `p`, `h2`, `h3`, `td`, `th`, `summary`, `blockquote` — вырезать все;
- в `li` — оставить **только ведущий**, остальные вырезать.

Не забыть вариационный селектор U+FE0F: без него `⚖️` режется наполовину и
остаётся невидимый хвост.

### 2.5 Типографика

- Мягкий перенос U+00AD, неразрывный дефис U+2011, узкий неразрывный пробел
  U+202F, обычный неразрывный U+00A0 — приводить к обычным символам.
  Глазом не видны, но ломают подсчёт слов и любое сравнение текстов.
- Кавычки-лапки `“ ”` → ёлочки `« »`, если так принято в проекте.

### 2.6 Согласованность внутри комплекта

Дешёвые проверки, которые ловят настоящие ляпы:

- **Валюты.** Внутри одного комплекта не должно быть `₽`, `€`, `£` и `$`
  вперемешку — площадка одна, валюта одна.
- **Юрисдикции.** Одна площадка не может ссылаться сразу на четырёх
  регуляторов.
- **Номера разрешений.** Один номер на весь комплект, не пять разных.
- **Ключевые числа.** Пороги кассы, сроки, множители, размеры каталога —
  если одно и то же число названо на двух страницах по-разному, это ляп,
  который читатель заметит.

## 3. Порядок операций

Порядок важнее самих правил: половина ошибок берётся из перестановки шагов.

1. **Вынуть FAQ до всякой чистки.** Блоки `itemprop="hasPart"` вытащить
   первыми, текст вопроса и ответа сохранить отдельно. Если чистить теги
   раньше, микроразметка schema.org растворится вместе с `div`.
2. **Подстановка имени площадки — по всему, включая вынутый FAQ.** Частая
   дыра: подстановка идёт по телу, а внутри FAQ литерал остаётся.
3. Снести служебное: `script`, `style`, `meta`, `link`, `noscript`, `img`,
   `hr`, `br`, `caption`.
4. Развернуть контейнеры: `div`, `section`, `article`, `aside`, `footer`,
   `header`, `span`, `thead`, `tbody`, `tfoot`, `figure`, `small`, `q`,
   `abbr`, `time`, `cite`, `code`, `kbd`, `samp`, `var`, `sup`, `sub`, `u`,
   `s`, `mark`, `ins`, `del`, `dfn`.
5. Оформление: `em`/`i` — в обычный текст, `b` — в `strong`.
6. Заголовки: `h1`→`h2`, затем `h4`–`h6`→`h3`.
7. Снять атрибуты, кроме разрешённых.
8. Ссылки: `/main` → `/`, внешние развернуть в текст.
9. Эмодзи — по двум правилам из 2.4.
10. Типографика, пустые блоки, осиротевшие `<li>`.
11. Собрать FAQ обратно из шаблона.
12. Только теперь — счёт ссылок и любые проверки количеств.

## 4. Ловушки, каждая из которых стоила одного разбора

**Односимвольные теги в списке разворачиваемых.** Маска `</?u[^>]*>` съедает
`<ul>`, маска `</?s[^>]*>` съедает `<strong>`, `<summary>`, `<span>`,
`<section>`. В одном прогоне так пропало 129 списков из 144 и 498 выделений из
685, и заметно это стало только при чтении глазами. Требовать границу имени
тега: `</?u(?=[\s>/])[^>]*>`.

**`<b>` съедает `<blockquote>`.** Замена `<b[^>]*>` на `<strong>` превращает
`<blockquote style="…">` в `<strong>`, а закрывающий `</blockquote>` остаётся
сиротой. Нужно `<b(?=[\s>])`, закрывающий — `</b>(?!lockquote)`.

**Развёртка `div` убивает FAQ** — отсюда шаг 1 в порядке операций.

**Внешние ссылки разворачивать, а не удалять.** Удаление вместе с содержимым
выгрызает куски фраз, и заметно это только при вычитке.

**Пустые блоки появляются ПОСЛЕ чистки, а не до.** Они возникают, когда из
контейнера вынули весь инвентарь. Подметать в конце.

**Осиротевшие `<li>` бывают и в исходнике.** В одном архиве их нашлось 286 в
44 файлах — дефект генератора, а не чистки.

**Два `h3` подряд** после `h4`→`h3`: подзаголовок встаёт вплотную к родителю.
Либо склеивать, либо удалять младший.

**Повторный прогон удваивает вставки.** Любой шаг, который что-то дописывает
(перечень ссылок, оглавление), обязан проверять, не вставлено ли уже.

---

## 5. Чего чистка сделать не может

**Достроить недостающую страницу.** Если ссылки ведут на страницу, которой в
папке нет, — это не грязь, а некомплект. Падать с ошибкой, а не выбрасывать
ссылку молча: выбросив её, вы потеряете сигнал.

**Починить содержание.** Объём, повторы, стиль, жанр — не задача чистки.

---

## 6. Финальная проверка — падать, а не чинить

```
1.  каждый href разрешается в существующий файл папки
2.  главная лежит по /, форма адресов единообразна
3.  внешних ссылок нет, пустых href нет
4.  литерала имени площадки нет — только переменные
5.  в каждом файле есть хотя бы одна переменная
6.  теги только из белого списка
7.  атрибуты только href и itemprop/itemscope/itemtype
8.  ноль пустых блоков и ноль осиротевших <li>
9.  эмодзи только в начале <li>
10. FAQ у всех страниц в одной разметке
11. внутри комплекта одна валюта, один регулятор, один номер разрешения
12. ни один вставляемый блок не продублирован
```

Отчёт удобнее отдавать пофайлово: сколько тегов развёрнуто, сколько имён
заменено, сколько ссылок переписано, что не удалось починить. По изменению
этих чисел от прогона к прогону сразу видно, когда чистка начинает съедать
лишнее.
