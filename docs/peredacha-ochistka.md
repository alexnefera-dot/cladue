# Передача: как мы чистим чужой контент и пишем свой

Файл рассчитан на то, чтобы его целиком отдали новому чату. Всё, что нужно
знать о порядке работы, — здесь; код лежит в репозитории по указанным путям.

---

## 1. Что за проект

Репозиторий `alexnefera-dot/cladue`, рабочая ветка `claude/new-branch-work-pmpuir`.

Мы пишем комплекты статей для площадок одной ниши. **Комплект — это семь
страниц** строго этих типов:

```
main  app  bonus  registracia  slots  vhod  zerkalo
```

Готовые комплекты лежат в `samples/v5-final/<имя-комплекта>/`. На сегодня их 65.

Всё меряется по профилю `engine/data-v5/profil-v5-B.json`. Профиль снят с
корпуса живых конкурентов: у каждого поля есть цель, часть полей помечена
`держат` — они обязаны попасть в полосу `|факт − цель| ≤ max(0,25·|цель|; пол)`,
где пол равен 2,0 для счётных полей и 0,8 для дробных.

Задание на новый комплект генерируется:

```bash
php engine/zadanie-v4.php --выход=zadaniya/nabor<N>
```

В задании сейчас **34 пункта**. Папка `zadaniya/` в гитигноре. Генератор
расходует пул масок из `engine/data-v4/maski.json` и gitignored
`engine/data-v4/zanyato-mestnoe.json` — пробные запуски обязаны сохранять и
восстанавливать второй файл, иначе маска «сгорает».

## 2. Чем меряем

Четыре инструмента, все в `tools/zamery/`:

```bash
# приёмка одной страницы по профилю: N/M и список промахов
php tools/zamery/zamer.php <файл.html> <тип>

# шинглы: 5-словные окна, доля пересечения + сами совпадения
php tools/zamery/shingl.php <файл-А> <файл-Б>

# тошнота: повторы словоформ по всему тексту страницы
php tools/zamery/tosh3.php <файл.html>

# сборка семи страниц в одну статью .md
php tools/zamery/statya.php <папка-комплекта> <выход.md>
```

Сводная приёмка комплекта:

```bash
php engine/priyomka-komplekt.php samples/v5-final/<комплект> \
    --профиль=engine/data-v5/profil-v5-B.json \
    --корпус=samples/v5-final
```

Она проверяет: поля по семи типам, каркас внутренних, полы по рынку, смещение
(объём, термины, ссылки ≥ 85 % от суммы целей), бренд по школе написания,
разметку (выделения, H3 с двоеточием, эмодзи), граф перелинковки, технику,
уникальность (шинглы против корпуса ≤ 3,5 %, каннибализация внутри ≤ 3 %,
скелет H2 ≤ 25 %, пересечение хвостов ≤ 12 %, повтор роли в H3 ≤ 60 %),
согласование, эхо тела в ответах, россыпь коротких абзацев.

## 3. Нормы графа ссылок

Держатся на уровне комплекта, проверяются сводной приёмкой:

| правило | норма |
|---|---|
| ссылок с главной | 26–40 |
| ссылок с внутренней | 3–11 |
| главная ведёт на типов | ≥ 4 |
| **входящих на `/bonus`** | **0** |
| внутренних, ведущих назад на `/` | 0–2 |
| главная лежит по адресу | `/`, не `/main` |

## 4. Как чистили чужой контент

Задача звучала так: есть архив, сделанный другим генератором, — привести его к
структуре нашего. Скрипты в `tools/ochistka/`, запускать по порядку.

### 4.1 Порядок операций — он важнее самих правил

**1. Вынуть FAQ до всякой чистки.** Блоки `itemprop="hasPart"` вытаскиваются
первыми, текст вопроса и ответа сохраняется отдельно. Если чистить теги
раньше, микроразметка schema.org растворится вместе с `div`.

**2. Подстановка бренда — по всему, включая вынутый FAQ.** У чужого генератора
именно тут была дыра: 38 имён из 164 сидели внутри FAQ и уцелели, потому что
подстановка шла только по телу.

**3. Снести служебное:** `script`, `style`, `meta`, `link`, `noscript`, `img`,
`hr`, `br`, `caption`.

**4. Развернуть контейнеры** (снять тег, оставить содержимое): `div`, `section`,
`article`, `aside`, `footer`, `header`, `span`, `thead`, `tbody`, `tfoot`,
`figure`, `small`, `q`, `abbr`, `time`, `cite`, `code`, `kbd`, `samp`, `var`,
`sup`, `sub`, `u`, `s`, `mark`, `ins`, `del`, `dfn`.

**5. Оформление:** `em`/`i` — в обычный текст, `b` — в `strong`.

**6. Заголовки:** `h1→h2`, затем `h4`/`h5`/`h6`→`h3`.

**7. Снять атрибуты** со всех тегов, кроме `href` у `<a>` и `itemprop`/
`itemscope`/`itemtype` у FAQ.

**8. Ссылки:** `/main` → `/`; внешние развернуть в текст.

**9. Эмодзи** — по двум разным правилам (см. ниже).

**10. Типографика, пустые блоки, осиротевшие `<li>`.**

**11. Собрать FAQ обратно** из шаблона в конец страницы.

**12. Только теперь — баланс ссылок и пересчёт.**

### 4.2 Ловушки, каждая из которых укусила один раз

**Односимвольные теги в списке разворачиваемых.** Маска `</?u[^>]*>` съедает
`<ul>`, маска `</?s[^>]*>` съедает `<strong>`, `<summary>`, `<span>`,
`<section>`. У меня из-за этого пропали **129 списков из 144 и 498 выделений
из 685**, и я заметил это только при чтении глазами. Обязательно требовать
границу имени тега: `</?u(?=[\s>/])[^>]*>`.

**`<b>` съедает `<blockquote>`.** Замена `<b[^>]*>` на `<strong>` превращает
`<blockquote style="…">` в `<strong>`. Нужно `<b(?=[\s>])`, а закрывающий —
`</b>(?!lockquote)`.

**Развёртка `div` убивает FAQ** — отсюда шаг 1.

**Внешние ссылки разворачивать, а не удалять.** Удаление вместе с содержимым
выгрызает куски фраз, и заметно это только при вычитке.

**Обратные ссылки на главную режутся с сохранением текста**, и порядок: сперва
`/main → /`, потом счёт.

**Эмодзи — два правила.** В `p`, `h2`, `h3`, `td`, `th`, `summary`,
`blockquote` — вырезать все. В `li` — оставить **только ведущий**. Не забыть
вариационный селектор U+FE0F: без него `⚖️` режется наполовину.

**Невидимая типографика.** Мягкий перенос U+00AD, неразрывный дефис U+2011,
узкий неразрывный пробел. Глазом не видны, но ломают подсчёт слов и любое
сравнение по шинглам.

**Пустые блоки появляются ПОСЛЕ чистки.** `<p></p>`, `<ul></ul>`,
`<blockquote></blockquote>` возникают, когда из них вынули весь инвентарь.
Подметать в конце.

**Осиротевшие `<li>` вне списка.** В чужом архиве их было 286 в 44 файлах —
дефект их генератора. Обёртывать в `<ul>` отдельным проходом.

**Схлопывание бренда после подстановки.** Замена литерала даёт
`%brand_name_en% Casino` и `%brand_name_en% %brand_name_en%` — обе конструкции
свернуть отдельным проходом.

**Имя, приросшее к слову.** `\bEva\b` не берёт `Evamirror.com` и `Evaalt.net`.
Нужна вторая маска `\bEva(?=[A-Za-z])`.

**Два `h3` подряд** после `h4→h3` — либо склеивать, либо удалять младший.

**Дубль перечня ссылок.** Если скрипт добавления ссылок прогнать дважды,
абзац-перечень встанет два раза; это роняет `anchor_once_pct` в ноль и поднимает
тошноту. Проверять на идемпотентность.

### 4.3 Как искать литерал бренда

Частота латинских слов с заглавной минус стоп-лист: провайдеры (`Playson`,
`Evolution`, `NetEnt`, `Belatra`…), названия игр, форматы (`PDF`, `KYC`, `AML`,
`VPN`), платёжки, юрисдикции (`Curacao`, `Malta`, `Kahnawake`). Что осталось в
верхушке — оно и есть.

### 4.4 Чего чистилка сделать не может

**Достроить недостающую страницу.** Пять площадок из восьми ссылались на
несуществующий тип — это не грязь, это некомплект, и падать надо с ошибкой.
Восемь недостающих страниц я дописал руками по профилю.

Объём, тошноту и жанр главной чистилка не лечит и делать вид не должна.

### 4.5 Финальная проверка — падать, а не чинить

```
1.  семь типовых файлов на месте
2.  каждый href="/x" разрешается в существующий файл
3.  /main не встречается ни разу
4.  литерала имени площадки нет — только переменные
5.  в каждом файле есть хотя бы одна переменная
6.  теги только из белого списка:
    p h2 h3 ul ol li table tr td th blockquote strong a details summary div dl dt dd
7.  атрибуты только href и itemprop/itemscope/itemtype
8.  ноль пустых блоков и ноль осиротевших <li>
9.  эмодзи только в начале <li>
10. граф ссылок по нормам раздела 3
```

## 5. Как пишем свой комплект

Порядок, выведенный на десятке комплектов. Отступать от него дорого.

1. **Сгенерировать задание** и прочитать его целиком: маска, ракурс, рефрен,
   словарь, порядок узлов, грани узлов, срезы и формы закрытия внутренних.
2. **Написать лист А** — до письма. На нём: первые слова всех тридцати H3
   внутренних страниц, форма хвоста каждой страницы и **зачин перечня ссылок**
   для каждой. Ни одно первое слово не повторяется больше двух раз; каждая
   повторяющаяся конструкция разводится отдельно, а на одной странице из шести
   перечня ссылок нет вовсе.
3. **Написать лист Б** — восемь служебных строк своими словами, на все семь
   страниц: шапка таблицы-паспорта, пороги кассы, независимость нижней цифры от
   способа пополнения, состав зала, кнопки фильтра, сверка держателя разрешения,
   путь заявки, хронометраж витрины.
4. **Свод площадки** — все числа комплекта, единые на семь страниц: подарок,
   множитель, оборот, предел ставки, срок, каталог, реестр, пороги кассы,
   отдача, кэшбэк, фриспины, лицензия, тайминги. Числа не должны пересекаться
   с соседними комплектами.
5. **Главная — один случай, а не восемь узлов подряд.** Сквозной случай с
   развязкой на последнем узле; узлы идут в порядке обхода.
6. **Писать страницу, мерить, править.** Правки — цельными кусками, не
   перестановкой слов: шестисловное окно ловит связки.
7. **Сразу после добора — шинглы против трёх-четырёх соседних комплектов**, до
   сводной приёмки. Это правило спасало почти каждый раз.
8. **Сводная приёмка.** Довести до «комплект принят».
9. Коммит, пуш, сборка статьи, отчёт.

### Ловушки мер, на которых спотыкаешься чаще всего

- `terms_total` считается по `NicheLexicon::prose()` — только `<p>` и `<li>`.
  Термины в таблицах и заголовках не считаются вовсе.
- `games_named` / `providers_named` / `names_uniq` — тоже только по прозе.
  На `slots` держится `providers_named = 0` при `names_uniq = 3`: имена студий
  в прозе запрещены, значит три разных имени набираются названиями игр.
- `anchors` дерётся с `terms_total`: добор терминов сдвигает опорные формулы.
- `h3_question_pct` смотрит **первое слово** H3.
- `h2_opens_para_pct`: `<details>` не входит в список блоков, поэтому FAQ-H2
  всегда считается «открытым абзацем». Нужны 1–2 содержательных H2, за которыми
  сразу идёт `h3`/`ul`/`table`.
- `table_cell_sent_pct`: ячейка считается предложением, если в ней есть `.!?` —
  «+0,3 п. п.» ломает меру, писать «+0,3 пункта».
- `lead_list` = 1, если `ul`/`ol` попал в первую четвёрку блоков. На главной
  нужен 1, на внутренних 0.
- `anchor_once_pct` считает **тексты ссылок**, а не опорные формулы: без единой
  ссылки поле равно нулю.
- `emoji_inline` смотрит только `<p>` и `<li>` — эмодзи в `<td>` мера не видит,
  хотя задание их запрещает.
- `ty` считает местоимения и не ловит повелительное второго лица.

## 6. Текущее состояние и что делать дальше

**Корпус разъехался.** Сегодня из 65 комплектов сводную приёмку проходят 35,
не проходят 30 — все старые. Они принимались под прежние нормы, потом нормы
менялись, и никто их не перемерял. Пара `organnaya-masterskaya-1` ↔
`pergamentnaya-masterskaya-1` даёт 4,44 % шинглов на `zerkalo` при пороге 3,5 %:
приёмка меряет новый комплект против корпуса, но пары внутри уже принятого
корпуса не пересчитываются никогда.

Следствие: шинглы каждого нового комплекта считаются против базы, треть которой
сама вне нормы.

**Две дыры в мере**, обе описаны выше: эмодзи вне списков (240 знаков в 27
комплектах) и повелительное второго лица.

**Проверяемая фактура.** 31 разный номер лицензии в формате
`Curacao № XXXX/JAZ`; формат настоящий, и часть номеров может совпасть с
действующими. Плюс две неверные привязки игры к студии: «Fruit Cocktail у
Belatra» в `solodovnya-1` и `Resident` в строке Belatra у
`shpalopropitochnaya-1` — оба тайтла на самом деле Igrosoft.

**Порядок работ, о котором договорились:**

1. перемерить корпус и решить судьбу тридцати — чинить или вынести из эталона;
2. закрыть две дыры в мере;
3. решить, что делать с проверяемой фактурой.

## 7. Как докладывать

Договорённость: не смешивать в отчёте настоящие находки и приборный шум.

**Видно снаружи** — переносы между комплектами, каннибализация, повтор скелета,
обращение на «ты», выдуманная фактура с именами реальных организаций, разнобой
валют и юрисдикций внутри комплекта.

**Приборный шум** — поля у края полосы: `anchors` 19 при потолке 20, тошнота
23,8 при потолке 23,75, доля H3 с двоеточием на границе. Нормы профиля — это
разброс живых конкурентов, а не шкала качества; стоять у края полосы значит
«так пишет редкий, но реальный сайт».

Про такое достаточно одной строки: «остальное в полосе».

## 8. Что нельзя

- Ключ API не коммитится и не появляется в переписке. Живёт в
  `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` либо в gitignored
  `engine/.anthropic-key`.
- Идентификатор модели не попадает в сообщения коммитов, заголовки и тела PR,
  комментарии кода и любые артефакты репозитория — только в ответы в чате.
- PR не создаётся без явной просьбы.
- Папка `zadaniya/` в гитигноре — не добавлять.
- Трейлеры коммитов:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: <ссылка на сессию>
```
