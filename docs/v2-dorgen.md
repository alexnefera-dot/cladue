# v2 — генерация по референсу конкурента (dorgen)

Вторая версия генератора: тот же движок, но **целится в показатели конкурента**
`dorgen` (экспорт `dorgen_export_24.07.2026`, 9 связок), а не в наш корпус из
50 сайтов. **v1 полностью сохранён** — по умолчанию генератор работает по нашему
корпусу; v2 включается флагом `--corpus=dorgen`.

## Как это устроено

Один код, два набора данных:

| | v1 (наш корпус) | v2 (dorgen) |
|---|---|---|
| Данные | `engine/data/` | `engine/data-dorgen/` |
| Доноров | 50 сайтов | 9 наборов (`set199`…`set267`) |
| Опенер по умолчанию | ВЫКЛ | **ВКЛ** (dorgen его использует) |
| Флаг | (по умолчанию) | `--corpus=dorgen` |

`engine/data-dorgen/` содержит:
- `donors.json` — 9 пер-сайтовых профилей, снятых нашим `Analyzer` с их HTML
  (замеры совпали с их отчётом один-в-один: set199 main я=185/вы=4/имп=28, и т.д.).
- `profile.json` — коридоры `[p10,median,p90]` по 8 наборам (аномальный `set232`
  исключён — у него протёк «Additional Text», ломает коридоры).
- `pools/pools.json` — пулы сущностей/тем/опенера (общие с v1; казино-домен тот же).

## Запуск

```bash
# список доноров-наборов dorgen:
php engine/generate.php --list-donors --corpus=dorgen

# клон конкретного набора dorgen (целимся в его метрики), с опенером как у них:
php engine/generate.php --all --corpus=dorgen --donor=set199 --brand-var --seed=x --out-dir=/tmp/v2 --prompt

# случайный набор dorgen по seed:
php engine/generate.php --all --corpus=dorgen --donor=random --brand-var --seed=x --out-dir=/tmp/v2 --prompt

# выключить опенер даже под dorgen:
php engine/generate.php ... --corpus=dorgen --no-opener
```

Дальше реалайз (realize.php / агент) и сравнение — как в v1, но донор берётся из
dorgen-набора:

```bash
# сравнить готовую связку с их набором:
php engine/compare-vs-donor.php <папка> set199   # ← нужен donors.json с dorgen;
# для этого укажи dorgen-датасет (см. ниже) или сравнивай инструментом v2.
```

> Примечание: `compare-vs-donor.php` читает `data/donors.json`. Чтобы мерить против
> dorgen-наборов, скопируй/укажи `data-dorgen/donors.json` или расширь инструмент
> флагом `--corpus` (todo, если понадобится).

## Регистры dorgen (по их 9 наборам)

- **личный «я»** — set199, set235 (я 173–185 на главной)
- **продающий «вы»+CTA** — set242 (вы 50, имп 137), set267 (вы 36, имп 60)
- **безличный/нейтральный** — set229, set256 (я/вы≈0)
- **умеренный** — set227, set240
- **аномальный** — set232 (исключён из коридоров)

Ключевое отличие dorgen от нашего корпуса: **больше объём** (главные 2130–6158
слов), **сильнее рандомизация голоса** между связками (CV «я» 155%, «вы» 124%,
императивы 98%), опенер-зачин присутствует.

## Как пересобрать данные dorgen (если появятся новые экспорты)

```bash
# 1. Нормализуй экспорт в папки set<id>/<тип>.html, затем:
php engine/extract-donors.php <папка-корпуса> engine/data-dorgen/donors.json
# 2. Пересчитай коридоры (исключив брак):
php engine/build-corpus-profile.php engine/data-dorgen/donors.json engine/data-dorgen/profile.json set232
```

Референс-исходники: `samples/dorgen-reference/` (нормализованные 9 наборов) и
`reports/dorgen-competitor-analysis.html` (их параметрический отчёт).

## Проверено на реализованных наборах

Эталоны — `samples/v2-dorgen/`: экспертный set199 **88%**, нейтральный set256 **82%**,
продающий set267 **78%** (one-shot). `compare-vs-donor.php --corpus=dorgen` мерит
прямо против dorgen; verify-loop (`make-fix-briefs --corpus=dorgen`) работает.

## Роадмап: как поднять процент (по убыванию рычага)

Систематические промахи, замеренные по всем наборам v1+v2 (one-shot):

1. **Плотность цифр — главный рычаг.** Реалайзер добавляет числа в прозу сверх
   ФАКТУРЫ почти на каждой странице (наш 4–6/100 vs цель 1.5–3). Промпт говорит
   «числа только из ФАКТУРЫ», но модель всё равно сыплет «97.3%, 1000 игр…».
   *Фикс:* в `PromptBuilder` выдавать **явный бюджет прозаичных чисел на страницу**
   (N = цель·слов/100 − числа в таблицах), проактивно — как это делает verify-loop
   постфактум. Поднимет one-shot почти везде.
2. **Тошнота на нейтральном/безличном.** Казино-SEO повторяющийся по природе;
   синоним-ротация помогает, но есть пол (~40 при цели ~33). *Фикс:* расширить пул
   синонимов по кластерам в `pools.json`, усилить инструкцию против повтора
   заголовков и головных существительных.
3. **Императивы на экспертном «я».** Конфликт «тяжёлое я + команды» (set199: 2 vs 28).
   Структурно: в я-повествовании команды не живут. *Фикс:* для экспертного донора
   с высокими императивами — разрешить блок «практические шаги» в безличном тоне,
   где команды уместны, не ломая «я» в остальном тексте.
4. **Продающий/деловой регистр.** verify-loop осциллирует (крупные правки тянут
   одеяло). *Фикс:* докрутить профиль отдельно — срезать целевую плотность цифр в
   `Planner` для этих регистров, мягче переписывать; брать на one-shot.
5. **Сущности/секции на отдельных сателлитах** — остаточный шум, в пределах ±2.

Приоритет: **#1 (бюджет цифр)** — самый широкий и низкорисковый; затем #2 и #4.

### Что уже внедрено и замерено (set267 main, one-shot, тот же донор)

| Параметр | базовый | +бюджет цифр/императивы | +числовые цели обращения | цель |
|---|---|---|---|---|
| Цифры/100 | 5.9 ✗ | 3.5 ✓ | 3.6 ✓ | 2.9 |
| Императивы | 113 ✗ | 60 ✓ | 54 ✓ | 60 |
| «вы» | 45 ✓ | 7 ✗ | **30 ✓** | 36 |
| Сущности | 13 ✓ | 12 ✓ | 12 ✓ | 12 |
| Тошнота | 44.5 | 43.3 | 46 ✗ | 35.9 |

Вывод: параметры СВЯЗАНЫ. Пока «вы»/«я» были только флагом «да/нет», подрезка
команд вымывала обращение (45→7). Числовые цели обращения расцепили связку —
четыре параметра держатся одновременно. Тошнота остаётся упрямой (пол ниши ~44
при цели ~36) и платит за остальные фиксы.

### Дисперсия реалайзера на ГЛАВНОЙ (важно для продакшна)

Два прогона ОДНИМ И ТЕМ ЖЕ промптом (обе главные с целями обращения):

| прогон | «вы» | императивы | strong | итог страницы |
|---|---|---|---|---|
| A | 30 ✓ | 54 ✓ | — | 84% |
| B | 4 ✗ | 125 ✗ | 10 ✗ | 63% |
| цель | 36 | 60 | 54 | |

Промпт идентичен — расходятся результаты. На длинной главной (3000+ слов) модель
держит цели нестабильно; на сателлитах (400–900 слов) фиксы работают ровно
(в том же наборе слоты 89%, зеркало/регистрация/приложение 84%).

**Практика:** главную гнать через verify-loop либо best-of-2 (сгенерить дважды,
взять лучшую по `compare-vs-donor`); сателлиты — one-shot достаточно. Итог набора
без этого «гуляет» на ±4 п.п. независимо от качества промпта.
