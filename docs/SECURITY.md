# Защита данных Pipboy

## Модель угроз и что сделано

| Угроза | Защита | Статус |
|---|---|---|
| Сосед по Wi-Fi читает API | Замок действует на уровне HTTP: все /api/* требуют ключ (X-Pipboy-Key), без него 401. Ключ выдаётся только по паролю замка | ✅ |
| Случайный взгляд в экран | Замок разделов (Цели/Финансы/Инфо/Психология) + скрытие сумм глазками по умолчанию | ✅ |
| Слив через облако | Никаких облаков: данные не покидают Mac, наружу уходят только тикеры курсов | ✅ by design |
| Слив через git | data.db, demo.db, backups/, export/ в .gitignore; репозиторий приватный | ✅ |
| Потеря/смерть диска | Локальные бэкапы (20 шт., авто раз в день) + внешняя папка бэкапа (Настройки) + экспорт MD/JSON | ✅ |
| Кража устройства / доступ к файлам | Сейчас: включи FileVault (Системные настройки → Конфиденциальность) — диск шифруется целиком. Нативная фаза: шифрование базы на уровне приложения, ключ в Keychain | ⚠️ частично |
| Перехват в домашней сети (HTTP) | Прототип ходит по HTTP внутри своей сети. Нативная фаза: TLS или сокет-пейринг для синка | ⏳ нативная фаза |
| Страницы-секреты | Шифрование страниц AES-256-GCM было; убрано из UI по решению пользователя (раздел и так под замком) — код жив, можно вернуть | 📦 законсервировано |

## Правила
- Пароль замка нигде не хранится в открытом виде (sha256 с солью приложения).
- Бэкап во внешнюю папку: указывай ВНЕШНИЙ ДИСК, не iCloud Drive/Dropbox — иначе сам же сольёшь базу в облако.
- Перед передачей Mac в ремонт: Настройки → бэкап на внешний диск → удалить app/data.db и app/backups.

## Нативная фаза (порядок)
1. Mac (Electron, каркас в desktop/): окно, уведомления, автозапуск.
2. Планировщик уведомлений в ядре: рутины/платежи/события, свой звук на категорию.
3. Шифрование базы на покое + ключ в Keychain (Touch ID открывает по-настоящему).
4. iPhone (Capacitor): тот же фронт, локальная SQLite, локальные уведомления.
5. Синк Mac↔iPhone по Wi-Fi: журнал операций, last-write-wins, без облака.
