# Библиотека фактов (принцип формирования фактуры)

> Самый глубокий слой. Генератор раскрывает в секциях **факт-слоты** — у каждого
> есть **пул значений / диапазон**, из которого на каждый сайт подставляется
> случайное правдоподобное значение. Числа реалистичны, но **сгенерированы**
> (часть неправдива). Уникальность сотен наборов достигается **варьированием
> значений фактов**, а не только перефразированием текста.

## Принцип

1. Каждый фактический тезис = **слот** (напр. «время вывода», «вейджер», «RTP»).
2. У слота — **пул значений** (round-числа) или **диапазон**; часть слотов «узкие»
   (лицензия, RTP ~96%), часть «широкие» (время вывода, размер APK).
3. На каждый сайт значение **сэмплируется независимо** → у 50 сайтов разные числа.
4. Значения **правдоподобны** (реалистичные диапазоны, круглые суммы), но не проверяемы.

## Что это меняет (и мои прежние ошибки)

- **Числа надо РАНДОМИТЬ по слотам, не фиксировать.** Я в Nova ставил фиксированные
  значения (вейджер x35, TLS 1.3, вывод «10–30 мин») — это делает генератор шаблонным.
- **Реальные предпочтения корпуса иные:** шифрование чаще **SSL**, а не TLS 1.3; вейджер
  чаще **x30**; возраст бывает и **21+**; RTP держится **96–97%**; провайдеров ~**30**.
- **Широкие слоты** (время вывода, размер APK, число игр, версии ОС) — главный источник
  различий между сайтами; их надо варьировать особенно сильно.

## Качественные тезисы (без чисел)

Помимо числовых слотов, секции раскрывают **тезисы-утверждения** — берутся из пулов фраз
(`semantic-lexicon.md`): гарантии безопасности, условия бонуса, шаги верификации,
признаки поддельного зеркала, правила ответственной игры и т.п. Их тоже нужно
**ротировать** из пула, а не повторять дословно.

## Вывод для генератора

Фактура собирается так же, как структура и стиль — **из диапазонов**:
на каждую страницу генератор сэмплирует значения факт-слотов (из пулов выше) и тезисы
(из пулов фраз), поэтому сотни наборов получаются с разными числами и разными
формулировками при одном каркасе. Это и есть защита от «шаблонности».
