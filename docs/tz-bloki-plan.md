# ТЗ по блокам: что меряется, что делаем и в каком порядке

Разбор трёх частей ТЗ против нашего кода и наших корпусов. Главное условие
заказчика — **не ломать текст**, поэтому первым делом выясняется, какие правки
текста вообще не касаются, и работы разводятся по слоям.

## 1. ТЗ и наш корпус — это два разных корпуса

Наш движок подогнан под `samples/v5-donors` (11 наборов, банк блоков) и
`samples/v5-konkurent/NEW100` (100 наборов, полосы приёмки, профиль, ворота
уникальности). Внутри NEW100 наша семья шаблонов — 79 наборов, несущих
`hero-value`. Проверяем по ним блоки из ТЗ:

| блок из ТЗ | доноры нашей семьи (79) | мы (10 наборов) |
|---|---|---|
| hero-value, value-pillars, slots-dashboard, slot-card, recent-payouts-block | 79 из 79 | 10 из 10 |
| faq-section | 75 из 79 | 10 из 10 |
| page-thematic-block, layout-block | 52 из 79 | 10 из 10 |
| review-quotes-block, hero-quicklinks | 79 из 79 | 10 из 10 |
| cta-block | **12 из 79** | 0 |
| action-block, spot-cta-block | **0 из 79** | 0 |
| related-sections | **0 из 79** | 0 |
| promo-timer-widget | **0 из 79** | 0 |
| yandex-index-only | **0 из 79** | 0 |
| win-notifications-root | **0 из 79** | 0 |
| support-widget | **0 из 79** | 0 |
| keywords-block | **0 из 79** | 0 |

Семи блоков из ТЗ в нашем корпусе нет вовсе. Зато они все есть — вместе с
`variant-v1…v4`, `bonus-calculator-widget` и `site-structure-block` — в одном
наборе репозитория: **`samples/v3-reference/7`**, двенадцать страниц. То есть
ТЗ снято с другой, более новой сборки того же оператора.

**Чем это важно.** Полосы приёмки, профиль и порог уникальности сняты с NEW100.
Добавление семи блоков уводит страницы из этих полос — не потому что текст
стал хуже, а потому что мерка меряет другое население. Это решается, но
решается отдельно от самой вёрстки блоков, и это главная причина разводить
работы по слоям.

## 2. Что из ТЗ уже выполнено — замер, а не мнение

Главные страницы, наша семья NEW100 (79) против наших наборов 818–827 (10):

| | доноры нашей семьи | мы | ТЗ говорит |
|---|---|---|---|
| карточек `slot-card` | медиана **24** | **24** | 24, фикс ✓ |
| эмодзи | медиана **54** (p10 52, p90 55) | **54** (51–59) | «у них 101, у нас 52, цель 90–120» ✗ |
| ссылок | медиана **65** | **69** | — ✓ |
| `h2` | медиана **9** | **10** | — ✓ |
| пул названий слотов | — | **207 игр, 12 на набор жребием** | «пул 150+» ✓ сделано |

Строка про эмодзи — единственная, где ТЗ расходится с замером: в нашей семье
медиана 54 при полосе 52–55, и мы ровно в ней. Цифра 101 взята из того же
другого корпуса. Поднимать плотность эмодзи до 90–120 значит уехать из полосы
NEW100 и переписать текст без измеренной причины. **Пока не перемерено на
корпусе ТЗ — не трогаем.**

## 3. Разделение работ на три слоя

### Слой О — оформление. Текста не касается вовсе

Правки живут в `verstka-v5.php` / `stili-v5.php` / `kartinki-v5.php`, то есть
**после** генерации: меняются атрибуты и стили, ни одно слово не переписывается,
приёмка и сито не шевелятся по построению.

1. **Версии блоков в CSS.** Наши страницы уже несут `variant-vN` — он приходит
   из донорских блоков банка: по пяти наборам встречаются `hero-value` v2/v3/v4,
   `recent-payouts-block` v1–v4, `slots-dashboard` v1/v3/v4, `value-pillars`
   v1/v2/v4. Но `verstka-v5.php` стилизует по первому классу элемента, поэтому
   все четыре версии выглядят одинаково. Нужно добавить правила под второй
   класс — CSS в ТЗ приведён дословно. Это самый дешёвый и самый заметный шаг.
2. **Модификаторы элементов:** бейдж карточки high/medium/low 67/25/8, цвет и
   пульс ячейки джекпота, тип строки выплат, размеры пилюль.
3. **FAQ:** к нашим `<details>` добавить микроразметку `FAQPage`/`Question`/
   `acceptedAnswer` и JSON-LD. Разметка, не слова.
4. **Блок ключей:** `<span>` → `<a href>`, три размерных класса, заголовок.

### Слой Б — мебель. Новые блоки, несущие текст

`related-sections`, `yandex-index-only`, `promo-timer-widget`,
`win-notifications-root`, `support-widget`, `action-block` + `cta-block`,
и четыре блока WP-линейки (плюсы-минусы, отзывы, оценки, эксперт).

Правило разделения: каждый такой блок — **отдельный виджет со своим пулом**,
вставляемый по карте страниц рядом с существующими виджетами. Сборка прозы
(`$абзац`, пулы фраз, правила героя, сумм и процентов) не трогается ни одной
строкой. Риск у слоя другой: блок двигает метрики страницы — слова, секции,
h2, ссылки. Поэтому порядок жёсткий: **один блок → парный замер → решение по
полосам** (исключить мебель из метрик, как сделано для страницы-каталога, либо
перемерить полосы по корпусу ТЗ).

### Слой Т — тексты полей режима Г

Пулы под новые блоки: заголовки и описания плиток, подписи быстрых ссылок,
анкоры перелинковки, абзацы SEO-блока. Отдельными файлами в `data-v5`;
существующие прозаические пулы не трогаются.

## 4. Порядок работ

Каждый шаг — отдельный коммит и отдельный замер.

| # | шаг | слой | риск для текста |
|---|---|---|---|
| 1 | версии блоков в CSS | О | нет |
| 2 | модификаторы элементов | О | нет |
| 3 | FAQ: схема и JSON-LD | О | нет |
| 4 | блок ключей: ссылки, размеры, заголовок | О | крошечный |
| 5 | перелинковка `related-sections` + парный замер | Б | есть, меряем |
| 6 | SEO-блок, таймер, всплывашки, поддержка | Б | есть, по одному |
| 7 | C-блоки с жребием наличия 0/1/2/3 | Б | есть |
| 8 | поля режима Г | Т | есть |

## 5. Что нужно решить до слоя Б

Корпус цели. Либо (а) остаёмся на NEW100 и берём из ТЗ только то, что в нём
есть — тогда слой О целиком, а из мебели только `cta-block` (12 из 79); либо
(б) целимся в корпус ТЗ — тогда надо перемерить профиль и полосы по
`samples/v3-reference/7` и той сборке, с которой ТЗ снято, и мебель ставится
вся. Слой О безопасен и нужен в обоих случаях, поэтому начинается сразу.

# Слой О сделан: что вошло и что замер отменил

## 1. Версии блоков в CSS — сделано

`verstka-v5.php` стилизовал по первому классу элемента, поэтому `variant-v1…v4`,
который наши страницы несут давно, ничего не менял: все четыре версии выглядели
одинаково. Добавлен проход `vsВерсииПоБлокам`: он идёт после базовой вёрстки,
находит рамку блока по отступу и дописывает объявления версии к уже готовым
`style=`. Правила — из ТЗ, для шести блоков, которые у нас есть: `hero-value`,
`value-pillars`, `slots-dashboard` (вместе с карточками), `recent-payouts-block`,
`page-thematic-block`, `faq-section`.

Два отступления от ТЗ, оба вынужденные:

- **Псевдоэлементы не ставятся.** `::before` у маркера FAQ и `::after` у стрелки
  инлайном не задаются; от версий v3 и v4 остаётся всё остальное.
- **Заливки фона сняты.** В ТЗ версии красят фон (`rgba(0,0,0,.22)` и подобные),
  но наши наборы — фрагменты, фон даёт шаблон сайта, и наши подложки нарочно
  прозрачные (`ПОДЛОЖКА` = transparent, см. комментарий в вёрстке: своя заливка
  давала белый текст по белому). На светлой теме тёмная заливка читается серой
  плашкой — это было видно на наборе 825. От версии остаётся костяк: колонки,
  карусель, пунктир, срезанное содержимое. Пунктир берётся от канта темы.

**Текста правка не касается.** Проверено дословно: у наборов 823–825 текст
оформленных страниц со снятыми тегами **побайтно совпадает** с выдачей до
правки. Самопроверка оформления не изменилась: «картинок 24 img-тегов 24
битых 0».

## 2. Что замер отменил

Три остальных пункта слоя О при проверке оказались уже в корпусной норме.

**Модификаторы элементов — совпадают.** Доли бейджа карточки слота: у доноров
нашей семьи high 632 / medium 237 / low 79 = **67 / 25 / 8 %**, у нас 80 / 30 / 10

Цвет джекпота через `--jp-color` не встречается ни у них, ни у нас — это из
другого корпуса.

**Редкие строки выплат — не вёрстка, а числа.** `mega` и `jackpot` у нас
отсутствуют, и это верно: тип строки у доноров — функция суммы, полосы почти не

**Блок ключей** в нашей семье не встречается вовсе (0 из 79) — это мебель из

1. **Поля мебели** (`sections`, `h2`, `paragraphs`, `words`, `anchors`,

   **после** того, как мебель встанет: цель без блока означала бы требование

2. **Поля фактуры прозы** (`words_per_para`, `para_spread`, `water`, `adj_pct`,
   `nausea_acad` в части прозы) — остаются на текущем профиле: мы внутри

3. **Полосы** не пересчитываем, пока наборов этой семьи два. Для количеств
   элементов берём полосы ТЗ (они по 70–100 наборам), для остального — текущие
   полосы NEW100, а мебель из метрик исключаем так же, как сделано для
   страницы-каталога (`V5_POLIA_KATALOGA`).
4. Появятся ещё наборы этой семьи — перемеряем полосы по ним и правило 18
   перестанет мешать.

# Слой Б, блок 1: перелинковка `related-sections`

## Как сделано

Блок собирается **пост-проходом**, когда готовы все двенадцать страниц:
карточки ведут на соседние страницы и берут тексты из них, а они готовы только
к концу сборки. Проза этим проходом не трогается — блок дописывается в конец
страницы. Разметка повторяет эталон: `ItemList` → `ListItem` с `position` →
вложенная `Article` со ссылкой, `headline` и `description`.

**Тексты карточек — режим Г по построению, без единого нового пула.** Наши h2
устроены как «Казино %brand%: Фриспины — Крутишь бесплатно, вейджер остаётся»:
до тире короткий заголовок, после тире готовая подпись. Карточка берёт h2 той
страницы, на которую ведёт, и разбирает его надвое. Текст уже сгенерирован под
этот набор, значит уникален по построению — у доноров на этом месте 3–4 строки
на 75 сайтов. Из пулов остались только шапка блока (8 форм) и подводка (6).

На пробном наборе: 96 карточных строк, **49 различных** внутри набора.

## Что пришлось починить по дороге

**Имя героя и сумма в анкоре.** Первая проба принесла на `info` карточку
«Марат сорвал 410к здесь» со страницы slots, и сито честно показало «одно имя —
разные истории»: имя и сумма привязаны к своей странице, анкор их переносить не
должен. Теперь заголовки с суммой, процентом или именем из банка набора
в карточки не берутся. После правки: чисел в карточках 0, сито 0 нарушений.

**Мерка считала мебель прозой.** Блок добавляет на каждую страницу секцию,
заголовок и четыре ссылки — приёмка сразу дала 8 провалов, и все по `sections`
и `h2`. Это не порча текста, а то, что профиль и полосы сняты с корпуса без
мебели. В `PageMetrics::measure` добавлено вычитание мебели перед замером (как
и было спланировано, по образцу `V5_POLIA_KATALOGA`): провалов стало 2 —
обычное число для сырого сида. Вычитание снимется, когда мебель встанет
целиком и профиль будет перемерен по корпусу ТЗ.

## Оформление

Базовые правила восьми новых классов в `verstka-v5.php`, версии v2/v3/v4 из ТЗ
(две колонки, карусель, пунктир в одну колонку), `related-cards` и

## Мебель не должна касаться текста — парный замер

Условие задачи: новые блоки не ломают текст. Это проверяется, а не
обещается. Стенд: один и тот же журнал, те же шесть сидов, две руки —
сборка без блока (коммит `2b76d6c3`) и с блоком. Обе руки прогоняются
целиком, потом с «после» снимается мебель и страницы сравниваются побайтно.

**Первая проба провалилась: 54 страницы из 72 разошлись.** Расхождения были
не в блоке, а в самой прозе: `-Демо доступно без входа` / `+Демо доступно без
доступа`, `-турнирах` / `+марафонах`. Причина — перекрут обрабатывает файл
целиком, текст блока попадает в его бюджет синонимов, и выбор слов в прозе
съезжает. То есть блок менял текст, которого не касался.

**Починка — мебель отрезается перед перекрутом и возвращается после.**
`v5OtsechMebel` / `v5VernutMebel` в `V5Blocks.php` режут по списку классов
`V5_MEBEL`, забирая байты как есть вместе с отступом, поэтому возврат простой
склейкой точен: round-trip проверен на 67 страницах, расхождений 0.
После починки — **0 страниц из 72**. Проза побайтно та же.

## Чего не покрыла первая починка: ворота по ссылкам

Проза совпала, а приёмка всё равно стала строже: промахи 2.17 → 3.67 на набор.
Разобрали по одной паре страниц, которые побайтно одинаковы вне блока:

```
БЕЗ   ✗ obzor 43/46 93% — fact_values 3→7, brand_ru 6→3, anchors 8→4
С     ✗ obzor 43/46 93% — fact_values 3→7, brand_ru 6→3, anchors 8→4   ← то же
С     ✗ чужие адреса: /news, /bonus, /partnery, /promo, /info, /obzor  ← новое
С     ✗ ссылок на obzor: 49, полоса корпуса 32–48                      ← новое
```

Постраничные поля совпали до цифры — вычитание мебели в `PageMetrics` работает.
Новыми оказались два **комплектных** ворота, которые считают по сырому html
мимо `PageMetrics`: список допустимых адресов и полоса входящих ссылок на тип.
Блок по построению ставит на каждую страницу пять ссылок во все стороны —
именно то, чего в корпусе без мебели нет.

Поэтому в `priyomka-v5.php` страница кладётся в `$всеHtml` уже без мебели:
комплектные ворота (ссылки, чужие адреса, шинглы, бренд, падежи) судят ту же
страницу, что и постраничные. После правки обе руки дают одно и то же число
провалов на всех шести парах.

Оба вычитания — временные, по правилу 18: полосы сняты с корпуса без мебели.
Снимутся вместе, когда мебель встанет целиком и профиль будет перемерен по
корпусу ТЗ.

## Третьи ворота: смысл

Приёмку починили, а партия 828–832 всё равно встала — сто попыток подряд без
единого набора. Виноват оказался третий страж, `smysl-v5.php`: у него свой
список допустимых адресов, и блок дал 25 находок «адрес вне корпуса» против
одной в руке без блока. Теперь и он получает страницу без мебели.

Контроль — весь ряд ворот (сверка → приёмка → смысл) на обеих руках, строка
против строки:

```
nabor-960  ✗ провалов: 3 | смысл          nabor-960  ✗ провалов: 3 | смысл
nabor-961  ✗ провалов: 2                  nabor-961  ✗ провалов: 2
nabor-962  ✗ провалов: 2 | смысл          nabor-962  ✗ провалов: 2 | смысл
nabor-963  ОК — ворота прошёл             nabor-963  ОК — ворота прошёл
nabor-964  ✗ провалов: 6                  nabor-964  ✗ провалов: 6
nabor-965  paragraphs 23.83 | смысл       nabor-965  paragraphs 23.83 | смысл
```

Все шесть пар совпали. Один набор из шести проходит ворота целиком — это
обычная доля, по ней партия и считалась раньше.

## Рама блока — теперь режим Г

Замер шести наборов: **72 шапки, различных 8; 72 подводки, различных 6.**
Карточки режим Г держали (тексты берутся из h2 своих страниц), а рама — нет:
ровно та дыра доноров, про которую ТЗ пишет «заголовок блока перелинковки — по
одной строке на 75 сайтов, не копировать».

Готовые списки заменены сборкой по шаблону. Шаблон идёт **со своими пулами**, а
не с общим словарём: общий давал «Связанные страницы в соседние разделы» и

страницы («Что почитать после раздела о бонусах»), так что рама привязана к
своей странице, а не только к жребию. Внутри набора шапки не повторяются —
список занятых идёт общим на все двенадцать страниц.

# Слой Б, блок 2: SEO-блок `yandex-index-only`

## Форма взята с замера, а не с ТЗ

ТЗ описывает блок по главной: шапка, три абзаца, 6–10 ссылок, «версий нет».
В корпусе (`samples/v3-reference/7`, единственный полный набор с этим блоком)
форма другая и зависит от страницы:

| | шапка | абзацев | ссылок |
|---|---|---|---|
| main | «Официальный портал и разделы» | 3 | 11 — во все прочие разделы |
| внутренние | своя на каждую страницу | 2 | 4–5 — соседи плюс «главная» |

Смежность тоже своя у каждой страницы: `vhod → registracia, zerkalo, bonus`,
`slots → bonus, registracia, obzor, promo` и так далее. Взяли замер: ТЗ
обобщило главную на все двенадцать.

Прячется блок приёмом visually-hidden — `position:absolute`, 1×1,
`clip-path:inset(50%)`. Не `display:none`: текст должен оставаться в индексе.

## Режим Г

Абзац собирается как «голова» плюс перечисление из трёх-четырёх хвостов,
выбранных без возврата и в случайном порядке. Шапка — ядро, связка и довесок,
каждый со своим пулом.

```
абзацев 1500, различных 1441 (96.1 %)   ← цель ТЗ «выше 90 %»
шапок    960, различных  557, повторов внутри набора 0
```

## Склейку шаблонов надо проверять, а не надеяться

Первая сборка дала «Основной адрес и вход и регистрация» и «Бонусы и промо и
промо»: довесок сам содержал «и», а то и повторял слово ядра. Ровно та же
болезнь была в перечислении хвостов («бонусы и промокоды и служба поддержки»).

Добавлена проверка `v5SklejkaChitaetsya`: не больше одного «и» и без повтора
знаменательных слов; `v5NePovtoryaya` принимает её и перебрасывает, пока строка
не станет годной. На 960 шапках негодных 0. Проверка поставлена и на раму
перелинковки — там та же сборка по шаблонам.
