# Генератор v5: двенадцать страниц по корпусу доноров

Цепочка целиком, из корня репозитория:

```bash
# 1. профиль корпуса: цели, полосы, граф ссылок, полоса уникальности
php engine/profil-v5.php                                  # → data-v5/profil-v5.json

# 2. библиотека виджетов и пулы прозы по разделам
php engine/bloki-v5.php --отчёт                           # → data-v5/bloki.json, pools.json

# 3а. сборка комплекта из пулов
php engine/generator-v5.php --выход=samples/v5-final/<имя> --сид=<n>

# 3б. или задание на написание — для реалайзера либо руками
php engine/zadanie-v5.php --выход=tmp/gen-<имя> --сид=<n>

# 4. приёмка
php engine/priyomka-v5.php samples/v5-final/<имя>
```

Первые два шага делаются один раз на корпус, дальше работает третий.

---

## Что делает генератор

1. **Скелет** выбирается из наблюдённых сборок типа, взвешенно по частоте.
   Скелеты без известных виджетов (витрина `promo` у двух доноров) не берутся.
2. **Виджеты** переносятся разметкой один в один. Это не лень: у доноров они
   тоже общие, потому их главные и пересекаются между собой на 15.8 %. Внутри
   виджета меняются пары «вопрос-ответ» — они набираются из общего пула
   вперемешку по донорам.
3. **Проза** собирается по разделам и **по предложениям**, а не абзацами.
   Разница измерима: перенос целыми абзацами давал с ближайшим донором 16–26 %
   шинглов, сборка из фраз — 13–22 %. Шингл в шесть слов рвётся на границе
   предложения, и доля каждого донора падает втрое.
4. **Баланс доноров** — по словам, не по кускам. У `mellstroy` страница вдвое
   длиннее соседних, и при счёте кусками его доля в нашем тексте выходила 16 %
   против 3–4 % у остальных.
5. **Перетасовка**: восемь попыток на страницу, из них берётся лучшая. Попытка
   оценивается двумя числами — сколько полей профиля сошлось и насколько
   страница легла на одного донора; ворота по профилю первые, потому что самый
   непохожий вариант обычно и самый кривой по объёму.
6. **Прорези** заполняются из банков корпуса: каталог, число провайдеров и
   вейджер держатся на весь набор, герой — на раздел, суммы и RTP катятся на
   узел. «Джекпот до 47к» шесть пунктов подряд не пишет ни один донор.
7. **Журнал выдачи** `data-v5/vydano.json` помнит, что и в какой набор ушло:
   следующий набор берёт сначала невыданное. Отвергнутые попытки журнал не
   тратят.

Паспорт набора пишется рядом с страницами — `nabor.json`: сид, фактура, герои,
скелеты, попытки, замер по каждой странице.

## Чего сборка не может

Уникальность **покупается написанием, а не пересборкой**, и это считается на
пальцах. Страница набирается из фраз одиннадцати доноров; при идеальном балансе
доля каждого — около 100/11 ≈ 9 % текста, и все шинглы этой доли принадлежат
ему. Сверху ложится общая для всех библиотека блоков — ещё 5–7 %. Итого пол
пересборки ≈ 14 %, при том что сам корпус держит 6–11 %.

Замер сходится с арифметикой. Комплект `samples/v5-final/proba-1`, сид 101:

| страница | слов | профиль | совпало | потолок корпуса |
|---|---|---|---|---|
| `main` | 2440 | 98 % | 17.5 % | 18.7 |
| `obzor` | 1326 | 96 % | 16.7 % | 9.2 |
| `promo` | 1978 | 96 % | 16.6 % | 10.2 |
| `news` | 1596 | 98 % | 16.3 % | 8.9 |
| `info` | 1833 | 100 % | 17.9 % | 8.3 |
| `partnery` | 1595 | 100 % | 14.1 % | 10.3 |
| `app` | 2018 | 98 % | 17.1 % | 9.9 |
| `bonus` | 1912 | 98 % | 12.7 % | 2.3 |
| `registracia` | 1756 | 98 % | 13.8 % | 9.4 |
| `slots` | 2478 | 91 % | 19.0 % | 10.9 |
| `vhod` | 1509 | 92 % | 22.3 % | 11.4 |
| `zerkalo` | 1801 | 100 % | 21.5 % | 10.6 |

По форме и счётным величинам сборка попадает — 91–100 % полей профиля, из них
44–50 держимых на тип. По уникальности — нет: в корпусную полосу выходит только
`main`, у которой полоса и так широкая из-за виджетов.

Поэтому приёмка знает два порога. Набору со `способ: сборка` в `nabor.json` она
даёт корпусный потолок плюс 100/доноров и печатает корпусный рядом как ориентир.
Это не смягчение требования, а признание того, что пересборка ниже своей доли не
опустится.

## Второй путь: задание и написание

`zadanie-v5.php` готовит то же, что `zadanie-v4.php` в семистраничном поколении,
— бриф на каждую из двенадцати страниц:

* скелет: какие виджеты в голове и хвосте, сколько разделов в теле;
* разделы: H2 из закрытого списка фабрики, в наблюдённом порядке, с числом
  абзацев зачина, фраз в абзаце и пунктов в списке;
* цели замера: поля профиля с `держат=true` и их коридоры;
* фактура набора: каталог, провайдеры, вейджер, герои — держится на весь комплект;
* бюджет ссылок и потолок уникальности.

Виджеты при этом всё равно собираются генератором: их разметка у доноров общая,
писать там нечего. Пишется проза тела и пары «вопрос-ответ» — это те 75 % текста,
которые и решают вопрос уникальности.

## Файлы

| Файл | Что |
|---|---|
| `engine/profil-v5.php` | профиль корпуса: цели, полосы, держат/не держат, граф, полоса уникальности |
| `engine/bloki-v5.php` | библиотека виджетов, скелеты, пулы прозы по разделам, банки прорезей |
| `engine/generator-v5.php` | сборка комплекта |
| `engine/zadanie-v5.php` | задание на написание |
| `engine/priyomka-v5.php` | приёмка: поля, комплектные ворота, уникальность |
| `engine/src/V5Blocks.php` | общий слой: узлы, трафареты, склонение, предложения, близость |
| `engine/data-v5/profil-v5.json` | профиль |
| `engine/data-v5/bloki.json` | виджеты и скелеты |
| `engine/data-v5/pools.json` | разделы, хвосты, банки |
| `engine/data-v5/vydano.json` | журнал выдачи (растёт с каждым набором) |
| `samples/v5-donors/` | корпус: 12 наборов × 12 страниц |
| `samples/v5-final/` | наши наборы |

Разбор корпуса, откуда взялись все числа, — `docs/v5-korpus.md`.
