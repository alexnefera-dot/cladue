# Партия 858–862

Пять наборов. Первая на исправленном страже процентов и исправленном
дедупликаторе списков.

## Итог замера

```
наборов: 5
сито всего 2 (0.40 на набор)
   одно имя — разные истории                  2
промахи приёмки: [0, 0, 0, 0, 0] | ср 0.00
пар ср 64.00 мед 63.0 | мельче млн 0.00 | равных 0.00
«джекпот»/1000 ср 3.65 мед 3.53 | «куш»/1000 ср 0.97
наборов с мелким джекпотом: 0 из 5
```

Попыток **40** против 116 прошлой партии: 20, 4, 4, 8, 4. Тринадцать минут
вместо тридцати шести.

**«Пакет звучит разными числами» не сработало ни разу** — в прошлой партии
находок по этому правилу было две. На пяти наборах это не доказательство
(правило выпадает 0.2–0.4 на набор), но сходится с прямым проигрышем стража
на фразе набора 853.

**Висячих «до» ноль.** Дедупликатор больше не вынимает число из тела фразы.

## Манера: ПОПРАВКА — жребий не бросался

**Здесь было написано неверно.** Я написал, что драйвер сам бросил жребий и
дал пять обычных наборов. Жребия не было: правку я внёс только в
`попытка()`, а решение принимается в `набор()` и передаётся работникам
готовым. В `набор()` остался прежний `номер in ГУСТЫЕ`, а без `V5_GUSTYE`
это пустое множество — то есть «обычный» всегда.

Результат совпал с тем, что дал бы жребий (на 858–862 он тоже давал ноль
густых), и потому ошибка не была видна. Она вскрылась на следующей партии:
жребий велел три густых, вышло ноль.

Исправлено в `набор()`; партия 863–867 пересобрана и получила густыми ровно
те наборы, которые назвал жребий.

## Проверка, которая оказалась ложной тревогой

Заметил, что у 858 и 859 один процент пакета (150 %), и посчитал повторы у
соседних наборов по всему корпусу — вышло 59.5 % против случайных 3.2 %.
Цифра оказалась мусором: скрипт считал наборы без поля `процентПакета` в
паспорте (все до 500-го) совпадающими друг с другом. По наборам, где поле
есть, повтор у соседей 0–8 % по окнам в полсотни. Дефекта нет.
