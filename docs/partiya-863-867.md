# Партия 863–867

Пять наборов. Первая, где жребий манеры действительно сработал, и первая с
нулевым ситом.

## Итог замера

```
наборов: 5
сито всего 0 (0.00 на набор)
промахи приёмки: [0, 0, 0, 0, 0] | ср 0.00
пар ср 56.20 мед 54.0 | мельче млн 0.00 | равных 0.00
«джекпот»/1000 ср 3.78 мед 3.81 | «куш»/1000 ср 0.91
наборов с мелким джекпотом: 0 из 5
```

**Сито 0 — такого ещё не было.** Прежние партии давали 0.20–1.10 на набор.
Два правила, которые портили последние партии, закрыты: «пакет звучит
разными числами» починен стражем процентов, висячих «до» нет после правки
дедупликатора.

Попыток **276** за 80 минут: 20, 8, 36, 12 и **200** на набор 867.

## Жребий манеры: сначала не сработал, потом сработал

Партия собиралась дважды.

**Первый раз** все пять вышли обычными, хотя жребий велел густыми 863, 865
и 867. Причина: правку жребия я внёс только в `попытка()`, а решение
принимается в `набор()` и передаётся работникам готовым. В `набор()`
остался прежний `номер in ГУСТЫЕ`, без `V5_GUSTYE` — пустое множество.

На партии 858–862 этого видно не было: там жребий и сам давал ноль густых,
результат совпал по случайности. Отчёт по 858–862 в этой части исправлен.

**Второй раз**, после правки в `набор()`, густыми вышли ровно 863, 865, 867.
Партия удалена и пересобрана целиком, журнал возвращён к состоянию после
858–862; сданные партии это не задело.

**Цена густой манеры видна сразу.** Набор 867 потребовал 200 попыток из 276
на всю партию — густой набор проходит ворота заметно реже. Это та самая
причина, по которой манеру когда-то назначали рукой; теперь цена платится
временем, а не периодичностью в корпусе.

Доля густых по корпусу 6.9 % → 7.3 %. До корпусных 28 % далеко: восемь
сотен прежних наборов тянут вниз, и выравниваться будет медленно.
