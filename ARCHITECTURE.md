# Непотопляемая архитектура редиректора

## Суть

Раньше: каждый клик `/go/*` = запрос к MySQL (чтение оффера + запись клика).
Под нагрузкой/DDoS база захлёбывалась → редиректы падали (522).

Теперь: **редирект вообще не трогает базу.**
- Офферы читаются из файла-кэша `offers.php` (мгновенно).
- Клик пишется одной строкой в файл `clicks.log` (атомарный append).
- Раз в 5 минут крон-скрипт `import.php` переливает лог в MySQL.

**Результат:** MySQL может лежать, тормозить, быть под DDoS — редиректам всё равно.
Они зависят только от файловой системы, которая тянет любой поток.

## Поток данных

```
Юзер → /go/dorgen_engine
         │
         ├─ go.php читает оффер из offers.php (файл, без БД)
         ├─ пишет клик строкой в clicks.log (append, без БД)
         └─ отдаёт 302 → партнёрка
                            
Крон (раз в 5 мин):
   import.php: clicks.log → MySQL (батч), потом чистит лог
                            
Панель stats.php: читает из MySQL (задержка до 5 мин)
```

## Файлы

| Файл | Что делает | Трогает MySQL? |
|------|-----------|----------------|
| `go.php` | редирект + запись клика в лог | **НЕТ** |
| `offers.php` | автогенерируемый кэш slug→URL | — (это данные) |
| `clicks.log` | накопитель кликов (TSV) | — (это данные) |
| `import.php` | крон: лог → MySQL | да (раз в 5 мин) |
| `stats.php` | панель | да (чтение) |
| `postback.php` | приём постбеков | да (запись конверсий) |
| `db.php` | общие функции + генерация offers.php | да |

## Установка

### 1. Залей файлы
`go.php`, `db.php`, `import.php`, `config.php` (+ `stats.php` если обновлял).

### 2. Настрой config.php
Проверь/добавь:
```php
'db_write'    => true,           // писать клики (в лог)
'fallback_offer' => '',          // пусто (аварийный режим выключен)
'click_log'   => __DIR__ . '/clicks.log',  // путь к логу (или оставь дефолт в tmp)
```
И убедись, что MySQL-креды заполнены (mysql_db, mysql_user, mysql_pass) — они
нужны для import.php и панели.

### 3. Построй кэш офферов первый раз
Открой в браузере (один раз):
```
https://sitegrator.com/import.php?key=ТВОЙ_POSTBACK_SECRET
```
Это создаст `offers.php` из текущих кампаний в базе. Проверь, что файл появился.

Или зайди в панель и пересохрани любую кампанию — кэш построится автоматически.

### 4. Настрой крон
ispmanager → CRON jobs → Create plan:
- Команда: `/opt/php82/bin/php /var/www/www-root/data/www/sitegrator.com/import.php`
- Расписание: раз в час → `0 * * * *`

⚠️ **ВАЖНО: только `/opt/php82/bin/php`, НЕ `/usr/bin/php`.**
Системный `/usr/bin/php` на этом сервере — PHP 7.2, он не понимает стрелочные
функции (`fn()`) в db.php и падает с `PHP Parse error: unexpected '=>'`.
Импорт при этом умирает молча (вывод уходит в `>/dev/null`), клики копятся
в clicks.log и не попадают в базу — в панели выглядит как «клики не пишутся».
Проверить версию: `/opt/php82/bin/php -v` → должно быть 8.2.x.

Сохрани. Теперь клики автоматически переливаются в базу раз в час.

### 5. Проверь
```
# редирект работает и пишет в лог:
curl -sI "https://sitegrator.com/go/dorgen_engine" | grep -i location

# лог наполняется (зайди в файловый менеджер, глянь clicks.log — растёт)
# через 5 минут (или запусти import.php вручную) клики появятся в панели
```

## Как работает защита от падений

- **Пик трафика ×100** → go.php только пишет строки в файл (дёшево). Держит.
- **DDoS на /go/** → то же самое, файл тянет тысячи строк/сек. Держит.
- **MySQL лёг** → клики копятся в clicks.log. Редиректы работают. Когда MySQL
  оживёт, import.php всё зальёт. Ничего не теряется.
- **Крон не отработал** → клики просто копятся в логе дольше, зальются следующим
  запуском. Не теряются.
- **import.php упал на середине** → использует .processing файл, докатит при
  следующем запуске.

⚠️ Оговорка про .processing: импорт коммитит пачками по 500 строк. Если процесс
**прервать вручную** (Ctrl-C) посреди заливки большого лога, уже закоммиченные
пачки останутся в базе, а `.processing` не удалится — следующий запуск зальёт
файл целиком заново и получатся дубли. Не прерывай импорт: на 100k кликов он
идёт ~1.5 минуты и после `offers.php обновлён` работает молча (это норма, не
зависание). Если дубли всё же появились — почистить так:

```sql
DELETE c1 FROM clicks c1 JOIN clicks c2
  ON c1.clickid = c2.clickid AND c1.id > c2.id
WHERE c1.clickid <> '' AND c1.clickid IS NOT NULL;
```
(clickid — 64-битный рандом, совпадение = повторный импорт, а не два разных клика)

## Аварийный режим (если совсем всё плохо)

Если даже запись в лог не нужна и надо просто слать всех на один оффер:
```php
'db_write'       => false,
'fallback_offer' => 'https://fnx-abs.net/di6viifma',
```
Тогда go.php даже лог не пишет — чистый редирект на один URL. Максимальная
разгрузка.

## Важные детали

- **offers.php обновляется автоматически** при изменении оффера в панели
  (add_campaign, update_offer, replace_offer_domain, delete_campaign).
  Плюс import.php обновляет его каждые 5 минут на всякий случай.
- **clickid** генерится в go.php и пишется в лог → попадает в MySQL при импорте.
  Привязка постбеков работает как раньше.
- **Уники/статистика** в панели — с задержкой до 5 минут (пока крон не импортнул).
- **Ботов** go.php помечает грубо (по UA). Точность та же, что была.
- **Флуд-лимит** сейчас не в go.php (убран, чтобы не читать состояние). Защита от
  флуда — на Cloudflare (rate limit правило). Это правильнее — режется на периметре.

## Обслуживание

- Файл `clicks.log` между импортами маленький (5 минут кликов). После импорта
  удаляется. Расти не должен.
- Если крон отвалится надолго — лог вырастет, но не потеряется. Проверяй, что
  крон работает (в панели статистика обновляется — значит импорт идёт).
- Логи import.php можно смотреть, запустив вручную:
  `https://sitegrator.com/import.php?key=СЕКРЕТ` — покажет, сколько импортнул.
