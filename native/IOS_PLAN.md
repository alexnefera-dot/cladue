# Pipboy iPhone + синхронизация — план и архитектура

Цель: один код → две версии (Mac + iPhone), правки идут в обе сразу, данные
синхронятся между устройствами без облака.

## 1. Общий код (как добиться «правки в обе версии за раз»)
Один Xcode-проект, **два таргета**: `Pipboy` (macOS) и `Pipboy iOS`.
- **Фронт (`app/public`) — общий**: тот же HTML/JS/CSS на обеих платформах.
  - Mac: читается с диска (`~/Downloads/cladue/app/public`), обновляется `git pull`.
  - iOS: **вшит в бандл** (папка-ресурс); обновляется при пересборке ИЛИ присылается
    с Мака при синхронизации (см. §4) — тогда веб-правки долетают без пересборки.
- **Слой данных — общий** (добавлен в оба таргета, кросс-платформенный):
  `Database.swift`, `Keychain.swift`, `Crypto.swift`, `Notifications.swift`,
  `NativeAPI.swift`, `AuthGate.swift`, `SyncService.swift`.
- **Платформенные части** — через `#if os(macOS)` / `#if os(iOS)`:
  - `WebView`: `NSViewRepresentable` (Mac) / `UIViewRepresentable` (iOS).
  - вход в приложение/сцена, авто-замок (NSEvent на Mac / scenePhase на iOS),
    экспорт (NSWorkspace на Mac / share sheet на iOS), `git pull` (только Mac).

Итог: 90% кода общее. Веб-правка = обе версии. Правка слоя данных = обе версии
(один файл). Только правка «оболочки» бывает платформенной.

## 2. Данные на iPhone
- Зашифрованная SQLCipher-база в `Documents` приложения.
- Ключ — в Keychain под Face ID (data-protection keychain на iOS работает «из коробки»).
- Поверх — iOS Data Protection (`NSFileProtectionComplete`): файл шифруется ОС, когда
  телефон заблокирован.
- **Чистый старт**: на новом устройстве база пустая → сидируем каркас категорий
  (перенесём `seed()` из `db.js` в нативный `Schema.swift`), либо первая синхра с Мака
  зальёт всё.

## 3. Сборка iOS (что нужно от тебя в Xcode — позже)
- Добавить таргет **iOS App**, минимальная iOS 16.
- Добавить общие .swift в оба таргета (галки Target Membership).
- Добавить `app/public` как **folder reference** в ресурсы iOS-таргета.
- Подключить пакет `swift-sqlcipher` к iOS-таргету.
- Signing: твой Apple ID (Personal Team) → 7-дневный триал-запуск на айфоне без $99.

## 4. Синхронизация Mac ↔ iPhone (без облака)
**Принцип:** обе базы равноправны; обмен изменениями по локальной сети (один Wi-Fi).

**Схема данных под синк (добавляем в обе версии):**
- у всех таблиц — стабильный `id` + `updated_at` (уже есть у большинства; добьём где нет).
- **`tombstones(table, row_id, deleted_at)`** — журнал удалений (иначе удалённое
  «воскреснет» при мердже).
- **`sync_state(peer, last_sync)`** — до какого момента синхронизировано с конкретным
  устройством.

**Транспорт:** Mac поднимает локальный слушатель (Network.framework, Bonjour-имя
`_pipboy._tcp` в локальной сети). iPhone находит Mac по Bonjour и подключается, когда
оба в одном Wi-Fi. (Телефон ↔ Мак напрямую, никаких серверов наружу.)

**Протокол (детерминированный, без AI):**
1. Рукопожатие: общий ключ из **парного кода** (QR/фраза, вводится один раз на обоих) —
   им шифруется весь обмен (AES-GCM поверх TLS).
2. A шлёт B все строки с `updated_at > last_sync(B)` + тумбстоны.
3. B мерджит: **last-writer-wins по `updated_at`** на строку; удаление побеждает, если
   `deleted_at` новее. Симметрично в обратку.
4. Обе стороны двигают `last_sync`.
- Конфликты решаются детерминированно (по времени), без ручного выбора.
- **Бонус:** в ту же сессию Мак может прислать свежий `app/public` → веб-апдейты
  долетают на iPhone без пересборки.

**Порядок реализации синка:** сначала схема (тумбстоны/updated_at/sync_state) в обе
версии → потом транспорт+мердж. Полноценно тестируется только когда обе апки живые.

## 5. Фазы
- **A. Мультиплатформа**: `#if os` в оболочке, iOS-WebView/сцена, путь к фронту
  (диск/бандл). После этого тот же код собирается под iOS.
- **B. iOS-апка standalone**: вшитый фронт, Face ID, своя зашифрованная база, пуши,
  сид для чистого старта. Запуск на твоём айфоне (триал).
- **C. Синхронизация**: схема → транспорт (Bonjour+Network.framework) → мердж
  (LWW+тумбстоны) → перенос фронта Mac→iPhone.

Правки по ходу — в общие файлы, т.е. сразу в обе версии.
