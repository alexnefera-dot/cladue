# Методика подсчёта позиций

## Загрузка данных
Excel читать **только** через BytesIO — прямой путь даёт BadZipFile:

```python
openpyxl.load_workbook(io.BytesIO(open(path,'rb').read()), data_only=True)
```

Файлы позиций приходят архивом (`Dorgen test.zip`). Служебные файлы, не входящие
в анализ доргенов: `brands_master.xlsx`, `converstion.xlsx`, `our-list-brands.xlsx`,
`motor.xlsx`, `enemies*.xlsx`, `serp_*.xlsx`.

## Структура файлов
- **brands_master.xlsx** — лист «Сводка», строка 3+: кол0=бренд, кол1=имя листа,
  кол4=объём рынка (кликов/мес). На листах бренда: кол0=запрос, кол1=клики.
  157 брендов, 276 093 уникальных запроса.
- **dorgenNNN.xlsx** — каждый лист = один замер. Строка 1: кол0=«Ключевое слово»,
  далее домены. Ячейка = позиция или `—`.

## Тиры
| Тир | Объём бренда |
|---|---|
| ВЧ | ≥ 1 000 000 |
| СЧ | 700 000 – 1 000 000 |
| НЧ | ниже |

Порог СЧ = 700k (не 300k, не 800k). Проверено: ни один другой порог не воспроизводит
старый рейтинг целиком — тот считался непоследовательно.

## Метрика
- Ключей домена в ТОП-3 / 10 / 30 / 50 / 100, разбито по тирам бренда.
- Основной показатель запуска: **ВЧ+СЧ в ТОП-10 на домен**.
- «Домен зашёл» = взял ≥1 ВЧ/СЧ ключ в ТОП-10.
- Считать по **последнему замеру**, не по пику.
- Сравнивать запуски **только на одинаковом номере замера**.

## Исключения
Домены с внешними манипуляциями:
`5936.team, cvnp.team, jvbs.team, zbrn.team, vmqk.team, casino28w.team, casino51m.team, kdnb.team`

Бренды, искажающие статистику: `vovan`, `pari`.

D274: `fkmz.team` (накрут на motor) и `gltb.team` (накрут на ramenbet) — считать отдельно.

## Формат выгрузки launches_*.xlsx (новые группы)
Лист «Сводка» + по листу на группу. На листе группы **несколько блоков** по 1570 ключей,
каждый со своим заголовком `Ключ \\ Домен`:

- блоки с меткой `Снимок ДД.ММ ЧЧ:ММ XML` над заголовком — **это замеры**;
- **последний блок без метки — среднее арифметическое** всех снимков, НЕ замер.
  Проверено: 77 и 66 дают 71, 4 и 6 дают 5, 20 и 16 дают 18. Где значение есть
  только в одном снимке — берётся оно.

Считать только блоки с меткой «Снимок». Усреднённый блок ломает метрику:
методика требует последний замер, а не среднее и не пик.

При одном снимке средний блок совпадает со снимком и выглядит как дубликат —
дедупликация по хешу его отсеет, но полагаться на это нельзя.

Позиции — числа, отсутствие — пустая ячейка (`None`), а не `—` как в старых dorgen-файлах.

## Обязательные проверки перед подсчётом
1. **Дубликаты листов.** Считать хеш содержимого, а не доверять именам.
   Подтверждённые дубли: D233 (Sheet5), D241 (Sheet4, Sheet11), D245 (Sheet6),
   D251 (Sheet2 дубль + Sheet4 пустой), D252 (Sheet6), D265 (Sheet3),
   D266 (Sheet2), D267 (Sheet5).
2. **Пустые листы.**
3. **Формат выгрузки.** У D273 Sheet1 содержит 91 строку вместо 1570 — это компактный
   формат, где перечислены только ранжирующиеся ключи. Данные полные, замер засчитывать.
   Отличать от реально усечённой выгрузки: сравнить число ключей с позицией.
4. **Домены на 2-м и 3-м листе.** Собирать список доменов со ВСЕХ листов.

## Известные особенности файлов
- `dorgne247.xlsx` — это **D248** (опечатка в имени).
- D266 целиком вложен в D267 (те же 20 доменов + 20 новых).
- D256 и D254 — по одному замеру, для сравнений динамики непригодны.

## Порядок запуска скриптов
```bash
pip install openpyxl
python3 build_brands.py    # brands.pkl  — справочник запрос → бренд → тир
python3 core.py            # meas.pkl    — замеры с дедупликацией листов
python3 traj.py            # traj.pkl    — траектории по номерам замеров
python3 mkdata.py          # data.json   — данные для отчёта
# сборка HTML: tpl.html + app.js + data.json через html.replace('__DATA__', dj)
```

Прочие скрипты — отдельные срезы: `cmp.py` (форматы и равный возраст),
`zones.py` / `controlled.py` (зоны с контролем по запуску), `otsev.py` и `peak.py`
(правила отсева), `brands_rep.py` (бренды), `rowcheck.py` (полнота листов).

## Отчёты
HTML, тёмная тема, вкладки, раскрывающиеся строки.
JSON вставлять через `html.replace('__DATA__', dj)`, **не** через f-string.
Проверять рендер через Playwright (`shot.py`) до публикации.
