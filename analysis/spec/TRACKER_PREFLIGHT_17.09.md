# Трекер: проверка перед подключением (17.09) и первый доступ (18.09)

Второй источник — API трекера `sitegrator.com`, эндпоинты `/v1/clicks` и
`/v1/conversions`. Контракт: `API.md` в ветке `claude/sitegrator-redirector`.
Конверсии и клики берутся оттуда напрямую, CSV больше не нужен.

§1–2 — то, что удалось проверить **до** получения доступа, по уже выгруженным
данным запусков и по старому CSV. §3 и дальше — что показали живые данные,
когда доступ появился 18.09: ответы на те же вопросы, найденные дефекты и одна
крупная аномалия трафика.

## 1 · Состояние доступа

| | |
|---|---|
| сеть до `sitegrator.com` | **открыта** — приходит `401` от самого API, а не `403` от прокси |
| формат ошибок | совпадает с dorgen: `{"error":{"code":"unauthorized",…}}` |
| `TRACKER_BASE` / `TRACKER_TOKEN` | **есть, доступ получен 18.09** (в сессии 17.09 отсутствовали) |

Переменные окружения подставляются при старте контейнера, поэтому добавленные
позже в текущую сессию не попадают — нужна новая сессия в окружении `dorgen`.
Токен в переписку не передавать: по §2 передачи он живёт только в переменных
окружения.

Проверка после перезапуска:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TRACKER_TOKEN" \
  "$TRACKER_BASE/v1/conversions?date_from=2026-09-10&date_to=2026-09-17&limit=2"   # ждём 200
```

Живая выгрузка недели 11–17.09 прошла без единой ошибки: **1 960 376 кликов,
393 запроса, ноль 5xx, ноль 429**, 455 МБ, около получаса. Ничего похожего на
50–75% пятисоток у `/v1/subdomains` здесь нет — трекер отдаёт данные надёжно.
Механизм возобновления не понадобился ни разу.

### Cloudflare режет Python по User-Agent

Найдено при первом же вызове скрипта. Перед `sitegrator.com` стоит Cloudflare, и
он отвечает **403 Error 1010** на User-Agent вида `Python-urllib/*`:

| клиент | ответ |
|---|---|
| `curl` со своим UA | 401 (нормальный ответ API) |
| `curl -A "Python-urllib/3.11"` | **403 Cloudflare** |
| `urllib` без UA (шлёт `Python-urllib/3.11`) | **403 Cloudflare** |
| `urllib` с `User-Agent: cladue-analytics/1.0` | 401 (нормальный ответ API) |
| dorgen, `urllib` без UA | 200 — такого правила нет |

Поэтому `pull_tracker.py` шлёт явный `User-Agent`. Без него выгрузка упала бы на
первом запросе после получения токена, причём с ошибкой Cloudflare, которая ни
на что осмысленное не указывает.

## 2 · Ключ соединения работает, но 2% строк отравлены

Проверено на `analysis/konversii_7dney.csv` (164 конверсии 09–16.09) против
выгрузки `/v1/subdomains` за 11–17.09 (154 800 сабдоменов).

| | |
|---|---|
| конверсий с пустым ключом | **0 из 164** |
| уникальных сабдоменов в конверсиях | 132 |
| правдоподобный ключ (в выгрузке или в реестре доменов) | **160 из 164 (97%)** |
| ключ не опознан | 4 |

Из 74 сабдоменов, которых нет в выгрузке 11–17.09, **66 прослеживаются в
`launch_*.txt` за 24.08–10.09** — то есть это не поломка ключа, а запуски раньше
окна выгрузки. Соединение по `subdomain` состоятельно.

### Четыре отравленные строки — это подстановка хоста реферера

| `source` | `referer` |
|---|---|
| `arkadaclubplay.buzz` | `https://arkadaclubplay.buzz/` |
| `lelang.su` | `https://lelang.su/` |
| `yandex.com` | `https://yandex.com/images/sear…` |
| `pinco.jkrv.team` | `https://duckduckgo.com/` |

В первых трёх `source` **дословно равен хосту реферера**. Это ровно тот отказ,
который описан в контракте: без параметра `site=` трекер берёт `subdomain` из
хоста реферера. Значит подстановка не гипотетическая — она происходит и даёт
ключ, которого в нашей сети не существует (`yandex.com`, зона `.su`).

Четвёртая строка иная: `pinco.jkrv.team` по форме нормальный сабдомен, но
`jkrv.team` нет в реестре из 1864 доменов, а реферер — DuckDuckGo.

**Правило при подключении.** Строки, чей `subdomain` не найден ни в выгрузке
`/v1/subdomains`, ни в `domains_flat.txt`, в расчёт не брать. Но **не отбрасывать
молча** — считать и показывать их числом: рост этой доли означает, что дор
перестал передавать `site=`, и это надо заметить сразу, а не через месяц.

> **Уточнено 18.09 по живым кликам.** Признак «`subdomain` равен хосту
> `referer`» на конверсиях работал случайно, а на кликах даёт 14.4% ложных
> срабатываний: дор редиректит со своего же сабдомена, и реферером оказывается
> он сам. Настоящий признак — ключ, не подтверждённый ни реестром, ни системой
> запусков. См. §3-бис п. 2.

## 3 · Ответы по живым данным, 18.09

Выгрузка `/v1/clicks` и `/v1/conversions` за 11–17.09 (окно закрыто:
`stable_until` = 2026-09-18T00:00:05+03:00). Разбор — `tracker_clicks_rep.py`
и `tracker_conv_rep.py`. Всё ниже — только кампания `dorgen_engine`.

| проверка §3 старой редакции | ответ |
|---|---|
| доля кликов с `subdomain: null` | **0.02%** (373 из 1 531 821) |
| доля кликов с отравленным ключом | **0.39%** (5 977) |
| доля конверсий с пустым ключом | **0%** (0 из 145) |
| `clickid` конверсии найден среди кликов | **98.62%** (143 из 145) |
| `is_bot` | **32.0%** за неделю, к 17.09 — 52.3% |
| `landing_path` | `null` у 100% строк, как и ожидалось |
| `payout`, `status` | `null` у 100%, как и ожидалось |
| глубина истории | клики есть с **28.07**, раньше пусто |

**Главное неизвестное закрыто: системы соединяются.** Ключ у кликов заполнен
практически везде, а не выборочно, как опасались. Больше того, связка держится
на уровне отдельного клика: `clickid` 143 из 145 конверсий находится в выгрузке
кликов, оба несовпадения — клики старше окна выгрузки. Медианный лаг
клик → конверсия **0.8 часа**, максимум 97.9 ч, отрицательных нет.

Конверсия от клика на конвертнувших сабдоменах — **1.42%** (145 на 10 213
кликов), 1.53% если считать от не-ботовых. Ни один из 120 кликов, давших
конверсию, не помечен `is_bot` — флаг конверсии не режет.

### Ключ вне txt-реестра — это дыры в реестре, а не чужой трафик

По реестру `domains_flat.txt` (1864 домена) опознаётся 89.4% кликов. Оставшиеся
9.7% (148 882 клика, 27 485 сабдоменов) проверены точечно через
`/v1/events?subdomain=…`: из 40 доменов с наибольшим числом кликов **38
опознаны системой запусков** как наши (59 411 кликов из 62 690, 94.8%), окна
запуска — от 20.07 и позже, то есть раньше начала txt-реестра (24.08).

Не опознаны ни в одном окне с 20.06 только `3781.team` (1907 кликов) и
`2075.team` (1372) — возможно, запуски ещё старше или данные после hard-purge.

Вывод: реальная соединяемость по ключу ≈ **99%**, а 89.4% — артефакт неполного
txt-реестра. Для отбора «наших» строк реестр не годится, нужна выгрузка
`/v1/subdomains` или проверка через `/v1/events`.

### `linked_at` — это не «строка финальная»

У всех 162 конверсий недели `linked_at` **один и тот же** —
`2026-09-17T23:36:21+03:00`. Это отметка последнего прогона связывания, а не
время привязки конкретной строки. Медианный «лаг» `at` → `linked_at` в 67 часов,
который получается при наивном чтении, смысла не имеет. Опираться на поле как на
признак устоявшейся строки нельзя; для окна анализа брать `meta.stable_until`.

## 3-бис · Дефекты, найденные при первом живом запуске

1. **Оба эндпоинта отдают все кампании трекера, `campaign=` игнорируется.**
   Наша — `dorgen_engine`, 78.1% кликов. Остальные 21.9% — 42 чужие кампании
   (`cryptoboss_engine`, `apex_engine`, `kush_engine`, …). Параметр `campaign` в
   запросе не отвергается ошибкой, а **молча не применяется**: ответ на
   `?campaign=dorgen_engine` первой же строкой отдаёт `cryptoboss_engine`.
   Фильтровать приходится на своей стороне. У конверсий то же: 145 наших из 162.

   Это важно не только для чистоты: у чужих кампаний брак другого порядка
   (`cryptoboss_engine` — 12.5% строк без ключа против наших 0.02%). Считать
   доли по странице целиком — значит приписать себе чужой брак.

2. **Совпадение `subdomain` с хостом реферера на кликах — норма, не отравление.**
   Дор редиректит со своего же сабдомена, и он же оказывается реферером: таких
   кликов 14.4%, и ключ у них наш и правильный. «Нет в реестре» — тоже не признак
   (см. выше). Рабочий признак — **форма ключа**: наш сабдомен это
   `бренд.домен.зона` в зонах `.casino/.team/.lol/.buzz`.

   | категория ключа вне реестра | кликов | доля кампании |
   |---|---:|---:|
   | наша форма (запуски старше реестра) | 155 244 | 10.13% |
   | чужая форма, взят из хоста реферера — **отравление** | 5 977 | **0.39%** |
   | чужая форма, чужая сетка (`.top`, `.click`) | 1 020 | 0.07% |

   Отравление — это `yandex.ru`, `ya.ru`, `yandex.uz`: поисковик вместо
   сабдомена. Его 0.39%, а не 34%, как показал первый прогон аудита. На
   конверсиях старый признак совпадал с новым случайно — там подставлялись
   чужие хосты.

3. **Аудит по одной странице смещён.** Страница отсортирована по времени, то есть
   это срез первых минут окна, а не неделя. Доля ботов на первой странице — 5%,
   по всей неделе — 32%. Числа из `audit` годятся как проверка живости API, для
   долей нужна полная выгрузка. Оба искажения (1 и 2) вместе давали на первом
   запуске «34% отравленных» — величину, которой не существует.

4. **`is_bot` пропускает мусор целыми сабдоменами.** См. §5.

## 4 · Замечание о ссылках дора

Во всех 154 800 строках выгрузки `ref_link_host` = `sitegrator.com`, а
`ref_link_slug` содержит только путь (`/go/dorgen_engine` у 135 252 строк, всего
27 вариантов) — без `site=` и без `lp=`. Само по себе это не доказывает, что
движок их не шлёт: поле похоже на хранимый слаг без query-части, а конверсии
показывают, что `site=` до трекера доходит. Но проверить по живым кликам стоит
(пункт 1 выше).

> **Проверено 18.09: `site=` доходит.** Ключ заполнен у 99.98% кликов кампании,
> так что пустой `ref_link_slug` — действительно свойство хранения слага, а не
> признак потерянного параметра. А вот `lp=` не доходит: `landing_path` пуст у
> всех 1 531 821 клика.

## 5 · `pokerdom.3615.team`: четверть кликов недели, вся с вложенности

Самая крупная аномалия выгрузки. Один сабдомен даёт **376 431 клик — 24.6% всей
нашей кампании за неделю**, при том что половину кликов дают 3443 сабдомена из
182 715, а второй по величине сабдомен — 11 679 кликов, в 32 раза меньше.

| | |
|---|---|
| кликов | 376 431 (24.6% кампании) |
| уникальных `clickid` | 376 431 — дублей нет |
| `is_bot` | **0** |
| конверсий | **0** |
| реферер | `null` либо он сам |
| страны | DE 42 760, NL 41 143, FR 35 787, US 31 934, SE 31 873, CN 28 529 |
| домен | `3615.team`, запуск 26.08 (`launch_26.08.txt`) |

На остальных сабдоменах конверсия от клика 1.42%. Здесь 376 тысяч кликов и ни
одной регистрации — при честном трафике такого не бывает. При этом `is_bot` не
сработал **ни разу**: детектор трекера этот источник не видит.

### Это вложенность, а не поломка

Видно по `exit_path`:

```
/promo/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru/ru
```

**199 148 кликов из 376 431** приходят с восемнадцатого уровня `/ru`. Это штатная
конструкция сайта, описанная в `SISTEMA.md` §4: hreflang наращивает `/ru` до
лимита (16 кодов), спинтакс берёт seed от хоста, пути и глубины, поэтому каждый
уровень отдаёт свой текст. Оставшиеся 177 246 кликов — с нулевой глубины, без
реферера; их причина отдельная и не установлена.

Первая редакция этого раздела называла происходящее багом движка и рекурсивной
ссылкой. Это неверно: вложенность закладывалась намеренно, «на входе всегда 0,
дальше как пойдёт».

### Срез Apache на 20 уровнях соблюдается

`SISTEMA.md` §4 говорит, что глубже 20× `/ru` Apache отдаёт 302 на `/` всем,
включая ботов, и что в PHP лимит 40 — два лимита расходятся, а историю «какой
лимит был в день запуска» из БД не восстановить. По кликам видно, какой из них
работает:

| уровней `/ru` | кликов | сабдоменов | конверсий |
|---:|---:|---:|---:|
| 0 | 1 331 993 | 182 706 | **145** |
| 1–17 | 664 | ~30 | 0 |
| 18 | 199 154 | 7 | 0 |
| 19–20 | 10 | 8 | 0 |
| >20 | **0** | — | — |

Режет именно Apache на 20. Это закрывает вопрос мануала «работает ли срез
Apache на 20», помеченный как «нужен лог».

### Вложенность денег не даёт — по крайней мере пока

Все **145 конверсий пришли с нулевой глубины**. На 199 828 кликов с вложенных
уровней — ни одной. Это ровно тот посредник, который мануал описывает как
«контент → глубина → конверсия», и первые данные по нему выглядят так.

Вывод пока слабый: почти весь объём вложенности даёт один сабдомен, так что это
наблюдение об одном случае, а не о сети. Считать как исход и следить, не как
предиктор — правило 4.

Отсюда два следствия:

- **Доля ботов 32% занижена.** Без этого сабдомена по неделе выходит 42.4%,
  и видна динамика: 14.8% (13.09) → 49.7% (15.09) → **56.0% (17.09)**. Доля
  растёт вчетверо за неделю, и это отдельный повод разбираться.
- **Клики нельзя брать как объём без разбора по сабдоменам.** Правило 6 мануала
  («клики — факт, не фактор») этого не отменяет, но сам факт здесь искажён:
  четверть объёма недели создана одним сабдоменом, который ничего не приносит.

Реализовано в `tracker_clicks_rep.py`:

- строка **«клики с вложенности»** и разбивка по уровням `/ru` с конверсиями на
  каждом — как исход, а не как брак;
- блок **«лидеры»**: сабдомены с долей ≥5% кликов кампании выносятся отдельно, и
  все доли печатаются ещё раз без них — это правило мануала «один домен держит
  среднее». По неделе 11–17.09 пересчёт даёт: клики 1 531 821 → 1 155 390, боты
  32.0% → 42.4%, вложенность 13.05% → 0.06%.

## 6 · Что осталось открытым

- `pokerdom.3615.team` (§5): 52.9% его кликов — с восемнадцатого уровня `/ru`,
  это штатная вложенность. Непонятно другое: почему на одном сабдомене её на три
  порядка больше, чем на всей остальной сети, и откуда 177 246 кликов с нулевой
  глубины без реферера.
- Рост доли ботов с 14.8% до 56.0% за неделю — причина неизвестна.
- Два домена, не опознанные системой запусков: `3781.team`, `2075.team`.
- `domains_flat.txt` как фильтр «наших» строк непригоден: не покрывает запуски
  до 24.08. Нужна либо выгрузка `/v1/subdomains` пошире, либо отказ от реестра
  в пользу проверки через API.
- `landing_path` по-прежнему `null` — правка на стороне дора не доехала.
