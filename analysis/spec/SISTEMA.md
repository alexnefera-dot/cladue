# Как работает система запусков

Описание процесса целиком: что чем является, что за чем идёт, что мы меняем и что
константа. Собрано из объяснений владельца и из инвентаря системы, снятого
разработчиком 15.09.2026 (`katalog_sistemy_15.09.txt`). Там, где источник —
слова владельца, а не БД, это помечено.

Движок: `dorgen-engine`. Регистратор — Spaceship, DNS — Cloudflare.
Часовой пояс везде Europe/Kyiv.

---

## 1 · Бизнес и что считается успехом

Дорвейная сеть под казиночные брендовые запросы на русском. Человек ищет бренд
казино, попадает на наш сайт, его редиректит на партнёрскую ссылку, он там
регистрируется и делает депозит. Платят за ФД (первый депозит) — **$40**.

**Регистрация — редкое явление, и оно является целью.** Это главное, что нужно
держать в голове при любом анализе: десятки тысяч сабдоменов дают единицы
регистраций. Распределение почти целиком в нулях.

Экономика доменов: `.casino` $7, `.team` $2, `.lol` $1, `.buzz` $3.
Средняя цена $2.12, безубыток $1.94 на домен.

Отсюда две стратегии, между которыми выбираем:
- заходить на сложные ВЧ/СЧ бренды — там больше конверсий на позицию;
- либо масштабировать количество запусков.

## 2 · Что такое запуск

> Со слов владельца: «что за базы заведено — это КОНТЕНТЫ; всё, что у нас есть —
> контент + домен, набор дефолтных 186 брендов, дальше процесс ты знаешь,
> вложенность на входе всегда 0, а дальше уже как пойдёт».

**Запуск = КОНТЕНТ + домен + дефолтный набор ~186 брендов.**

Технически это жизненный цикл одного `content_domain` — «базы», например `3479.team`.
Отдельной таблицы «запуск» нет.

На базе разворачивается по одному сабдомену на бренд: `shuffle.3479.team`,
`pinup.3479.team` и так далее. Обычно **166–206 сайтов в запуске**, типично ~186.

**Единица наблюдения в аналитике — сабдомен** (домен × бренд). Ключ соединения
с трекером — полный хост, `domains.url`.

Масштаб на 15.09.2026: ~1649 баз, ~306 тыс. сабдоменов, ~206 видимых брендов,
~898 Cloudflare-аккаунтов, ~1378 аккаунтов Яндекс.Вебмастера.

> Со слов владельца: «нет ограничения в 82 запуска, будет любое количество,
> думаю минимум 50 в день до сотен». И: «контенты мы конечно будем менять».

**Вложенность на входе всегда 0.** Все запуски стартуют с нулевой вложенности;
что вырастет дальше — это уже результат, а не входной параметр.

## 3 · Конвейер, шаг за шагом

```
контент-пак + домен
      │
      ▼
1. Базу заводят                 content_domains.created
      │
      ▼
2. Генерация сайтов             content_generation_jobs (~50 сек)
   раскладка ~186 брендов       sites.created / domains.created
      │
      ▼
3. Инфраструктура               NS → Cloudflare → wildcard vhost → сертификат
      │                          is_ns_added / is_cloudflare_added /
      │                          is_virtual_host_added / is_certificate_added
      ▼                          (~98–99% успеха)
4. Планирование старта          schedules: at_time или when_ready
   задержка обычно 4–5 ч        activated_at — факт
      │
      ▼
5. Пайплайн Яндекс.Вебмастера   yandex_pipeline_started
      │
      ├─ add        хост добавлен в Вебмастер        host_added
      ├─ verify     подтверждение прав               verify_ok / verify_failed
      ├─ meta       мета проставлена                 meta_set
      └─ recrawl    отправка на переобход            recrawl_sent
      │             упёрлись в квоту                 quota_hit
      ▼
6. Финиш                        yandex_pipeline_finished
   длительность чаще 3–9 ч, хвост до 30+ ч
      │
      ▼
7. Робот приходит, страницы попадают в выдачу
      │
      ▼
8. Человек ищет бренд → находит наш сабдомен → кликает
      │
      ▼
9. Редирект на ref_link с меткой ?s=<host>
      │
      ▼
10. Регистрация и депозит во внешнем трекере → постбек
```

**Статусы базы:** `idle` / `running` / `waiting_verify` / `waiting_quota` /
`completed` / `failed` / `partial`. На срезе: completed 1358, partial 41, idle 229.

## 4 · Что видит человек и что видит бот

Это не поле в БД, но без этого не понять, откуда берутся регистрации.

Сайт отдаётся **боту**. Человека **редиректит** на партнёрскую ссылку.

- Любой URL с `/ru` → человеку 302 на `ref_link`, боту и whitelist — сайт.
- Не-ru HTML → то же самое: люди на ref, боты/whitelist/статика — сайт.
- Глубже 20× `/ru` → 302 на `/` **всем**, включая ботов. Это Apache RewriteMap.
  В PHP при этом лимит 40 — **два лимита расходятся**, и историю «какой лимит был
  в день запуска» из БД не восстановить.
- Отличают бота от человека по: UA, whitelist IP (4 адреса), `Sec-Fetch-Dest`,
  `Accept`, `UIR=0`, параметр `_georedir`.

Hreflang наращивает `/ru` до лимита, 16 кодов: `ru`, `en`, `x-default`, `ru-KZ`,
`en-AU`, `ru-BY`, `ru-UZ`, `ru-SG`, `ru-ZA`, `ru-PH`, `ru-RU`, `ru-HK`, `ru-PK`,
`ru-US`, `ru-CA`, `ru-IE`.

Sitemap — только `/` плюс плоские `/bonus`, `/registracia` и т.д., без вложенных
`/ru`. `lastmod` случайный в пределах текущего месяца.

Robots.txt: `Allow /`, запрет query-строк, блок Semrush / Ahrefs / MJ12 / rogerbot /
xenu, ссылка на sitemap.

**Cloudflare Worker сейчас не живой** — cron выключен, `is_worker_added` у всех NULL.
Гео-редирект идёт с origin, то есть PHP плюс карта Apache. Код воркера есть, но на
домены не накатывается.

**IndexNow** — ключи у сабдоменов есть, отправка выключена.

## 5 · Бренды

В базе 6159 брендов, из них **206 видимых** — они и идут в запуски. Скрытые
(5953) не участвуют: генерация всегда с `include_hidden=0`.

Сабдомен называется по бренду: `shuffle` из `brand.name_en`, очищенное.
Длина 1–39 символов, среднее ~8, пик 6–9. Дефисы редки (29 из 6159).

У бренда своя палитра CSS — **~6004 уникальных палитры на 6159 брендов**, то есть
почти у каждого своя. Плюс `keywords` (в среднем ~7.3 тыс. символов, максимум ~70 тыс.),
`established` (заполнено у ~1534), `popup` (1466), `api_form` (1485).

Каждый бренд выходил ~1500–1547 раз — это `brand_release_count`.

> Со слов владельца, критично для анализа: «на одном домене могут заходить на позиции
> одни бренды, на другом другие, поэтому оптимально всё же сравнивать не бренды
> между собой».

То есть бренд — **структура сопоставления, не переменная**. Сравнивать можно только
бренд с самим собой во времени: `brand_release_seq`, `days_since_brand_last_release`.

На новых сайтах `brand_pages` уже **не копируются** — берутся только `content_pages`
плюс `brand_slides`.

## 6 · Контенты (паки)

Контент — это пак текстов и страниц, который раскладывается на все бренды базы.

Имя пака выглядит как `content-2026-09-14b-7str-oform-2_44` или `nabory-611-620_5`.

> Со слов владельца: «это всё одно, название контента не надо разносить его
> на параметры».

**Контент берётся как один параметр — целиком имя.** Не декомпозировать.

Живые цифры: 674 пака, из них `7str` 630, `12str` 20, `nabory` 20.
Реально гонялись 140 паков. `content_reuse_count` типично 206 — то есть пак
раскладывается на все бренды базы.

Структура страниц:
- **7str** = главная + 6 внутренних: `bonus`, `registracia`, `app`, `zerkalo`,
  `vhod`, `slots`
- **12str** = главная + 11: те же плюс `news`, `info`, `promo`, `obzor`, `partnery`

Длины текстов пака (порядок величин): title ~26 тыс. символов со спинтаксом,
description ~2.6 тыс., additional_text ~3.2 тыс., additional_text_2 ~140 тыс.,
header_phone ~22 тыс. со спинтаксом, body страницы ~27 тыс., h1 ~1.2 тыс.

Спинтакс детерминированный: seed = хост + путь + глубина `/ru`. Значит мета и
телефон **зависят от глубины URL**.

`welcome_bonus` у всех «275% + 150FS» — сейчас это константа, как различитель
бесполезен.

Шаблон: `Theme1` у всех новых. `Theme2` только на очень старых (~166 сайтов из
первой пятитысячи).

## 7 · Оформление

У сайта есть `cssPrefix` = буква(`site_id`%26) + `site_id`, и набор CSS-переменных:

`main-background`, `secondary-background`, `content-background`,
`unactive-background`, `highlighter`, `button-color`, `link-font-color`,
`main-font-color`, `button-hover-color`, `main-border-radius`,
`button-border-radius`, `font-scale-factor`, `gradient-first-color`,
`gradient-second-color`, `alternative-highlighter`, `button-hover-background`,
`vendors-animation-speed`.

Из них считаются производные: яркость фона, яркость кнопки, контраст кнопка/текст,
хеш палитры.

В имени пака есть версия оформления: `oform` / `oform-2` / `styled_img`.
Это и есть оформление как параметр — оно приходит вместе с именем контента.

## 9 · Яндекс.Вебмастер

Каждой базе назначается аккаунт Вебмастера. Распределение: 1 запуск на аккаунт —
~1337 аккаунтов, 2 — 36, 3 — 4. То есть почти всегда аккаунт одноразовый.

Возраст аккаунта на момент старта **бимодален**: либо 0–1 день, либо ~29–38 дней.

Пайплайн по каждому сабдомену: add → verify → meta → recrawl.

**Лимиты в коде** (глобальные константы, не колонки БД):
- `VERIFY_FAIL_LIMIT` = 3 — после трёх неудач подтверждение исчерпано (439 сабдоменов)
- повтор verify через 30 минут
- **квота 150 URL в сутки** по Киеву
- допрохождение с `00:10`, шаг 12 минут

Результат на срезе: VERIFIED ~290 тыс., FAILED ~554, плюс IN_PROGRESS и
INTERNAL_ERROR. `yandex_webmaster_recrawled` ~95%, `added` ~96%.
Упирание в квоту — обычно 2–5 раз за запуск.

Типичные ошибки: квота, `VERIFICATION_FAILED 3/3`, HTTP 504.

`hosts_purge` — чистка хостов на аккаунте, случалась у 1081 базы.

**Позиции система не снимает.** Таблицы `domain_positions` и
`domain_positions_google` — 0 строк. `positions_rank` пусто.

> Со слов владельца: «позиции я не могу собирать».

Позиции добываются только вручную, отдельным съёмом выдачи.

## 10 · Время

> Со слов владельца: «время запуска там у нас есть параметром, потому что есть часы
> удачные, есть неудачные, как мне кажется, а может они считаются от переобхода».

Это открытый вопрос, и он правильно поставлен: часов на самом деле четверо, и они
разной грубости.

| часы | что это | роль |
|------|---------|------|
| старт пайплайна | `yandex_pipeline_started`, пик 14–21 Киев | вход |
| отправка на переобход | `recrawl_sent` из events | **основной** |
| приход робота | по логам/первым кликам | исход |
| час конверсии | из постбека трекера | самый грубый |

Час конверсии — это **время доставки постбека, а не события**: 16 из 17 регистраций
пришли на минуте `:15`, все депозиты на `:22`, с одного `postback_ip`. Разрешение
часовое, сдвиг до часа.

Задержка от заведения базы до старта пайплайна: в тот же день ~1093 базы,
на следующий ~249, редко 2–11 дней.
От создания расписания до активации — обычно 4–5 часов.
Сам пайплайн чаще 3–9 часов, хвост до 30+.

Режим старта: `at_time` (~806) или `when_ready` (~59 + 75 в ожидании).
У `when_ready` есть автостарт по нагрузке — в логе CPU в среднем ~38%, максимум 83%.

Воскресенье даёт меньше запусков.

## 12 · Что мы меняем, а что константа

**Меняем от запуска к запуску:**
контент-пак, версию оформления, зону и имя домена, время старта, режим запуска.

**Назначается системой:** аккаунт Вебмастера, аккаунт Cloudflare, палитра (от бренда),
cssPrefix (от site_id).

**Сейчас константа и как различитель бесполезно:** welcome_bonus, шаблон (Theme1
у всех новых), набор из 186 брендов, `include_hidden=0`, глубина `/ru` (40 в PHP /
20 в Apache), число hreflang (16), гео-редирект включён, воркеры выключены,
IndexNow выключен.

> Со слов владельца про глобальные константы: «их просто надо фиксировать раз
> у каждого домена (запуска), а если меняются — чтоб было видно пулы с разными
> параметрами».

То есть константы пишутся в строку запуска как срез на момент старта, и когда
что-то меняется — видно два пула с разными настройками.

Тут есть известная дыра: `runtime_*` в API отдаёт **текущие** значения на момент
запроса, а не исторические на момент старта. Снапшот в БД не пишется.

## 13 · Чего в системе нет и не будет

> Со слов владельца: «типа аксес лог — там миллионы строк в день, его никак
> не отдашь, и он постоянно очищается».

- **Access-log** — миллионы строк в день, ротируется. Отдать нельзя. Принято.
- **Позиции** Яндекса и Google — таблицы пустые, система их не снимает.
- **Регистрации** внутри системы — нет, только внешний трекер.
- **Clickid-level склад** — нет, поэтому нет `/v1/clicks` и `/v1/conversions`.
- **Исторические значения глобальных констант** — snapshot не пишется.
- **Метрика Яндекса** — пусто.
- **EN-версии сайтов** — почти пусто.
- **RKN, GSA, ping, бан, spin, search** — поля есть, не наполняются.
- **Данные после hard-purge**: при soft-delete базы сайты, домены и клики
  вычищаются, аналитика по сабдомену пропадает. Сейчас soft-deleted = 0.
- **Скрытые бренды** в запусках — не бывает, `include_hidden` всегда 0.

Отдельно: ~1487 сайтов-сирот без домена. В аналитику сабдоменов они не попадают.

> Правило владельца: «мы работаем только с теми данными, что есть в системе.
> Если важного для анализа нет — выдели в отдельный список в каждом разделе».

## 14 · Модель данных

```
content_domains  (база: xxx.team)
  ├── cloudflare_accounts
  ├── yandex_webmaster_accounts
  ├── yandex_webmaster_pipeline_accounts / events / schedules / auto_start_log
  ├── content_generation_jobs
  └── domains  (сабдомены brand.xxx.team)
        └── sites
              ├── brands   (+ brand_pages / slides / tabs / faqs)
              └── contents (+ content_pages / tabs)
                    └── site_pages / site_slides / site_tabs
```

**Ключи соединения:**

| ключ | уровень | что даёт |
|------|---------|----------|
| `subdomain` / `domains.url` | сабдомен | канонический ключ к трекеру (`?s=host`) |
| `domain_id` | сабдомен | PK |
| `site_id` | сайт | карточка |
| `brand_id` | бренд | видимый бренд |
| `content_id` | контент | у старых сайтов часто NULL |
| `content_domain_id` | запуск | база |
| `yandex_webmaster_account_id` | запуск | аккаунт Вебмастера |
| `cloudflare_account_id` | запуск | CF-аккаунт базы |

## 15 · Глоссарий

| термин | значение |
|--------|----------|
| **база** | `content_domain`, домен запуска: `3479.team` |
| **запуск** | жизненный цикл одной базы: контент + домен + 186 брендов |
| **сабдомен** | `brand.база`, единица наблюдения: `shuffle.3479.team` |
| **контент / пак** | набор текстов и страниц, раскладывается на все бренды базы |
| **оформление** | версия оформления пака: `oform`, `oform-2`, `styled_img` |
| **7str / 12str** | 7 или 12 страниц в паке |
| **nabory** | отдельное семейство паков |
| **переобход / recrawl** | отправка URL в Яндекс.Вебмастер на переобход |
| **квота** | 150 URL в сутки на аккаунт Вебмастера |
| **вложенность** | глубина `/ru/ru/…` в URL; на входе всегда 0 |
| **ФД** | первый депозит, за него платят $40 |

## 16 · Что владелец сказал дословно

Формулировки, которые меняли направление работы. Они короткие и важнее пересказа.

- «Создаются сотни доменов за день с 186 поддоменами, это вводные, а дальше идут
  все описанные процессы. **Регистрация — редкостное явление, которое является целью**».
- «Всё, что у нас есть — контент + домен, набор дефолтных 186 брендов.
  **Вложенность на входе всегда 0**, а дальше уже как пойдёт».
- «**Клики нет смысла анализировать**, там могут быть боты». Позже: «клики можешь

- «**Это всё одно, название контента не надо разносить его на параметры**».
- «На одном домене могут заходить на позиции одни бренды, на другом другие,

- «**Позиции я не могу собирать**».
