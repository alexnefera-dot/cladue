Эндпоинты для выгрузки данных

Четыре GET-эндпоинта. Основной отдаёт денормализованную строку на сабдомен, остальные — временной ряд трафика, сырые события пайплайна и снимок глобальных констант. Ключ соединения с трекером — полный хост сабдомена.

Общие правила

чтокак
форматJSON, Content-Type: application/json; charset=utf-8
методтолько GET
авторизацияAuthorization: Bearer <token>
времяISO 8601 со смещением: 2026-09-15T13:03:11+03:00. Europe/Kyiv везде
только дата2026-09-15
отсутствующее значениеnull. Не пустая строка, не 0, не "-"
булевоtrue / false, не 1 / 0
сабдоменполный хост, нижний регистр, без схемы и www: shuffle.3479.team
пагинациякурсорная, см. ниже. Offset не используем — 306 тысяч строк
повторный запростот же диапазон дат → те же строки. Порядок стабильный

Пагинация

Все списочные эндпоинты принимают limit и cursor и возвращают одинаковую обёртку:

{
  "data": [ ... ],
  "meta": {
    "count": 1000,
    "next_cursor": "eyJpZCI6MzA0MTJ9",   // null, если это последняя страница
    "generated_at": "2026-09-15T18:20:04+03:00"
  }
}

limit — по умолчанию 1000, максимум 5000. cursor — непрозрачная строка из предыдущего ответа. Пока next_cursor не null, клиент запрашивает дальше.

Про recrawl_sent_at и recrawl_wave

Это два самых важных поля во всём ответе. Квота — 150 URL в сутки, возобновление с 00:10 Киев шагом 12 минут. Значит часть сабдоменов одной базы уходит на переобход сразу, а остаток почти сутки спустя, и это единственный параметр, который различается внутри одной базы. Сравнение по нему автоматически очищено от зоны, контента и даты.

Если recrawl_wave не хранится — не считайте его, отдайте только recrawl_sent_at, волну я выведу сам по времени относительно pipeline_started.

2 · GET /v1/traffic

Временной ряд — в строку сабдомена не денормализуется. Одна строка = сабдомен × дата. Отдавать только дни с ненулевым значением.

параметртипобяз.что значит
date_from · date_todateдапо дате трафика
subdomainstringнетвернуть только этот хост
limit · cursorнет
{
  "data": [
    { "subdomain": "shuffle.3479.team", "date": "2026-09-15",
      "clicks": 4, "views": 1, "country_mix": { "RU": 3, "null": 1 } }
  ]
}

Важно: ваш «клик» — это не переход человека из поиска

870 тысяч кликов на 226 тысячах сабдоменов, а регистраций за тот же период — около пятисот. Конверсия 0.05%. При этом клики есть у 74% всех сабдоменов. Значит счётчик считает срабатывание редиректа, а не живого посетителя.

Это не делает его бесполезным — наоборот, объёма хватает, чтобы сравнивать конфигурации за неделю. Но называть его конверсией нельзя, и в отчётах он пойдёт как отдельная метрика «срабатываний редиректа», а деньги — только из трекера.

3 · GET /v1/events

Сырые события пайплайна. Нужны, чтобы пересчитывать длительности под любое определение, а не полагаться на заранее посчитанные. Одна строка = одно событие.

{
  "data": [
    { "subdomain": "shuffle.3479.team", "content_domain_id": 2844,
      "event": "recrawl_sent", "at": "2026-09-15T13:41:02+03:00",
      "detail": null },
    { "subdomain": "shuffle.3479.team", "content_domain_id": 2844,
      "event": "verify_failed", "at": "2026-09-15T13:12:40+03:00",
      "detail": "VERIFICATION_FAILED 1/3" }
  ]
}

Значения event: host_added · verify_started · verify_ok · verify_failed · meta_set · recrawl_sent · recrawl_done · quota_hit · error · hosts_purge.

Параметры те же: date_from, date_to, опционально subdomain или content_domain_id, плюс пагинация.

Что выяснилось из вашей выгрузки и меняет схему

Человек не видит сайт

Любой URL с /ru отдаёт человеку 302 на ref_link; сайт видят только боты и whitelist. Значит контент и оформление влияют не на конверсию, а только на то, как страницу оценивает Яндекс. Это переворачивает интерпретацию всей группы «оформление»: контраст, логотипы, popup работают как сигнал качества для робота, а не как элементы, которые кто-то увидит. Мерить их всё равно нужно — но связывать надо с попаданием в выдачу, а не с регистрацией.

Apache и PHP не согласованы по глубине

PHP разрешает 40 уровней, hreflang наращивает до 40, а Apache режет (/ru){21,} и отдаёт 302 на корень всем, включая ботов. То есть половина объявленных в hreflang уровней ведёт в редирект. Это проверяемо и, возможно, лечится одной строкой конфига — но сначала надо увидеть в данных, какие уровни реально ранжируются.

Предела вложенности на запуск не существует

Глубина не пишется в строку запуска — это глобальный runtime, и историю восстановить нельзя. Значит поля предел_вложенности в API не будет, а сравнение пределов возможно только вперёд, после того как вы начнёте менять константу и логировать изменения через /v1/globals.

Верификация — отдельный шаг воронки

Между «хост добавлен» и «отправлен на переобход» стоит подтверждение прав: 290k VERIFIED, 554 FAILED, 439 исчерпали лимит 3 из 3. Доля небольшая, но шаг в воронке есть, и его надо считать отдельно.

Сабдоменов на базу не 200, а 166–206

306 тысяч сабдоменов на 1649 баз — в среднем 186. Я считал знаменатель как «домены × 200»; теперь он берётся из фактических строк, и это единственный правильный способ.

Все поля названы так же, как в вашем каталоге от 15.09, чтобы не пришлось сопоставлять. Если какое-то поле дорого отдавать — скажите до реализации: почти всё заменимо, кроме subdomain, recrawl_sent_at и pipeline_started. Без этих трёх не считается ничего.
