# План анализа: порядок мануала с пометками, что стало измеримо

Это **не новый план**. Это «Порядок работы, когда данные придут» из
`analysis/spec/ANALITIKA.html` (Блок 2), переписанный по шагам с отметками, что
из него теперь считается — после подключения API трекера 18.09 — а что
по-прежнему упирается в отсутствующий лог.

Мануал остаётся источником правил. Здесь только привязка к данным, которые
есть на руках, и команды.

---

## 0 · Что изменилось после трекера

Мануал писался в расчёте на лог обращений (`/v1/botlog`), которого нет и не
будет. Четыре вещи, которые он относил к логу, закрываются кликами трекера.

| мануал говорил | чем закрывается теперь |
|---|---|
| `human_hits_from_yandex > 0` — «был в выдаче», нужен лог | клик с яндексовым реферером из `/v1/clicks`. **Не равно индексации:** клик требует индекса, высокой позиции и спроса сразу; отсутствие клика ни одно из них не опровергает (`INDEKSACIYA_18.09.md` §0) |
| `days_to_first_click_after_recrawl`, нужен лог | первый клик трекера минус `recrawl_sent_at` из `/v1/subdomains` |
| глубина обхода, распределение уровня `/ru` — нужен лог | `exit_path` клика. **Измерено:** уровней `/ru` до 20, кликов глубже нет |
| «работает ли срез Apache на 20» — нужен лог | **режет Apache, не PHP.** Ноль кликов с уровнем >20 за неделю 11–17.09, хотя в PHP лимит 40 |
| «глубина против денег», посредник контент → глубина → конверсия — нужен лог | клики и конверсии по уровням считаются, но **сравнивать нельзя**: на вложенных кликах реферер всегда свой же сабдомен, источник не доходит. Отложено до правки на стороне дора |
| трафик по дням (правило 7, экспозиция) — `/v1/traffic` сломан | клики трекера дают сабдомен × дату. Показов (`views`) по-прежнему нет |
| ФД | приходят напрямую, `event=fd` |

Чего это **не** закрывает: обращения робота как таковые. Поэтому в Анализе B
классы «переобход ушёл, робот не пришёл» и «робот пришёл, в выдачу не попал»
остаются слитыми в одну строку — их различает только лог. А вот класс «в выдаче
был, денег не дал» теперь отделяется чисто: есть клики, нет конверсий.

## 1 · Приёмка

Критерии мануала, проверять на каждой выгрузке:

- хост уникален и в нижнем регистре;
- ~206 сабдоменов на запуск, не меньше;
- есть строки без трафика и без конверсий;
- `recrawl_sent_at` таймстемпом;
- `runtime_*` заполнены;
- период покрывает полные окна.

**Расхождение — остановиться и спросить, не чинить на своей стороне.**

Добавить к приёмке две проверки, которых в мануале нет, потому что источник был
другой:

- **кампания.** `/v1/clicks` и `/v1/conversions` отдают все кампании трекера,
  параметр `campaign=` в запросе молча игнорируется. Наша — `dorgen_engine`,
  78.1% кликов. Фильтровать на своей стороне, иначе чужой брак попадёт в наши
  доли (у `cryptoboss_engine` 12.5% строк без ключа против наших 0.02%);
- **сверка ставки.** Мануал считает от 0.178% регистраций и 0.026% ФД на
  сабдомен. Пересчитать по факту на выгрузке и, если разошлось, разбираться до
  расчётов, а не после.

Команды:

```bash
python3 analysis/scripts/pull_api.py     subdomains  <from> <to>   # ~12 мин, 613 МБ
python3 analysis/scripts/pull_tracker.py clicks      <from> <to>   # ~30 мин, 455 МБ/нед
python3 analysis/scripts/pull_tracker.py conversions <from> <to>
python3 analysis/scripts/tracker_clicks_rep.py analysis/api/tracker_clicks_<from>_<to>.jsonl
```

## 2 · Выборка

Только закрытые окна: **≥ 6 дней от `recrawl_sent_at`** (не от старта
пайплайна). Случаи — сабдомены с конверсией, фон — все остальные из того же
отбора. Свежие не берутся ни в случаи, ни в фон.

Окно анализа не позже `meta.stable_until` из ответа трекера.

Про глубину истории: клики трекера есть **с 28.07**, конверсии — с 13.06.
Отзыв августа снят 18.09 (правило 10 в новой редакции), поэтому рабочее окно
начинается там, где есть обе системы: клики с 28.07, выгрузка запусков — с той
даты, на которую её сняли.

**Незакрытые окна не выбрасываются, а помечаются.** В выводы они не идут, в
отчёте показываются числом, и на следующем расчёте пересматриваются: за неделю
их окна закроются. Каждый расчёт начинается с того, что выводы по прежде
незакрытым переснимаются.

## 4 · Анализ B — почему не зашло

Разложение всех сабдоменов по пяти классам. Это деление, не проверка гипотезы:
статистика тут не нужна.

**Промежуточный исход «был в выдаче» — рабочий и куда мощнее конверсии.**
25 424 события против 176 на том же окне. Разрезы сначала читаются на нём
(эффекты от 1.05×), конверсией подтверждаются. Первый замер — `REZULTATY_18.09.md` §6.

| класс | чем ловится сейчас |
|---|---|
| не дошёл до переобхода | `yandex_pipeline_stage ≠ done` |
| переобход ушёл, робот не пришёл | **слит со следующим**, различает только лог |
| робот пришёл, в выдачу не попал | **слит с предыдущим**: у обоих нет кликов |
| в выдаче был, денег не дал | клики есть, конверсий нет — **теперь отделяется** |
| верификация не прошла | `verification_status = FAILED`, `fail_count = 3` |

## Проверять на каждом расчёте

Чек-лист мануала плюс две строки, которые добавил первый живой прогон.

| что | правило |
|---|---|
| объект жив в момент измерения | число с выпавшего сайта не используется |
| усечение слева | запуск, чьё окно не целиком внутри выгрузки, не берётся вовсе |
| отбор по результату | выборка определяется до того, как видны исходы |
| эффект группы под видом эффекта дня | дробить до уровня, где значение постоянно |
| неизвестный возраст | сравнивать только запущенное вместе |
| один домен держит среднее | каждое среднее — вместе со значением «без лидера» |
| **вложенность** | считать и показывать по уровням `/ru`, вместе с конверсиями на каждом. Правило 4: исход или посредник, никогда не предиктор |
| **чужая кампания** | всё считается только по `dorgen_engine` |

Обе новые строки уже реализованы в `tracker_clicks_rep.py`: он печатает разбивку
по уровням вложенности с конверсиями, список лидеров с долей ≥5% кликов и
пересчёт долей без них.

## Чего по-прежнему нет

- **Лог обращений** — классы 2 и 3 Анализа B слиты, доля ботов среди робота неизвестна.
- **`landing_path`** — `null` у 100% кликов, глубина входа не считается.
- **`payout`, `status`** — `null`, деньги только расчётные.
- **`views`** — показов нет ни в одном источнике, только клики.
- **`content_label` до 15.09** — восстанавливается по реестру запусков.
- **Исторические `runtime_*`** — приходят текущие константы, не снимок на старт.
