## 2 · БЛОКЕР: `/v1/subdomains` отдаёт 500 примерно на половине запросов

Это важнее всех недостающих полей: в таком виде массовая выгрузка нереальна.

Один и тот же запрос, восемь раз подряд с паузой 2.1 с:

| эндпоинт | коды | доля ошибок |
|----------|------|-------------|
| `/v1/subdomains` 15.09 limit=50 | 6×500, 2×200 | **75%** |
| `/v1/subdomains` 10.09 limit=50 | 4×500, 4×200 | **50%** |
| `/v1/traffic` 15–16.09 limit=50 | 3×500, 5×200 | 37% |
| `/v1/events` 16.09 limit=50 | 2×500, 6×200 | 25% |
| `/v1/globals` 15.09 | 8×200 | 0% |

Тело ответа: `{"error":{"code":"internal","message":"Internal error"}}`, HTTP 500.

**Ошибка не детерминирована и ни от чего не зависит.** Пять одинаковых запросов
подряд дали `200, 200, 500, 500, 500`. Проверено отдельно, что это не параметры:

- `limit=50` → 500, тот же `limit=300` → 200 (та же дата, тот же `date_field`);
- `date_field=pipeline_started` → 500, `cd_created` → 200;
- окно в один день → 500, окно в три дня → 500.

Чем «тяжелее» эндпоинт, тем чаще падает: `globals` (один объект) не падает никогда,
`events` 25%, `subdomains` 75%. Похоже на таймаут или исчерпание ресурса в
обработчике, а не на логику.

**Что просим:** найти причину по серверным логам за 17.09. Для нас практический
критерий — курсорная выгрузка на сотню страниц должна проходить без ретраев.
Сейчас при 50% на запрос выгрузка недели рвётся гарантированно.

## 4 · ЗАЯВКА: `quota_wait_until` пуст, хотя значение есть в тексте рядом

На 17.09 поле `pipeline_error` заполнено у 100% строк, но это **не ошибка**:

```
"150 готово, 56 ждут квоту (до 18.09.2026 10:46 Киев)"   — 102 строки
"150 готово, 56 ждут квоту (до 18.09.2026 10:34 Киев)"   —  97 строк
"Суточная квота переобхода исчерпана"                    —   1 строка
```

Для сравнения, 16.09: `pipeline_error = null` у всех 200 строк.

Две проблемы сразу:

1. **`quota_wait_until` = `null` у 100% строк во всех когортах**, хотя время
   ожидания напечатано прямо в тексте `pipeline_error`. Значение существует —
   его просто не кладут в поле. Это самая дешёвая правка из всего списка.
2. **`pipeline_error` используется как поле статуса, а не ошибки.** Отличить
   настоящий сбой от «ждём квоту» можно только разбором русской строки. Просим
   либо отдельное поле статуса, либо машинный код вместо текста.

`yandex_pipeline_stage` при этом различает состояния корректно (`done` 199,
`quota_wait` 1) — но не совпадает с `pipeline_error`, который заполнен у всех 200.
