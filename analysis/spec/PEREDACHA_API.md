Один файл для старта в новой сессии. Репозиторий `alexnefera-dot/cladue`, рабочая

## 1 · Что за работа

Дорвейная сеть под казиночные брендовые запросы. Запуск = **КОНТЕНТ + домен +
дефолтный набор 206 брендов**. Единица наблюдения — **сабдомен** (домен × бренд),
их 206 на запуск. Регистрация (ФД) — редкое событие и цель; десятки тысяч сабдоменов
дают единицы регистраций.

Экономика: `.casino` $7, `.team` $2, `.lol` $1, `.buzz` $3. Платят $40 за ФД.
Средняя цена домена $2.12, безубыток $1.94 на домен. Отсюда две задачи:
заходить на сложные ВЧ/СЧ бренды ради конверсий — или масштабировать количество запусков.

Вся аналитика — по-русски, часовой пояс Europe/Kyiv.

## 2 · Окружение `dorgen`

Создано в claude.ai/code → селектор окружения. Настроено:

| | |
|--|--|
| Network access | `Custom` |
| Allowed domains | `dorgen-engine.com`, `*.dorgen-engine.com` + Artifact content domains |
| Package managers | галочка «Also include default list» стоит |
| Env vars | `DORGEN_BASE=https://dorgen-engine.com`, `DORGEN_TOKEN=…` |

**Токен живёт только в переменных окружения.** В репозиторий он не пишется никогда —
`pull_api.py` читает его из `os.environ`. Если он понадобится в явном виде — брать из
окружения, не из переписки и не из файлов.

Смысл этой настройки: данные тянутся из API самой сессией, пользователь ничего не
пересылает руками.

Проверка, что сеть открыта:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' "$DORGEN_BASE/v1/globals?on=2026-09-15" \
  -H "Authorization: Bearer $DORGEN_TOKEN"     # ждём 200
```

Если `CONNECT tunnel failed, 403` — сессия запущена в старом окружении, а не в `dorgen`.

## 4 · Скрипт `analysis/scripts/pull_api.py`

Читает `DORGEN_BASE` / `DORGEN_TOKEN` из окружения. Курсорная пагинация по 1000,
пауза 2.1 с между запросами (~28 req/min при лимите 30), окно режется на куски по
31 дню. Пишет JSONL в `analysis/api/` (каталог в `.gitignore`: один день
`subdomains` это ~110 МБ).

```bash
python3 analysis/scripts/pull_api.py audit
python3 analysis/scripts/pull_api.py globals 2026-09-15
python3 analysis/scripts/pull_api.py subdomains 2026-09-10 2026-09-17
python3 analysis/scripts/pull_api.py traffic    2026-09-10 2026-09-17
python3 analysis/scripts/pull_api.py events     2026-09-16 2026-09-17
```

Для `subdomains` скрипт сам ставит `date_field=pipeline_started` — для аналитики «запуск»
считается по старту пайплайна, не по дате создания домена.

**Повторы разведены по смыслу.** Аудит 17.09 показал, что 5xx на этом API случайны
и независимы (один и тот же запрос: 200, 200, 500, 500, 500), поэтому по ним повтор
короткий и частый — длинный откат только теряет время. По 429 наоборот
экспоненциальный откат, это настоящий лимит. Сетевые ошибки повторяются дважды:
блокировка политикой окружения сама не рассосётся. Число попыток на страницу —
`DORGEN_TRIES`, по умолчанию 15.

**Выгрузка возобновляется.** Рядом с JSONL живёт `<имя>.jsonl.state` с курсором и
длиной записанного. Оборвалось — повторите ту же команду, продолжит с места обрыва:

```bash
python3 analysis/scripts/pull_api.py subdomains 2026-09-10 2026-09-17   # оборвалось
python3 analysis/scripts/pull_api.py subdomains 2026-09-10 2026-09-17   # продолжит
```

Состояние пишется после каждой страницы и только после `fsync` данных, а при старте
файл обрезается ровно по записанной длине — поэтому обрыв в любой момент не даёт ни
дублей, ни битых строк. Успешная выгрузка состояние удаляет, так что повтор команды
начнёт её заново. Проверено жёстким убийством процесса посреди выгрузки 16.09:
28 110 строк, ноль битых, ноль дублей.

Без этого выгрузка недели не доходит до конца: при 50-75% пятисоток обрыв гарантирован.

## 5 · Второй источник — API трекера

`sitegrator.com`, эндпоинты `/v1/clicks` и `/v1/conversions`. Конверсии и клики
берутся оттуда напрямую, **CSV больше не нужен**. Контракт — `API.md` в ветке
`claude/sitegrator-redirector`. Переменные `TRACKER_BASE` / `TRACKER_TOKEN`.

Отличия от контракта dorgen: `limit` до 5000, окно дат до 92 суток, 60 запросов
в минуту, 2 одновременных. Ключ соединения — `subdomain`, совпадает с
`subdomain` из `/v1/subdomains`.

Выгрузка — `analysis/scripts/pull_tracker.py` (`audit`, `clicks`, `conversions`),
разбор — `tracker_clicks_rep.py` и `tracker_conv_rep.py`. Всё проверенное — в
`analysis/spec/TRACKER_PREFLIGHT_17.09.md`. Коротко по неделе 11–17.09
(1 960 376 кликов, 393 запроса, ноль ошибок):

- **Ключ состоятелен.** Пустой `subdomain` у 0.02% кликов и 0% конверсий,
  `clickid` конверсии находится среди кликов у 98.6%. Медианный лаг
  клик → конверсия 0.8 ч. Конверсия от клика 1.42%.
- **Трекер отдаёт все кампании, `campaign=` в запросе молча игнорируется.**
  Наша — `dorgen_engine`, 78.1% кликов; остальное — 42 чужие кампании с другим
  уровнем брака. Фильтровать на своей стороне.
- **Отравление ключа — 0.39%** (`yandex.ru`, `ya.ru`: поисковик вместо
  сабдомена), плюс 0.07% ключей чужих сеток. Признак не «`subdomain` равен хосту
  реферера» (так у 14.4% нормальных кликов — дор редиректит сам с себя) и не
  «нет в реестре», а **форма ключа**: `бренд.домен.зона` в наших зонах.
- **`domains_flat.txt` не годится как фильтр наших строк**: по нему опознаётся
  89.4% кликов, но выборочная проверка через `/v1/events` показала, что 38 из 40
  крупнейших «чужих» доменов — наши запуски до 24.08. Реальная соединяемость ≈99%.
- **Боты: 32% за неделю, 56% на 17.09**, доля растёт. Один сабдомен
  (`pokerdom.3615.team`) даёт 24.6% кликов недели при нуле конверсий — объёмы
  считать с пересчётом «без лидера».
- **Вложенность считается по `exit_path`**: все 145 конверсий пришли с нулевой
  глубины, на 199 828 кликов с уровней 1–20 — ноль. Срез Apache на 20 работает.
- **`linked_at` — не признак финальной строки**: у всех 162 конверсий он один
  и тот же, это отметка прогона связывания. Окно брать по `meta.stable_until`.
- Клики доступны **с 28.07**, раньше пусто.

Всегда `null`: `payout`, `status` (партнёрка не шлёт суммы и отмены),
`landing_path` (дор не передаёт `lp=`, правка в работе — на 18.09 не доехала).
Боты не отфильтрованы, есть `is_bot` и параметр `ua_class`.

## 5-бис · API системы запусков — что есть

Полный контракт: `analysis/spec/API_USAGE_17.09.md`. Коротко:

Только `GET`, JSON UTF-8, `Authorization: Bearer <token>`. Время ISO-8601 со смещением
Europe/Kyiv. Нет значения → `null`. Пагинация `limit` (max 1000) + opaque `cursor`,
`meta.next_cursor: null` — конец. Окно дат max 31 день. Лимит ~30 req/min, max 2 тяжёлых
запроса одновременно.

| endpoint | одна строка = | ключевое |
|----------|---------------|----------|
| `/v1/subdomains` | сабдомен (включая мёртвые) | ids, pipeline/*, `recrawl_sent_at`, tld/pattern, `content_label`, brand/*, css + contrast_*, суммы clicks/views |
| `/v1/traffic` | сабдомен × дата (только дни с clicks+views > 0) | `clicks`, `views`, `country_mix`. **Не использовать:** курсор сломан, дальше 1000 строк не выгрузить. Трафик переедет в отдельное API, оно не реализовано |
| `/v1/events` | событие пайплайна | `host_added`, `verify_ok/failed`, `meta_set`, `recrawl_sent`, `quota_hit`, `hosts_purge`, `error`. **Выгружать по базам** (`content_domain_id`): без фильтра список обрывается на первых минутах суток и рапортует «конец», выборка выходит смещённой. См. `AUDIT_API_17.09.md` §9 |
| `/v1/globals` | один объект, не массив | текущий снимок констант, **не журнал истории** |

**Чего в v1 нет и не будет:**

- `/v1/clicks`, `/v1/conversions` — нет clickid-level склада в engine, конверсии приходят
  из трекера отдельно (CSV).
- `/v1/botlog`, `/v1/botlog/raw` — access-log это миллионы строк в день и он ротируется,
  отдать его нельзя. Принято как данность, не переспрашивать.
- Исторические `runtime_*` на момент старта — snapshot в БД не пишется. То, что приходит
  в `runtime_*`, это **текущие** константы сервера на момент запроса.
- Данные после hard-purge.
- Трафик по дням: `/v1/traffic` в нынешнем виде нерабочий (курсор отвергается), а
  заменяющее его отдельное API ещё не реализовано. До тех пор `clicks`/`views` по
  датам недоступны — правило 7 и кривая видимости считать не на чем.

Многое из `null`-полей выводится на нашей стороне из сырых id и таймстемпов —
`*_seq`, возраст, `pack_date`, `brand_release_seq` считаются по истории запусков из
`analysis/launch_*.txt` и `analysis/launches.md`.

## 6 · Правила аналитики, которые нельзя нарушать

Полный мануал: `analysis/spec/params.html` (он же опубликован артефактом) и его
самодостаточная копия `analysis/spec/ANALITIKA.html`. Блок 1 — API и условия к данным,
для пользователя и разработчика. Блок 2 — аналитика, рабочая инструкция.

Выжимка того, на чём уже спотыкались:

1. **Дизайн — случай-контроль, не средние по группам.** Регистрация редка, распределение
   почти всё в нулях; средние по группам на таком распределении не значат ничего.
   Случаи = конвертнувшие сабдомены, фон = остальные с закрытым окном. Мера — odds ratio.

2. **Объединение — Mantel-Haenszel, не логистическая регрессия с дамми по брендам.**
   Около одной конверсии на бренд в неделю → bias от incidental parameters.
   Скорректированный OR — условная логистическая со стратами по брендам.

3. **Бренды — структура сопоставления, между собой не сравниваются.** На одном домене
   в топ заходят одни бренды, на другом другие. Выживает только `brand_release_seq` —
   бренд против самого себя во времени.

4. **Вложенность на входе всегда 0.** Это исход или медиатор, никогда не предиктор.

5. **Контент — один параметр, целиком имя.** Не разносить на составляющие.

6. **Клики — факт, не фактор.** Там могут быть боты. Смотреть можно, взвешивать нельзя.

7. **Экспозиция нормируется в домен·днях** — пересечение 6-дневного окна с окном выгрузки.

8. **Четверо часов**: старт пайплайна, отправка на переобход (основные), приход робота
   (исход), час конверсии (самый грубый — это время доставки постбека, не события).

9. **Возраст — главный конфаундер.** Любое сравнение зон, контентов, серий делать в
   контролируемом окне. Один раз уже получили `.casino` 4.01× при p=0.009 — оказалось
   артефактом возраста: `.casino` перестали запускать после 12.09, а знаменатель `.team`
   тянул мёртвые августовские домены.

10. **Отзыв августа отменён 18.09, вместо него — пометка окна.** Прежнее правило
    вычёркивало август целиком: позиции тогда снимались после выпадения сайтов.
    Это касается замеров выдачи, а не фактуры из API — конверсии и клики трекера
    от способа снятия позиций не зависят. Поэтому август идёт в расчёт, а
    негодными остаются только выводы, опиравшиеся на августовские позиции
    (ширина в выдаче, кривая видимости).

    Взамен у каждого запуска указывается состояние окна: закрыто, если от
    `recrawl_sent_at` прошло ≥6 суток. **Незакрытые в выводы не идут, но
    показываются числом**, и после каждого следующего расчёта выводы по ним
    переснимаются — окно к тому времени закроется. Ни один запуск больше не
    выбрасывается насовсем: он либо в расчёте, либо ждёт своего окна.

11. **Для часовых разрезов — страта по контенту.** Добавлено 18.09 после того,
    как «ночной старт» оказался эффектом одного пака, запущенного ночью: страт
    по бренду и по дню не хватило, конфаундером был контент. Час старта и
    контент оба являются свойствами базы, так что без страты по контенту они
    неразделимы.

12. **Проверять на холдауте всё, что нашлось перебором.** Разбить выборку по
    времени пополам и посмотреть, держится ли направление. Ночной старт давал
    0.44 на одной половине и 5.53 на другой — по общей выборке это выглядело
    как устойчивые 2.26.

Статистика считается на стандартной библиотеке: `math.comb` (точный биномиальный),
`statistics.NormalDist`. Внешних зависимостей не тянуть.

## 7 · Что установлено

Полный расчёт с таблицами — `analysis/spec/REZULTATY_18.09.md`. Ниже выжимка,
разделённая на то, что подтверждено на двух источниках, что отменено проверкой,
и что перешло из прежних сессий непроверенным.

### 7.1 · Подтверждено 18.09, случай-контроль на 189 035 сабдоменах

Панель: `/v1/subdomains` 25.08–17.09 (331 548 строк) + клики трекера 01–17.09
(4 951 619) + конверсии 01–17.09 (324 наших). Окно закрыто ≥6 суток от
`recrawl_sent_at`, 176 случаев. Везде рядом сырой OR, MH по бренду и MH по дню.

- **Главная потеря — не конверсия, а выдача.** Воронка: 100% `done` → 72.2%
  получили клик → **13.4% получили клик с яндексовым реферером** → 0.09%
  конверсия. Из 176 конверсий 174 — на сабдоменах с яндексовым кликом.
  Конверсия среди попавших в выдачу **0.684%**, среди остальных **0.001%**.
  Рычаг — доля 13.4%, а не конверсия внутри неё.
- **«Есть поисковый клик» — рабочий промежуточный исход.** Называть его
  «попал в выдачу» неверно: клик требует индекса, позиции и спроса
  одновременно. Индексация как таковая ничем из доступного не меряется —
  `INDEKSACIYA_18.09.md` §0. 25 424 события против 176,
  в 144 раза больше: срезы читаются от 1.05×, а не от 1.5×. Мануал относил это
  к отсутствующему логу — закрывается яндексовым реферером клика.
- **12-страничные паки вдвое лучше семистраничных.** Конверсия 2.28
  [1.36–3.81], выдача 1.59 [1.51–1.66]; у 7-страничных 0.44 и 0.63. Согласовано

### 7.2 · Отменено проверкой — не воспроизводить

- **Ночной старт (00–05) как фактор.** Выглядел как 2.26–2.62, но на холдауте
  направление меняется: 0.44 на 01–06.09 против 5.53 на 07–11.09. Весь эффект —
  один пак `NEW102оформленосдатой`, запущенный 10.09 ночью: без него OR 0.89
  p=0.74. Конфаундером был контент, поэтому **для часовых разрезов нужна страта
  по контенту**, страт по бренду и дню недостаточно.
- **NEW102 как единое семейство.** Это два противоположных пака:
  `оформленосдатой` даёт 2.09% конверсии из выдачи, `оформленобездаты` — 0.32%
  при среднем 0.69%. Прежняя оценка 1.82× считала их вместе.
- **Фильтр по `campaign = dorgen_engine`.** Кампания трекера — это бренд или
  оффер, а не принадлежность сети: 295 673 клика вне `dorgen_engine` наши,
  `apex_engine`, `kush_engine`, `vavada_engine`, `pinup_engine`, `leebet`,
  `banda_engine` целиком наши. Отбор строк — только по ключу `subdomain`.
- **«Краулерная ловушка» и баг движка.** Путь `/promo/ru/ru/…` — штатная
  вложенность: hreflang наращивает `/ru`, спинтакс берёт seed от глубины.
  Ничего чинить не нужно.

## 9 · Реестр запусков — постоянный рабочий процесс

Пользователь присылает список запуска (группы и домены). Порядок действий:

1. Разобрать группы и домены.
2. Проверить пересечения с `analysis/domains_flat.txt` и `analysis/karantin_dubli.txt`.
3. Дописать секции групп в `analysis/launch_DD.MM.txt` за этот день.
4. Обновить `analysis/domains_flat.txt`.
5. Перегенерировать txt-списки: `python3 analysis/scripts/alltxt.py`
   (в нём `FILES` и `WEEK` — дописать новый день).
6. Дописать секцию в `analysis/launches.md`.
7. Закоммитить и запушить в `claude/dreamy-edison-rslqbw`.
8. Отдать пользователю txt-файлы и коротко подытожить по-русски.

Состояние реестра на 17.09: `domains_flat.txt` = 1864 домена.
15.09 — 265 доменов в 11 группах, 16.09 — 20 в 2, 17.09 — 58 в 3.
Неделя 11–17.09 — 592 домена.
