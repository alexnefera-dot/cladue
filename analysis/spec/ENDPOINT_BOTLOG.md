# Эндпоинт: заходы поисковых роботов

Запрос на новые данные. Формат, поля, объём.

---

## Что нужно

Агрегат по логу обращений, считается ночным заданием по вчерашнему логу.
Сырой лог не нужен и не запрашивается — после агрегации он может ротироваться
как обычно.

Две формы, начать можно с первой:

**A. Сводная — одна строка на сабдомен.** ~330 тыс. строк, 50–70 МБ.
Можно отдать полями прямо в `/v1/subdomains`.

**Б. По дням — сабдомен × сутки × бот**, только дни с заходами. ~1–2 млн строк
за 30 дней по одному `yandex`, 150–300 МБ.

---

## Формат строки

```json
{
  "subdomain": "pinup.3479.team",
  "date": "2026-09-15",
  "bot": "yandex",

  "hits": 42,
  "first_hit_at": "2026-09-15T03:14:22+03:00",
  "last_hit_at":  "2026-09-15T21:02:10+03:00",

  "unique_paths": 7,
  "pages": ["/", "/bonus", "/slots", "/app"],
  "max_ru_depth": 3,

  "status_2xx": 40,
  "status_3xx": 1,
  "status_4xx": 1,
  "status_5xx": 0,

  "bytes_sent": 812340
}
```

Для сводной формы — те же поля без `date`, накопительно за всё время, плюс
`days_with_hits`.

| поле | тип | описание |
|---|---|---|
| `subdomain` | string | хост, lowercase, без схемы |
| `date` | date | сутки по Europe/Kyiv (только в форме Б) |
| `bot` | enum | `yandex` · `google` · `other`. Обязателен минимум `yandex` |
| `hits` | int | число обращений |
| `first_hit_at` | datetime | первое обращение |
| `last_hit_at` | datetime | последнее обращение |
| `days_with_hits` | int | в скольких сутках были заходы (только в форме A) |
| `unique_paths` | int | различных страниц |
| `pages` | array | канонические страницы пака, которые забрал робот: `/`, `/bonus`, `/registracia`, `/app`, `/zerkalo`, `/vhod`, `/slots`, `/news`, `/info`, `/promo`, `/obzor`, `/partnery`. Хвосты `/ru` отбрасываются: `/bonus/ru/ru` считается как `/bonus` |
| `max_ru_depth` | int | максимальная глубина `/ru` в URL |
| `status_2xx`…`status_5xx` | int | обращения по классам кода ответа |
| `bytes_sent` | int | суммарно отдано байт. Необязательное |

---

## Объём

Оценка по фактическим числам: 331 548 сабдоменов за 24 дня, около 13 000 новых
в сутки.

| форма | строк | размер |
|---|---:|---:|
| A · сводная, только `yandex` | ~330 тыс. | 50–70 МБ |
| Б · по дням, только `yandex`, 30 дней | ~1–2 млн | 150–300 МБ |
| Б · по дням, все боты, 30 дней | ~2–4 млн | 300–600 МБ |

Хранение агрегатов: 30 суток достаточно.

---

## Требования к эндпоинту

Как у существующих: `GET`, `Authorization: Bearer`, JSON UTF-8, время ISO-8601
со смещением Europe/Kyiv, `null` вместо пустых значений.

Параметры: `date_from`, `date_to`, опционально `subdomain`,
`content_domain_id`, `bot`, пагинация `limit` + `cursor`,
`meta.next_cursor: null` на последней странице.

**Курсор должен переживать границу суток.** У `/v1/traffic` пагинация не
работает вовсе, у `/v1/events` курсор обрывается на первых минутах суток и при
этом отдаёт `next_cursor: null` — выгрузка успешно завершается на неполных
данных, что хуже явной ошибки. Проверка: выгрузить одни сутки целиком и сверить
число строк со счётчиком в БД.

---

## Чего не нужно

User-Agent строкой, IP, referer робота, заголовки запроса и ответа, тело
ответа, методы, полные URL с хвостами `/ru`, отдельные записи по каждому
обращению.
