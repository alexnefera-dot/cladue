# API трекера — выгрузка для аналитики

Два эндпоинта из общего контракта на восемь: **`/v1/clicks`** и **`/v1/conversions`**.
Остальные шесть (`/v1/subdomains`, `/v1/traffic`, `/v1/events`, `/v1/globals`,
`/v1/botlog`, `/v1/botlog/raw`) — на стороне системы запусков, трекер их данных
не знает и отдавать не может.

Ключ соединения двух систем — **`subdomain`** (хост в нижнем регистре, без схемы
и `www`) и **`clickid`**.

---

## Общие правила

| | |
|---|---|
| метод | только `GET`, ответ JSON, `charset=utf-8` |
| авторизация | `Authorization: Bearer <token>` (или `X-Api-Token: <token>`) |
| время | ISO 8601 со смещением, пояс **Europe/Kyiv**: `2026-09-15T13:03:11+03:00` |
| только дата | `2026-09-15`, границы **включительно** |
| нет значения | `null` — не пустая строка, не `0`, не `"-"` |
| булево | `true` / `false` |
| хост | нижний регистр, без схемы и `www` |
| повторный запрос | тот же диапазон → те же строки, порядок стабильный |

### Обёртка ответа

```json
{
  "data": [ ... ],
  "meta": {
    "count": 1000,
    "next_cursor": "eyJ0cyI6MTc4OTU2MDYyNCwiaWQiOjJ9",
    "generated_at": "2026-09-15T18:20:04+03:00",
    "stable_until": "2026-09-15T18:00:11+03:00",
    "timezone": "Europe/Kyiv"
  }
}
```

`next_cursor: null` — последняя страница. `limit` по умолчанию 1000, максимум 5000.
`cursor` — непрозрачная строка из предыдущего ответа, OFFSET не используется.

**`stable_until`** — время последнего импорта кликов. Строки с `at` раньше него
финальные и при повторном запросе не изменятся. Более свежие конверсии ещё могут
дозаписать `subdomain`, когда клик доедет из лога (см. «Задержка привязки»).

### Ошибки

```json
{ "error": { "code": "invalid_range", "message": "date_to earlier than date_from" } }
```

`unauthorized` 401 · `invalid_param` 400 · `invalid_range` 400 ·
`rate_limited` 429 · `internal` 500.

### Ограничения

| | |
|---|---|
| диапазон дат за запрос | не больше 92 суток, иначе `invalid_range` |
| строк за запрос | максимум 5000 |
| запросов в минуту | 60 на токен, дальше 429 с `Retry-After` |
| одновременных выгрузок | 2, третья получает 429 сразу |

Ограничения не про экономию — трекер стоит на одном сервере с приёмом постбеков
и отдачей редиректов, и выгрузка не должна их ронять.

## 1 · `GET /v1/clicks`

Одна строка = переход. Переход с реферером Яндекса доказывает, что сабдомен был
в выдаче.

```
GET /v1/clicks?date_from=2026-09-14&date_to=2026-09-15&limit=1000
Authorization: Bearer <token>
```

| параметр | тип | обяз. | |
|---|---|---|---|
| `date_from` · `date_to` | date | да | включительно |
| `subdomain` | string | нет | только этот хост |
| `ua_class` | enum | нет | `all` (по умолч.) · `human` · `bot` |
| `event` | enum | нет | фильтр по событию: `direct` · `view` · `click` |
| `limit` · `cursor` | int · string | нет | |

| поле | тип | пример |
|---|---|---|
| `at` | datetime | `2026-09-15T15:02:41+03:00` |
| `clickid` | string | `73aa6251ac4c4421` — уникален на переход, не на человека |
| `subdomain` | string · null | `shuffle.3479.team` |
| `referer` | string · null | `https://yandex.ru/` — обрезан до 255 символов |
| `country` | string · null | `RU` — из заголовка Cloudflare `CF-IPCountry` |
| `campaign` | string · null | `dorgen_engine` — слаг реф-ссылки |
| `landing_path` | string · null | `/ru/ru/ru/` — точка входа, см. ниже |
| `exit_path` | string · null | `/ru/ru/ru/bonus` — путь из реферера |
| `is_bot` | bool | классификация по User-Agent на момент клика |
| `event` | enum | `direct` · `view` · `click` — см. ниже |

**Боты не фильтруются по умолчанию.** Молчаливый отброс строк — ровно тот случай,
когда данные придут, расчёт пройдёт, а результат будет неверным, и по ответу
этого не видно. Отдаётся флаг, решение за аналитиком. Классификация грубая —
поиск бот-сигнатур в User-Agent (`bot`, `crawl`, `spider`, `curl`, `python`,
`headless` и подобные), плюс пустой UA.

### `event`: переход, показ преленда и клик по нему

У части кампаний включён преленд — промежуточная страница вместо мгновенного
редиректа. Тогда один посетитель даёт **две строки**:

| `event` | что произошло |
|---|---|
| `direct` | преленда нет, сразу ушёл на оффер (так у большинства кампаний) |
| `view` | показан преленд |
| `click` | нажата кнопка на преленде — **тот же `clickid`**, что у `view` |

**Переходом считается `direct` или `view`.** Строки `click` — это второй шаг
того же посетителя; сложив их с остальными, трафик кампаний с прелендом
удвоится, и они станут несравнимы с остальными.

Конверсия привязывается к `clickid`, общему для `view` и `click`, поэтому
соединение по `clickid` работает одинаково в обоих случаях.

### `landing_path` и `exit_path` — это разные вещи

- **`exit_path`** — страница, **с которой ушли**. Считается из `Referer`.
  Бесплатно, но появляется только если реферер вообще дошёл.
- **`landing_path`** — страница, **на которую пришли из поиска**. Реферер её не
  знает: если человек полистал сайт, реферер покажет последнюю страницу.
  Приходит отдельным параметром `?lp=` от дор-движка.

Реф-ссылка со стороны дора должна выглядеть так:

```
https://sitegrator.com/go/dorgen_engine?site=shuffle.3479.team&lp=/ru/ru/ru/
```

- `site=` — хост. Без него `subdomain` берётся из хоста реферера, а реферер
  пропадает при `rel="noreferrer"`, при переходе на http и в части браузеров —
  такие клики уходят с `subdomain: null` и выпадают из соединения.
- `lp=` — путь входа из сессии. Передаётся **путь, а не число уровней**: из пути
  выводится и глубина, и тип страницы; из числа — ничего.

Пока движок их не шлёт, `landing_path` приходит `null`.

## 2 · `GET /v1/conversions`

Одна строка = событие.

```
GET /v1/conversions?date_from=2026-09-14&date_to=2026-09-15&event=fd
Authorization: Bearer <token>
```

| параметр | тип | обяз. | |
|---|---|---|---|
| `date_from` · `date_to` | date | да | включительно |
| `event` | enum | нет | `reg` · `fd` |
| `subdomain` | string | нет | только этот хост |
| `limit` · `cursor` | int · string | нет | |

| поле | тип | пример · значения |
|---|---|---|
| `at` | datetime | `2026-09-15T15:15:11+03:00` |
| `event` | enum · null | `reg` · `fd` |
| `event_raw` | string · null | сырое имя события от партнёрки |
| `clickid` | string | связывает с переходом |
| `subdomain` | string · null | |
| `referer` · `country` | string · null | |
| `campaign` | string · null | |
| `landing_path` · `exit_path` | string · null | как в `/v1/clicks` |
| `payout` | null | всегда — см. ниже |
| `status` | null | всегда — см. ниже |
| `linked_at` | datetime · null | момент привязки к клику |

`event_raw` нужен, чтобы новое событие от партнёрки было видно, а не утонуло
в «прочем»: `event` станет `null`, а `event_raw` покажет, что именно пришло.
Текущая классификация — `reg`/`registration`/`lead` → `reg`,
`dep`/`deposit`/`sale`/`ftd`/`purchase` → `fd`.

### Задержка привязки

Постбек приходит через минуты после клика, а клик доезжает до базы кроном раз
в час. В момент постбека клика в базе ещё нет, поэтому `subdomain`, `referer`,
`country`, `landing_path` и `linked_at` у свежей конверсии пустые — их дописывает
ближайший импорт.

Данные клика **снимаются в строку конверсии**, а не подтягиваются соединением
на лету. Поэтому: после заполнения `linked_at` строка финальная и не изменится,
а чистка старых кликов по retention её не обнуляет задним числом.

**Практика:** брать окно, целиком закрытое `meta.stable_until`. Строки с
`linked_at: null` и `subdomain: null` — это конверсии, для которых клика в базе
нет вообще (постбек с чужим или потерянным `clickid`). Они **отдаются**, а не
отбрасываются.

---

## Чего в трекере нет

| что | почему |
|---|---|
| `payout` | партнёрка сумму в постбеке не присылает. Отдаётся `null`, а не выдуманный `0` |
| `status` (approved/hold/rejected) | постбек приходит один раз, отмену депозита партнёрка не шлёт. Узнать, снимаются ли ФД задним числом, отсюда нельзя — это запрос к партнёрке |
| `content_label` | в трекере нет. Матчится в анализе по `subdomain` через `/v1/subdomains` |
| IP и User-Agent | не выгружаются намеренно: для расчёта не нужны, а хранятся у нас |
| позиции, RKN, GSA, Метрика | трекера не касаются |

## Настройка

Токены — в `config.php`, ключ `api_tokens`. Список, а не один токен: каждому
потребителю выдаётся свой, чтобы отозвать один, не трогая остальных, и чтобы
в логе было видно, кто что тянул. Пустой список = API выключен целиком.

```php
'api_tokens' => [
    'analytics' => '…',
],
```

Сгенерировать: `php -r 'echo bin2hex(random_bytes(24)), "\n";'`

Токен в git не кладётся — как и MySQL-креды, он живёт только в `config.php`
на сервере.

Обращения пишутся в `cache/api.log` (токен, эндпоинт, диапазон, строк, мс),
файл обрезается по достижении 5 МБ.

### retention

`retention_days` в `config.php` — через сколько суток крон удаляет старые клики.
Конверсии не удаляются никогда, и снимок в строке конверсии переживает чистку.
Но `/v1/clicks` за период старше retention вернёт пусто. Если аналитике нужна
история глубже — поднять значение или поставить `0`.
