# Общий план проверки архива

Применяется к каждому архиву целиком, независимо от шаблона. Особенности шаблонов — в файлах `checks/<N>-str.md`.
Автоматическая часть выполняется скриптом `scripts/check_archive.py`, коды проверок совпадают.

Уровни: **ERROR** — сайт в брак; **WARN** — нужно посмотреть и решить; **INFO** — справочно. Сайты с заглушками, дублями и неполные 7-стр не дорабатываются, а **убираются** из выдачи; причина пишется в отчёт и сводку.

## A. Архив и структура

| Код | Проверка | Критерий | Как | Уровень |
|---|---|---|---|---|
| A1 | Мусор в архиве | Нет `__MACOSX`, `.DS_Store`, `Thumbs.db`, файлов `._*` | авто | WARN |
| A2 | Раскладка | `<N>-стр/<домен>/<страница>.html`; для группы есть шаблон. Группы 9-стр и 10-стр собираются в 7-стр: `privacy`, `contacts`, `about` выбрасываются | авто | WARN / INFO (сборка) |
| A3 | Количество страниц | В папке сайта столько файлов `.html`, сколько страниц в шаблоне (для 13-стр — 12) | авто | ERROR |
| A4 | Набор страниц | Имена файлов совпадают с эталонным набором шаблона, без лишних и недостающих. Неполный сайт 7-стр не дорабатывается, а убирается | авто | ERROR / убран (7-стр) |
| A5 | Имена и посторонние файлы | Имена латиницей в нижнем регистре; в папке сайта только `.html`, без вложенных папок | авто | WARN |
| A6 | Кодировка | UTF-8 без BOM, переводы строк LF, без символов-замен `U+FFFD` (следы порчи текста при выкачке) | авто | ERROR |

## B. Содержимое страницы

| Код | Проверка | Критерий | Как | Уровень |
|---|---|---|---|---|
| B1 | Объём | Не меньше минимума слов для шаблона; меньше 60 слов — заглушка. Сайт с заглушками не дорабатывается, а убирается с пометкой «контент из заглушек» | авто | WARN / убран (заглушка) |
| B2 | Заголовки | Не меньше минимума `h2` для шаблона | авто | WARN |
| B3 | Тема раздела | Ключевые слова раздела встречаются не реже 2 раз; текст не похож на другой раздел (политика, контакты, о нас) | авто + вручную по первому `h2` | WARN |
| B4 | Чужие бренды и контакты | Бренд считается по сайту: латинское слово в строгом контексте («казино X», «X Casino», «зеркало X», «сайт X», «вход в X», строка `<p>X.</p>`) не реже 3 раз на 2 страницах; слова из контекстов слотов и провайдеров («от X», «слот X») не считаются. E-mail и чужие домены — ошибка, примерные домены и известные сервисы — нет, телефон — предупреждение | авто | ERROR / WARN (телефон) |
| B5 | Плейсхолдеры | Только `%brand_name_ru%`, `%brand_name_en%`, `%domain_name%`, `%date%`; нет `{NAME}`, `{AMOUNT}`, `{{ }}`, `[[ ]]`, `{a\|b}`. Отсутствие бренда на странице допустимо | авто | ERROR / INFO (нет бренда) |
| B6 | Разметка | Теги закрыты и вложены правильно; только теги из списка в `templates/README.md`; нет `html`, `head`, `body`, `script`, `style`, `img`, `iframe`, `div`, `span` | авто | ERROR |
| B7 | Пустые элементы | Нет пустых `h2`, `h3`, `p`, `li`, ссылок без текста | авто | WARN |
| B8 | Повторы заголовков | Один `h2` не повторяется на странице | авто | WARN |
| B9 | Порядок блоков | FAQ («❓ Честные ответы на вопросы») не первый блок | авто | INFO |
| B10 | Склейки | Слова и числа не склеены без пробела (следы вырезанных тегов) | авто | INFO |
| B11 | Согласованность чисел | Процент бонуса, лимиты и сроки не противоречат друг другу в пределах сайта | авто (список значений) + вручную | INFO |
| B13 | Тонкая страница | Главная: не меньше 200 слов настоящего текста (абзацы, списки, таблицы; карточки слотов и строка бренда не считаются) и хотя бы один раздел (`h2` или `h3` не про слот), либо не меньше 150 слов и трёх разделов. Иначе сайт убирается с пометкой «главная без текста». Главная короче 260 слов и остальные страницы короче 100 слов без разделов — предупреждение | авто | убран (главная) / WARN |
| B12 | Качество текста | Русский язык без английских вставок, нет обрывов фраз, нет «лёгких денег» и обещаний гарантированного выигрыша, нет упоминаний других казино | вручную, выборочно 2–3 страницы на сайт | WARN |

## C. Ссылки

| Код | Проверка | Критерий | Как | Уровень |
|---|---|---|---|---|
| C1 | Ссылки в никуда | Каждая внутренняя ссылка ведёт на `/` или на страницу, которая есть в этом сайте | авто | ERROR |
| C2 | Ссылка по смыслу | Якорь называет один раздел, а ссылка ведёт на другой («бонусы» → `/app`, «промокоды» → `/`). Так задумано, только справочно | авто | INFO |
| C3 | Внешние ссылки | Нет `http(s)://`, `mailto:`, `tel:` | авто | WARN |
| C4 | Перелинковка | На странице есть хотя бы одна внутренняя ссылка (кроме 1-стр) | авто | INFO |

## D. Уникальность

| Код | Проверка | Критерий | Как | Уровень |
|---|---|---|---|---|
| D1 | Точные дубли | Нет одинаковых файлов в архиве. Сайт с дублем убирается с пометкой «контент дублированный» | авто | убран (дубль) |
| D2 | Почти-дубли между сайтами | Совпадение 6-словных цепочек. От порога (`--порог`, по умолчанию 60 %) сайт убирается как дублированный, из пары остаётся тот, где текста больше; от 30 % — предупреждение и строка в разделе «Уникальность» | авто | убран (дубль) / WARN |
| D4 | Совпадение по сайту | В отчёте раздел «Уникальность»: для каждого сайта максимальное совпадение текста страницы с любой страницей другого сайта, показаны сайты от 30 %. Порог отбора по уникальности задаёт пользователь | авто | справочно |
| D3 | Дубли внутри сайта | Ни одна страница не содержит ≥ 50 % текста другой страницы того же сайта | авто | WARN |

## Режим «только фильтрация»

Когда правки делает другой этап (чистка кода и переменных на стороне пользователя), архив только фильтруется: набор страниц, заглушки, тонкая главная, точные дубли и уникальность. Бренды, переменные, ссылки и разметка не смотрятся.

```bash
python3 scripts/filter_archive.py Archive.zip -o /tmp/filter --порог 60
```

Результат: `сводка.md`, `сайты.tsv` (строка на сайт с вердиктом, причиной, объёмом и совпадением), `годные.txt`, копии страниц в `годные/` и `убрано/` (без `--без-копий`). Сайт с совпадением страницы от порога с чужой убирается, из пары остаётся сайт с бо́льшим текстом. Скрипт потоковый: рассчитан на архивы в сотни тысяч страниц.

## Порядок проверки архива

1. Запустить скрипт: отчёт в `reports/<дата>-<имя архива>.md`, сайты разложить по типам во временную папку (не в репозиторий):
   ```bash
   python3 scripts/check_archive.py Archive.zip -o reports/2026-09-06-archive.md --sort /tmp/sorted
   ```
   В папке будут `годные/<тип>/<домен>/`, `на-доработку/<тип>/<домен>/`, `убрано/<тип>/<домен>/` и `сводка.md` с причинами. Сайты 8/9/10-стр лежат уже собранными в 7-стр. Пользователю отдаётся весь архив целиком.
2. Пройти по сайтам с ERROR: заглушки, недостающие страницы, чужие бренды, незаполненные переменные, ссылки в никуда, дубли.
   Что чинится механически — чинить на распакованной копии и проверять заново:
   ```bash
   python3 scripts/fix_archive.py /tmp/Archive-fixed --brand Motor --brand Daddy
   python3 scripts/check_archive.py /tmp/Archive-fixed -o reports/2026-09-06-archive-fixed.md --sort /tmp/sorted
   ```
   Скрипт заполняет `{NAME}`/`{AMOUNT}`, `{YYYYMMDD}` → `%date%`, снимает скобки `{{ }}`, заменяет e-mail и чужие домены на `%domain_name%`, а бренды — на плейсхолдеры: `--auto-brand` находит бренд каждого сайта сам (той же функцией, что проверка), `--brand X` задаёт вручную. Заглушки, недостающие страницы и дубли так не чинятся.
3. По WARN решить: тема страницы (B3) — открыть первый `h2` и пару абзацев.
4. Выборочно прочитать 2–3 страницы на сайт по пункту B12.
5. Итог по сайту: **годен** / **на доработку** с перечнем кодов. Годные отдать пользователю архивом по типам.

Порядок решений по браку, как договорились с пользователем:

- **нет страницы** (A3/A4) — убрать;
- **чужой проект или сервис** — убрать: это сайт не по нашей теме, а не брендовая опечатка;
- **не те бренды** (B4) — сначала починить `fix_archive.py --auto-brand`, и только то, что не исправилось, убрать: второй прогон запускается как `python3 scripts/check_archive.py … --убрать B4`.
