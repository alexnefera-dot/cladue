# CLAUDE.md

Инструкция для Claude Code и других AI-ассистентов, работающих в этом репозитории.

## О репозитории

**Репозиторий:** `alexnefera-dot/cladue`

Проверка архивов с HTML-фрагментами сайтов по шаблонам. Процесс:

1. Пользователь присылает архив: `<N>-стр/<домен>/<страница>.html` (N — количество страниц шаблона).
2. Шаблоны разобраны в `templates/README.md`, планы проверки — в `checks/`.
3. Архив прогоняется скриптом, отчёт кладётся в `reports/`, дальше — ручная часть плана.
4. Новый вариант шаблона: описать в `templates/README.md`, завести `checks/<N>-str.md`, добавить набор страниц в `TEMPLATES` скрипта.

## Структура

```
cladue/
├── CLAUDE.md
├── templates/README.md      # разбор шаблонов: формат файлов, наборы страниц, типовые дефекты, открытые вопросы
├── checks/
│   ├── 00-common.md         # общий план проверки, коды A*/B*/C*/D*/F*
│   └── <N>-str.md           # особенности шаблона на N страниц
├── scripts/check_archive.py # автоматическая часть плана (только стандартная библиотека Python 3)
├── scripts/fix_archive.py   # механические правки: {NAME}/{AMOUNT}, замена чужого бренда на плейсхолдеры
├── reports/<дата>-<архив>.md # отчёты по проверенным архивам
└── docs/oformlenie-instrukciya.md # инструкция пользователя по оформлению комплектов (стили и картинки)
```

## Проверка архива

```bash
python3 scripts/check_archive.py Archive.zip -o reports/2026-09-06-archive.md --sort /tmp/sorted
```

- Принимает zip или распакованную папку. Имена в zip с macOS без флага UTF-8 перекодируются автоматически.
- `--sort` раскладывает сайты по типам (`годные/`, `на-доработку/`, `сводка.md`) во временную папку; результат отдаётся пользователю архивом, в репозиторий не попадает.
- Группы 9-стр и 10-стр при проверке собираются в шаблон 7-стр (`CONVERT` в скрипте). Неполный сайт 7-стр убирается из выдачи (`DISCARD_INCOMPLETE`).
- Механические дефекты (`{NAME}`, `{AMOUNT}`, чужой бренд) правятся на распакованной копии: `python3 scripts/fix_archive.py /tmp/Archive-fixed --brand Motor`, затем проверка заново. Исправленные копии в репозиторий не попадают.
- Код возврата 1, если есть ERROR. Уровни и коды проверок — в `checks/00-common.md`; коды в скрипте и в документе должны совпадать.
- Отчёт — сгенерированный файл, руками не править: выводы и решения записывать в `templates/README.md` (открытые вопросы) или в `checks/`.
- Пороги и наборы страниц живут в начале скрипта (`TEMPLATES`, `CONVERT`, `TOPIC`, `ANCHOR_TARGET`, `LATIN_WHITELIST`).

## Оформление комплектов

Стили и картинки для годных комплектов делаются по `docs/oformlenie-instrukciya.md` прямо в чате, по запросу пользователя. Скрипты и движок для этого в репозиторий не добавлять: так решил пользователь.

## Язык

Общение с пользователем, документы и отчёты — на русском. Сообщения коммитов — на английском.

## Git

- `main` — основная ветка. `claude/<описание>-<id-сессии>` — ветки Claude Code.
- Работать только в назначенной ветке. Пушить командой `git push -u origin <ветка>`.
- Коммиты в формате [Conventional Commits](https://www.conventionalcommits.org/): `docs`, `feat`, `fix`, `chore`, `refactor`.

## Правила для AI-ассистента

- Перед изменением файла прочитать его целиком и следовать его стилю.
- Делать минимальные, сфокусированные изменения; не расширять задачу.
- Не добавлять заглушки и разделы «на будущее» — только то, что нужно сейчас.
- Не коммитить сами архивы и их содержимое: только отчёты и документы. Не коммитить секреты и персональные данные.
- Меняя проверку в скрипте, обновить её описание в `checks/00-common.md`, и наоборот.
