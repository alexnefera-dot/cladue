# yandex-sites

Инструмент на PHP, который прогоняет список поисковых запросов через выдачу
Яндекса, собирает сайты из результатов, отбирает нужные по настраиваемым
правилам и, при желании, заходит на каждый отобранный сайт как посетитель из
поиска, сохраняя HTML и скриншоты страниц.

Что умеет:

- **веб‑интерфейс** (окно в браузере): ввод ключей, запуск сбора, прогресс, таблица
  результатов и повтор сбора по таймеру — без работы в консоли;
- три источника выдачи: официальный **Yandex Search API**, сервис **XMLStock**
  и **живая выдача** yandex.ru, как её видит обычный пользователь (через ваши прокси);
- отбор сайтов: доменные зоны, чёрные и белые списки доменов, слова и
  регулярные выражения в заголовке и сниппете, регулярные выражения по URL,
  минимальное число запросов, в выдаче которых встретился сайт;
- HTTP-проверка сайтов: код ответа, редиректы на чужой домен, наличие или
  отсутствие текста на странице (телефон, «домен продаётся»);
- визиты на сайты через headless Chromium (Playwright) или curl с Referer
  выдачи Яндекса; несколько визитов на сайт с разными прокси и User-Agent,
  чтобы увидеть, показывает ли сайт разным посетителям разные версии страницы;
- результаты в `sites.csv` (открывается в Excel), `sites.json`, `domains.txt`,
  страницы сайтов в `out/pages/<сайт>/` (при обходе шапки — в `out/pages/<N>-стр/<сайт>/`,
  файлы названы по URL).

Ответы источников кэшируются: фильтры можно менять и перезапускать отбор без
повторных обращений к выдаче.

## Требования

- PHP 8.1 или новее с расширениями `curl`, `dom`, `json`, `mbstring`
  (`intl` желательно для кириллических доменов в фильтрах).
- Для визитов с выполнением JavaScript — Node.js 18+ и Playwright
  (`npm install playwright && npx playwright install chromium`); без них
  визиты выполняются через curl.
- Composer не обязателен: сторонних PHP-зависимостей нет, автозагрузка встроена.

## Установка

```bash
git clone https://github.com/alexnefera-dot/cladue.git
cd cladue
php bin/setup.php --proxy=http://host:port:user:pass
```

`bin/setup.php` создаёт `config.php`, `.env` и `proxies.txt` из примеров
(существующие файлы не трогает), добавляет переданные прокси, создаёт папки
`cache/`, `out/`, `debug/`, проверяет PHP-расширения и Playwright и печатает
команды для проверки прокси и пробного запуска. Обновить код до свежей версии
с GitHub, не трогая настройки, прокси, кэш и результаты: `php bin/setup.php --update`.
Всё то же можно сделать руками:

```bash
cp config.example.php config.php   # источник, правила отбора, визиты
cp .env.example .env               # данные доступа к API / XMLStock
cp proxies.example.txt proxies.txt # прокси для живой выдачи и визитов
```

## Веб‑интерфейс

Кто не хочет работать в консоли — запустите панель управления, она откроется в браузере:

```bash
php bin/panel.php
```

Панель (адрес `http://127.0.0.1:8777`, доступна только с этого компьютера) разбита на две
вкладки: **«Главная»** (запросы, запуск, прогресс, журнал и таблица результатов) и
**«Настройки»** (ключи доступа и все условия отбора). Панель позволяет:

- ввести ключи доступа (XMLStock, при желании Yandex API) — они сохраняются в `.env`;
- задать запросы и условия отбора: источник, регион, число страниц, разрешённые зоны,
  дополнительные исключения доменов;
- **параметры XMLStock** (когда выбран этот источник): устройство выдачи (мобайл / десктоп /
  планшет), домен Яндекса (`yandex.ru` / `.by` / `.kz` / …) и произвольные доп. параметры
  (`key=value` через `&`, например `within=77`);
- **дедупликация по домену** — «один сайт на домен»: если домен уже есть, любой его
  поддомен второй раз не берётся (это же можно включить в конфиге как `unique_by => 'domain'`);
- **тип домена** — брать любые домены, только корневые (`example.ru`) или только поддомены
  (`shop.example.ru`) (`filters.domain_scope`);
- включить открытие найденных сайтов в браузере (Chromium) с числом заходов и движком;
- **брать только топ N выдачи** (по умолчанию 10);
- **база собранных доменов**: каждый сбор записывает найденные домены в общую базу
  (`runs/domains-base.txt`) и по умолчанию **пропускает пересечения** — домены, которые
  уже собраны раньше, второй раз не берутся; базу видно в панели, её можно очистить;
- **уникальные домены**: результаты сводятся по регистрируемому домену — если в разных запросах
  встречаются разные поддомены одного домена, берётся один (галочка «дедуп по домену», по умолчанию вкл);
- **предпросмотр при сборе**: на этапе «Сборка» (галочка «делать скриншот главной») по каждому
  уникальному домену делается **скриншот главной** (или пишется ошибка) — сразу видно объём будущей
  выгрузки и где **наши** сайты (помечены «исключён как наш»), ещё до полной выгрузки; нужен Chromium.
  В таблице результатов у каждого сайта — **превью** (клик увеличивает в окне), **крестик ✕** чтобы
  убрать неподходящий сайт, а кнопка **«Очистить всё»** чистит контент по **оставшимся**;
- **два шага без выпадающего списка этапов** (вкладка «Главная»): кнопка **«Собрать сайты»**
  стоит рядом с запросами (шаг 1 — домены из выдачи + скриншоты главной), а кнопка **«Выгрузить
  страницы оставшихся»** — над таблицей результатов (шаг 2 — открывает в браузере и сохраняет
  страницы только тех сайтов, что остались после удаления крестиком);
- **очистка контента — кнопками в таблице результатов**: из скачанных страниц делает **шаблоны
  статей** — оставляет только тело статьи (после `</h1>` и до блока «Популярные запросы»), убирает
  блок слотов, приводит все ссылки к шести относительным путям (`/vhod`, `/registracia`, `/main`,
  `/app`, `/slots`, `/zerkalo`) и подставляет переменные вместо домена (`%domain_name%`), даты
  (`%date%`) и названия бренда (`%brand_name_ru%` / `%brand_name_en%`). **Бренд определяется
  автоматически** (английский — из домена, русский — по тексту через транслитерацию), с учётом
  регистра и смешения латиницы/кириллицы (`STAKE`≡`STAKЕ`). **Посторонние бренды** (другие казино
  в тексте) тоже заменяются — по встроенному списку известных брендов (дополняется файлом
  `brands.txt`). У каждого сайта в таблице есть кнопка **«Очистить»** — смотрите скриншот и жмёте,
  очищенные статьи ложатся в папку **`runs/current/content/<N>-стр/<сайт>/`** (N — число очищенных
  страниц), ничего не скачивается; а кнопка **«Очистить всё»** (над таблицей) чистит сразу все
  **оставшиеся** сайты по тем же папкам (наши и убранные крестиком исключены). Повторная «Выгрузка
  страниц» — чистый пере-сбор: прежние `pages/` и `content/` удаляются, качаются только оставшиеся.
  Массовая очистка в архив доступна и из консоли — `php bin/clean-content.php`;
- **обход меню сайта** (галочка «Скачивать все страницы из шапки сайта»): на этапе выгрузки
  открывается не одна страница, а все страницы из меню — **и в шапке, и в подвале** (footer),
  начиная с главной, только в пределах **того же поддомена** (`www` считается тем же хостом);
  ссылки и редиректы на **другие поддомены** (соседние бренды сетки) и на другие сайты
  пропускаются, карты сайта (`htmlmap`, `sitemap`, `sitemap-all.xml`) и файлы-ресурсы (`.xml`,
  `.pdf`, картинки …) — тоже; «циклы» переключателя языка (`/RU-ru/RU-ru/…/app`) **схлопываются**,
  так что реальная страница за циклом (`app`) качается один раз; языковой префикс не плодит копий
  (`/promo` и `/RU-ru/promo` — одна страница, без `promo-2`); главная не сохраняется дважды
  (ссылка меню на «/» не создаёт `main-2`); лимит — «Макс. страниц на сайт»;
  - **повтор при любой ошибке через другой прокси**: если страница не открылась (таймаут, сеть),
    вернула код блокировки (403/429/5xx) или это страница-заглушка антибота (**Cloudflare**,
    DDoS-Guard и т.п.) — загрузка повторяется через **другой прокси** (`visit.retries`, по
    умолчанию 2); страницы-блокировки **не** сохраняются как контент, а помечаются ошибкой
    «заблокировано»;
  - **файлы называются коротко по URL** — по последнему сегменту адреса: `/registracia` →
    `registracia.html`, `/catalog/plastikovye/` → `plastikovye.html`, главная → `main.html`;
  - **одна и та же страница не качается дважды**: адреса-алиасы (`/`, `/index.php`, `/about` и
    `/about/`) сводятся к одному и открываются один раз;
  - **одностраничники и дубликаты не качаются дважды**: сначала открывается главная, затем
    одна пробная страница из меню; если она сильно совпадает с главной (порог `visit.similarity`,
    по умолчанию 0.9) — сайт считается одностраничником и остальные страницы не открываются;
    совпадающие между собой внутренние страницы тоже отбрасываются;
  - **скриншот — только для главной** (по ней и смотрят сайт); внутренние страницы сохраняются
    как HTML без картинок;
  - **заглушки не путаются с дубликатами**: экран проверки возраста (18+), cookie-стена или
    «включите JavaScript» выглядит одинаково на всех страницах, но за ним контент разный.
    В Chromium (Playwright) такая заглушка по возможности проходится автоматически (нажимается
    «Да / Подтверждаю / Принять»), а если пройти не удалось — страницы всё равно **не** схлопываются
    в один и помечаются как «заглушка (проверка возраста/куки)»;
  - **папки по числу страниц**: готовые сайты раскладываются в `out/pages/<N>-стр/<сайт>/`
    (`1-стр`, `7-стр`, `11-стр` …) — сразу видно, сколько уникальных страниц у сайта;
- **исключение своих шаблонов**: сайты, которые вы сами размещаете, можно не собирать и не
  скачивать — они опознаются по устойчивым меткам (путь к ассетам, домен размещения, токен
  проверки из `<head>`), не завися от меняющихся кодов/стилей (QR, оформление). По умолчанию уже
  включена метка `/uploads/brands/` (общий путь к ассетам шаблона — ловит все бренды на любых
  доменах); дополнительные точечные метки (конкретные домены, токены) удобно держать в
  `own-markers.txt` (по одной на строку, файл не коммитится) или в `filters.own_markers`. Такой
  сайт в отчёте помечается **«исключён как наш»**; HTML не сохраняется, но **скриншот главной
  остаётся** (в папке `out/pages/наши/<сайт>/`) — чтобы проверить глазами; метки-домены отсеиваются
  ещё на этапе сбора;
- **отчёт по каждому сайту**: сколько страниц скачано, либо **текст ошибки с причиной** (таймаут,
  код ответа, редирект…), либо «исключён как наш»; ссылки открыть сохранённый HTML и скриншот;
- **повторять сбор каждые N часов** — таймер: панель раз в N часов запускает сбор заново
  (и каждый раз добавляет в результат только новые домены);
- видеть прогресс (сбор → фильтрация → открытие сайтов), журнал и таблицу результатов,
  скачать `sites.csv`, `sites.json`, `domains.txt`.

Схема работы: **этап 1** — проходим XMLStock по всем запросам (топ N) → фильтруем домены
(дедуп по домену + пропуск уже собранных из базы) → сохраняем новые домены; **этап 2** —
выгрузка: открываем все собранные сайты в браузере. По таймеру этап 1 повторяется каждые N часов
и добавляет только новые домены.

Панель — надстройка над теми же командами (`bin/run-job.php` выполняет один сбор и пишет
прогресс в `runs/current/status.json`); всё, что делает панель, доступно и из консоли.

## Источники выдачи

| Источник | Как включить | Что нужно | Особенности |
|----------|--------------|-----------|-------------|
| Yandex Search API (по умолчанию) | `source => 'api'` | каталог Yandex Cloud, сервисный аккаунт с ролью `search-api.webSearch.user`, API-ключ (`YANDEX_FOLDER_ID`, `YANDEX_API_KEY`) | официальный платный API, до 100 сайтов на страницу, стабильный XML-формат |
| XMLStock | `source => 'xmlstock'` или `--source=xmlstock` | `XMLSTOCK_USER` и `XMLSTOCK_KEY` из личного кабинета xmlstock.com | тот же формат Яндекс.XML, платно за запрос, без настройки Yandex Cloud |
| Живая выдача | `source => 'live'` или `--live` | свои прокси (`proxies.txt`) | страница yandex.ru как у пользователя, около 10 результатов на страницу, вёрстка Яндекса меняется |

### Yandex Search API

1. В консоли Yandex Cloud выберите каталог — его идентификатор и есть `YANDEX_FOLDER_ID`.
2. Создайте сервисный аккаунт с ролью `search-api.webSearch.user` и API-ключ для него — `YANDEX_API_KEY`.
   Вместо ключа можно использовать IAM-токен (`YANDEX_IAM_TOKEN`), он живёт 12 часов.
3. Квоты: 10 запросов в секунду, 10 000 синхронных запросов в час, не более 250 результатов на запрос.

Документация: <https://yandex.cloud/ru/docs/search-api/>.

### XMLStock

Сервис отдаёт выдачу Яндекса в формате Яндекс.XML. В `.env` укажите
`XMLSTOCK_USER` и `XMLSTOCK_KEY`; в разделе `xmlstock` конфигурации можно
задать домен поиска (`domain`, например `yandex.kz`), тип устройства
(`device`) и любые дополнительные параметры сервиса (`extra_params`).
Параметры поиска (`region`, `groups_on_page`, сортировка) общие с API.

### Живая выдача

Скрипт запрашивает страницу `yandex.ru/search/?text=…&lr=…&p=…` с обычными
заголовками браузера, разбирает HTML и отдаёт результаты в тот же конвейер
фильтров. Как это устроено:

- Прокси берутся из общего списка `proxies` в конфигурации, файла `proxy_file`
  (`--proxies=FILE`) и опций `--proxy=…`; основной формат строки —
  `http://host:port:user:pass`, остальные описаны в `proxies.example.txt`.
  Без прокси — прямое подключение; строка `direct` добавляет прямое подключение
  в общую очередь. Тот же список по кругу используется для визитов на сайты.
- Прокси используются по кругу (`requests_per_proxy` запросов подряд через один);
  между запросами через один прокси выдерживается пауза `delay_ms` плюс случайная
  добавка `jitter_ms`, между любыми запросами — не меньше `min_gap_ms`.
- Каждому прокси назначаются постоянный User-Agent и своя банка cookies.
- **Капча не обходится.** Прокси, получивший капчу, ставится на паузу на
  `captcha_cooldown` секунд, запрос повторяется через следующий прокси
  (`attempts` попыток). Если все прокси на паузе дольше `max_wait`, прогон
  останавливается, результаты сохраняются. Сетевые ошибки дают паузу
  `error_cooldown`, после `max_proxy_failures` ошибок подряд прокси отключается.
- Ответы API Яндекса и живая выдача могут отличаться: живая страница
  персонализирована под регион и историю, поэтому для сравнения используйте
  один регион (`--region`) и несколько запусков.

Перед прогоном полезно проверить прокси: каждый делает один запрос к выдаче,
и в ответе видно, получена ли выдача, капча или ошибка:

```bash
php bin/yandex-sites.php --check-proxies --proxies=proxies.txt
```

Если Яндекс изменил вёрстку и результаты перестали разбираться, запустите с
`--save-html=debug` — все полученные страницы (включая капчу) сохранятся вместе
с метаданными (`*.json`: прокси, код ответа, конечный URL, тип страницы), и
проверьте разбор сохранённой страницы:

```bash
php bin/yandex-sites.php --live --proxies=proxies.txt -q "пластиковые окна" --limit=1 --no-cache --save-html=debug -v
php bin/yandex-sites.php --parse-html=debug/пластиковые_окна-p1-…-serp.html
```

Команда показывает тип страницы (выдача, капча, пусто), найденные результаты и
признак следующей страницы — по ней удобно поправить `src/Live/HtmlResponseParser.php`.

Юридическая оговорка: автоматические запросы к странице поиска ограничены
пользовательским соглашением Яндекса; официальные пути — Yandex Search API и
XMLStock. Живой режим предназначен для небольших объёмов через собственные прокси
и с умеренной скоростью.

## Быстрый старт

```bash
# запросы из файла, настройки из config.php, результаты в out/
php bin/yandex-sites.php queries.example.txt

# XMLStock, две страницы по 50 результатов, регион Санкт-Петербург
php bin/yandex-sites.php --source=xmlstock --pages=2 --region=2 queries.txt

# живая выдача через прокси, 3 страницы (около 30 результатов на запрос)
php bin/yandex-sites.php --live --proxies=proxies.txt --pages=3 queries.txt

# зайти на каждый отобранный сайт браузером, сохранить HTML и скриншот
php bin/yandex-sites.php queries.txt --visit

# по три визита на сайт с разными прокси и User-Agent — увидеть разные версии страницы
php bin/yandex-sites.php queries.txt --visit --variants=3

# только первые 3 запроса, подробный вывод, все результаты с причинами отклонения
php bin/yandex-sites.php queries.txt --limit=3 --raw -v

# подготовка контента из скачанных страниц (out/pages → out/content + архив)
php bin/clean-content.php --brand-ru=криптобосс --brand-en=cryptoboss --brands=STAKE --zip=out/content.zip
```

По завершении в консоль выводится сводка: сколько запросов обработано, сколько
результатов отклонено и по каким правилам, первые отобранные сайты, статистика
по прокси и визитам, пути к файлам. С `-v` результаты печатаются по мере получения.

## Файл запросов

Один запрос на строку, пустые строки и строки с `#` пропускаются, дубли
удаляются. Допустимы операторы Яндекса, например `окна пвх site:msk.ru`.
Максимальная длина запроса — 400 символов.

## Настройка (`config.php`)

Файл возвращает массив; все ключи необязательны, пример с комментариями —
`config.example.php`. Разделы:

| Раздел | Что настраивает |
|--------|-----------------|
| `source` | источник выдачи: `api`, `xmlstock`, `live` |
| `api` | Yandex Search API: версия (`rest`/`xml`), доступ, пауза между запросами, повторы |
| `xmlstock` | адрес, доступ, домен поиска, устройство, дополнительные параметры |
| `proxies`, `proxy_file` | общий список прокси для живой выдачи и визитов (по кругу) |
| `live` | домен, паузы, попытки, паузы после капчи и ошибок, cookies, User-Agent |
| `search` | регион, число страниц, сайтов на странице (API/XMLStock), группировка, сортировка, свежесть |
| `cache` | каталог и время жизни кэша ответов |
| `filters` | правила отбора результатов; `own_markers` / `own_markers_file` — метки своих шаблонов («исключён как наш») |
| `site_check` | HTTP-проверка отобранных сайтов |
| `visit` | визиты на сайты: драйвер, число вариантов, прокси, Referer, скриншоты, каталог, обход шапки (`crawl`, `max_pages`, `similarity`) |
| `output` | каталог и имена файлов, разделитель CSV, BOM для Excel |

Параметры `--pages`, `--region`, `--groups`, `--delay`, `--out`, `--source`,
`--proxies`, `--visit-driver`, `--variants` в командной строке переопределяют
значения из файла.

## Правила отбора

Правила из раздела `filters` применяются к каждому результату выдачи;
результат отклоняется первым сработавшим правилом, причина попадает в сводку
и в `results.csv` (при `--raw`).

| Правило | Описание |
|---------|----------|
| `max_position` | учитывать только первые N результатов каждого запроса |
| `allowed_tlds` | разрешённые зоны, например `['ru', 'рф', 'su']`; пусто — любые |
| `include_domains` | если задано — берутся только эти домены (например, свои сайты для проверки позиций) |
| `exclude_domains` | исключения; по умолчанию — список агрегаторов, маркетплейсов, соцсетей, СМИ (`DefaultExclusions::LIST`) |
| `url_must_match`, `url_must_not_match` | регулярные выражения по URL страницы |
| `title_any`, `title_all`, `title_none` | хотя бы одно / все / ни одно из слов в заголовке |
| `snippet_any`, `snippet_none` | то же по заголовку, описанию и пассажам вместе |
| `unique_by` | считать сайтом хост (`host`, поддомены отдельно) или домен (`domain`; поддомены одного домена второй раз не берутся) |
| `domain_scope` | какие домены брать: `all` — любые, `root` — только корневые (`example.ru`), `subdomain` — только поддомены (`shop.example.ru`) |
| `min_queries` | сайт должен встретиться минимум в N разных запросах — отсекает случайные сайты |
| `min_hits` | минимальное число попаданий в выдачу |

Шаблоны доменов: `example.ru` — домен и поддомены, `*.example.ru` — только
поддомены, `=example.ru` — точное совпадение, `/^shop\d+\./i` — регулярное
выражение. Шаблоны текста — подстрока без учёта регистра или регулярное
выражение в разделителях (`'~окн[аы]~iu'`, для кириллицы нужен флаг `u`).
Шаблоны URL — только регулярные выражения.

Пример: найти сайты производителей, отбросив агрегаторы и форумы, и оставить
только те, что попали в выдачу минимум по двум запросам:

```php
'filters' => [
    'allowed_tlds' => ['ru', 'рф'],
    'exclude_domains' => [...DefaultExclusions::LIST, 'competitor.ru'],
    'url_must_not_match' => ['~/(forum|blog|news)/~i'],
    'title_none' => ['форум', 'отзывы', 'вакансии'],
    'min_queries' => 2,
],
```

## Проверка сайтов

Включается флагом `--check-sites` или `site_check.enabled = true`. Отобранные
сайты запрашиваются параллельно (`concurrency`), проверяются:

- код ответа (`require_status`, по умолчанию только 200; https, затем http);
  запрос идёт с User-Agent робота Яндекса (`site_check.user_agent`);
- редирект на другой домен (`reject_offsite_redirect`);
- наличие всех шаблонов на странице (`page_must_match`), например телефона
  `'~\+7[\s\-(]*\d{3}~u'` или ссылки `mailto:`;
- отсутствие шаблонов (`page_must_not_match`): «домен продаётся», «сайт заблокирован».

Страницы в windows-1251 и других кодировках перекодируются в UTF-8 перед
проверкой. Результат проверки попадает в колонки `check_*` CSV и в JSON.
Проверка отсеивает сайты; визиты (ниже) ничего не отсеивают, а сохраняют страницы.

## Визиты на сайты

Включается флагом `--visit` или `visit.enabled = true`. Для каждого отобранного
сайта открывается страница из выдачи (`target => 'found'`) или главная
(`'root'`) с Referer страницы выдачи Яндекса по тому запросу, где сайт был
найден (`referer => 'serp'`; варианты `'yandex'`, `'none'` или свой URL).

Драйверы:

- **playwright** — headless Chromium через `tools/render-page.js`: выполняется
  JavaScript, ждётся загрузка (`wait_ms`), сохраняются HTML после рендера и
  скриншот (`screenshot`, `full_page`). Нужны Node.js и Playwright:

  ```bash
  npm install playwright
  npx playwright install chromium
  node tools/render-page.js --check    # проверка окружения
  ```

  Если Chromium установлен в нестандартное место, укажите `visit.browser_path`.
- **curl** — обычный HTTP-запрос без JavaScript; используется, когда Playwright
  недоступен (`driver => 'auto'`), или принудительно (`--visit-driver=curl`).

User-Agent по умолчанию — робот Яндекса:
`Mozilla/5.0 (compatible; YandexBot/3.0; +http://yandex.com/bots)`. Так первый
визит показывает страницу такой, какой сайт отдаёт её поисковику. Тот же
User-Agent используется для HTTP-проверки сайтов. Переопределить его для визитов
и проверки можно флагом `--user-agent="…"` или в `visit.user_agents` /
`site_check.user_agent`. Для запросов к самой выдаче Яндекса всегда используются
браузерные User-Agent (`live.user_agents`): своему роботу Яндекс выдачу не отдаёт.
Часть сайтов проверяет робота по обратному DNS адреса, а не по строке
User-Agent, поэтому «версия для робота» может совпасть с обычной.

Прокси для визитов берутся по кругу из общего списка `proxies` / `proxy_file`
(`visit.proxy => 'list'`, по умолчанию; `null` — всегда напрямую, строка —
один конкретный прокси): каждый следующий визит идёт через следующий прокси.

Разные версии страницы. Параметр `variants` (`--variants=N`) открывает каждый
сайт N раз: первый визит — как робот Яндекса, следующие — как браузеры из
списка `visit.user_agents` (по одному на вариант), каждый через свой прокси. Для каждого визита считается
отпечаток видимого текста страницы; в CSV колонка `page_variants` показывает
«разных версий/визитов» (например, `2/3`), в JSON у сайта есть список `visits`
с адресом, прокси, User-Agent, кодом ответа, конечным URL, заголовком, путями
к файлам и отпечатком, а также число `variants`. Если у сайта `2/2` при
`--variants=2`, он показал роботу и посетителю разные страницы (клоакинг или
персонализация).

Файлы: `visit.dir/<хост>/variant-1.html`, `variant-1.png`, `variant-2.html`, …
Ограничить число посещаемых сайтов — `max_sites`, одновременность и паузы —
`concurrency`, `delay_ms`.

## Кэш и повторные запуски

Ответы сохраняются в `cache/<источник>/` (по умолчанию на 7 дней). Повторный
запуск с теми же запросами и параметрами не обращается к источнику, поэтому
фильтры можно подбирать без затрат. `--offline` запрещает обращения к источнику
(запросы вне кэша пропускаются с предупреждением), `--no-cache` отключает кэш,
`--dry-run` показывает список запросов и сколько обращений потребуется.

## Результаты

`sites.csv` / `sites.json` — по одной строке на сайт, отсортированы по числу
запросов, в которых сайт встретился, затем по лучшей позиции:

| Колонка | Содержимое |
|---------|------------|
| `host`, `host_unicode`, `domain` | хост, он же в Unicode для кириллических доменов, регистрируемый домен |
| `url`, `title` | страница и заголовок с лучшей позицией |
| `best_position`, `best_query` | лучшая позиция и запрос, в котором она достигнута |
| `queries_count`, `hits`, `queries` | число запросов, число попаданий, список «запрос (позиция)» |
| `check_status`, `check_final_url`, `check_title`, `check_result` | итог HTTP-проверки, если она включена |
| `page_file`, `page_final_url`, `page_title`, `page_variants` | сохранённая страница первого визита и число разных версий |

`domains.txt` — просто список хостов для передачи в другие инструменты.
`results.csv` (флаг `--raw`) — все результаты выдачи с причиной отклонения.
В `sites.json` также сохраняются статистика прогона, ошибки, статистика прокси
и использованные настройки.

## Параметры командной строки

```
php bin/yandex-sites.php [опции] [queries.txt ...]

--queries=FILE        файл с запросами (можно несколько раз); файлы можно передавать и без опции
-q, --query="…"       запрос из командной строки (можно несколько раз)
--limit=N             обработать только первые N запросов
--source=api|xmlstock|live   источник выдачи;  --live — то же, что --source=live
--proxies=FILE        файл со списком прокси (общий для живой выдачи и визитов)
--proxy=АДРЕС         добавить прокси, например http://host:port:user:pass (можно несколько раз)
--check-proxies       проверить каждый прокси одним запросом к живой выдаче и выйти
--save-html=DIR       сохранять все страницы живой выдачи (и капчу) с метаданными для отладки
-c, --config=FILE     файл конфигурации (по умолчанию ./config.php, если есть)
-o, --out=DIR         каталог результатов (по умолчанию out/)
--pages=N             страниц выдачи на запрос
--groups=N            сайтов на странице для API/XMLStock, 1–100
--region=ID           регион поиска (213 — Москва, 2 — Санкт-Петербург, 225 — Россия)
--delay=MS            пауза между обращениями к источнику
--check-sites         HTTP-проверка отобранных сайтов
--visit               визиты на отобранные сайты с сохранением HTML и скриншотов
--visit-driver=X      playwright | curl | auto
--variants=N          визитов на сайт: первый — как робот Яндекса, следующие — как браузеры (и разные прокси)
--user-agent="…"      свой User-Agent для визитов и проверки сайтов вместо YandexBot
--raw                 записать все результаты с причинами отклонения
--no-cache            не использовать кэш
--offline             работать только по кэшу
--parse-html=FILE     разобрать сохранённую страницу живой выдачи (отладка)
--dry-run             показать запросы и настройки, ничего не запрашивать
-v, --verbose         подробный вывод;  --quiet — только ошибки
-h, --help            справка;  --version — версия
```

Коды выхода: 0 — успех, 1 — прогон прерван фатальной ошибкой источника
(результаты по обработанным запросам всё равно сохраняются), 2 — ошибка в
аргументах или конфигурации.

## Пробный запуск без ключей и прокси

В комплекте есть фейковый сервер, который изображает все три источника и
несколько «сайтов»:

```bash
FAKE_MODE=local php -S 127.0.0.1:8089 tests/fake-api-server.php &

# Yandex Search API
YANDEX_FOLDER_ID=demo YANDEX_API_KEY=demo \
YANDEX_REST_ENDPOINT=http://127.0.0.1:8089/v2/web/search \
php bin/yandex-sites.php -q "пластиковые окна" --no-cache -v

# живая выдача (домен поиска указывает на фейковый сервер) и визиты браузером
YANDEX_LIVE_DOMAIN=http://127.0.0.1:8089 \
php bin/yandex-sites.php --live -q "пластиковые окна" --pages=2 --delay=0 --no-cache -v

# XMLStock
XMLSTOCK_USER=demo XMLSTOCK_KEY=demo XMLSTOCK_ENDPOINT=http://127.0.0.1:8089/yandex/xml/ \
php bin/yandex-sites.php --source=xmlstock -q "пластиковые окна" --no-cache
```

Переменные `YANDEX_REST_ENDPOINT`, `YANDEX_XML_ENDPOINT`, `XMLSTOCK_ENDPOINT`
и `YANDEX_LIVE_DOMAIN` переопределяют адреса источников (пригодятся и для
прокси-шлюзов). Визиты в демо-режиме на «сайты» фейкового сервера не попадут:
адреса вида `http://okna-moskva.ru:8089/` нужно направить на 127.0.0.1 через
`visit.resolve` (см. `tests/IntegrationTest.php`).

## Обработка ошибок и лимитов

- Временные ошибки API (HTTP 429, 5xx, сетевые, код 55 «превышена частота»)
  повторяются с нарастающей задержкой (`api.retries`, `api.retry_delay_ms`).
- Фатальные ошибки (неверный ключ, HTTP 401/403, исчерпан лимит — код 32,
  закончились прокси в живой выдаче) останавливают прогон; уже собранные
  результаты сохраняются.
- Ошибка по отдельному запросу пропускает только этот запрос; после
  `search.max_consecutive_errors` ошибок подряд прогон останавливается.

## Разработка

```bash
php tests/lint.php   # проверка синтаксиса
php tests/run.php    # тесты (юнит + сквозные через фейковый сервер; тест Playwright пропускается без Node.js)
```

Структура:

```
bin/yandex-sites.php        точка входа CLI
tools/render-page.js        Node.js + Playwright: открывает страницы в Chromium, сохраняет HTML и скриншоты
src/Cli/Application.php     разбор аргументов, сборка зависимостей, сводка
src/Config.php              значения по умолчанию, config.php, .env, проверка
src/Runner.php              конвейер: запросы → выдача → фильтры → сайты → проверка → визиты
src/Search/                 Yandex Search API v2/v1, XMLStock, парсер XML, кэш, ошибки
src/Live/                   живая выдача: запросы через прокси, список прокси, разбор HTML-страницы
src/Visit/                  визиты на сайты: драйверы Playwright и curl, отпечаток страницы
src/Filter/                 правила отбора, шаблоны доменов и текста, список исключений
src/Check/                  параллельная HTTP-проверка сайтов
src/Output/ReportWriter.php CSV, JSON, список доменов
tests/                      тесты, фикстуры, фейковый сервер
```

Чтобы подключить другой источник выдачи, реализуйте `RawFetcherInterface`
(сырой ответ по запросу и странице) и, если формат не Яндекс.XML,
`ResponseParserInterface`, затем передайте их в `Runner`.
