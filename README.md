# yandex-sites

Скрипт на PHP, который прогоняет список поисковых запросов через официальный
**Yandex Search API** (Yandex Cloud), собирает сайты из выдачи и отбирает нужные
по настраиваемым правилам:

- доменные зоны (`ru`, `рф`, …), чёрные и белые списки доменов;
- слова и регулярные выражения в заголовке и сниппете;
- регулярные выражения по URL;
- минимальное число запросов, в выдаче которых встретился сайт;
- опциональная HTTP-проверка самих сайтов: код ответа, редиректы на чужой домен,
  наличие или отсутствие текста на странице (телефон, «домен продаётся» и т. п.).

Результат — `sites.csv` (открывается в Excel), `sites.json` и `domains.txt`.
Ответы API кэшируются, поэтому фильтры можно менять и перезапускать отбор без
повторных обращений к API.

## Почему официальный API, а не разбор HTML yandex.ru

Автоматические запросы к обычной выдаче Яндекса быстро упираются в капчу,
нарушают пользовательское соглашение и ломаются при каждом изменении вёрстки.
Yandex Search API отдаёт ту же выдачу в стабильном XML-формате, работает
с лимитом 10 запросов в секунду и тарифицируется по числу запросов.
Скрипт поддерживает API v2 (REST, по умолчанию) и устаревший API v1 (XML).

## Требования

- PHP 8.1 или новее с расширениями `curl`, `dom`, `json`, `mbstring`
  (`intl` желательно для кириллических доменов в фильтрах).
- Доступ к Yandex Search API: идентификатор каталога и API-ключ сервисного аккаунта.
- Composer не обязателен: сторонних зависимостей нет, автозагрузка встроена.

## Установка

```bash
git clone https://github.com/alexnefera-dot/cladue.git
cd cladue
cp config.example.php config.php   # правила отбора и параметры поиска
cp .env.example .env               # доступ к API
```

В `.env` впишите `YANDEX_FOLDER_ID` и `YANDEX_API_KEY`. Вместо `.env` можно
задать те же переменные окружения или заполнить раздел `api` в `config.php`.

## Доступ к Yandex Search API

1. В консоли Yandex Cloud выберите каталог — его идентификатор и есть `YANDEX_FOLDER_ID`.
2. Создайте сервисный аккаунт и назначьте ему роль `search-api.webSearch.user`.
3. Создайте для сервисного аккаунта API-ключ — это `YANDEX_API_KEY`.
   Вместо ключа можно использовать IAM-токен (`YANDEX_IAM_TOKEN`), но он живёт 12 часов.
4. Сервис платный и тарифицируется по количеству запросов. Один запрос —
   одна страница выдачи (до 100 сайтов). Квоты: 10 запросов в секунду,
   10 000 синхронных запросов в час, не более 250 результатов на запрос.

Документация: <https://yandex.cloud/ru/docs/search-api/>.

## Быстрый старт

```bash
# запросы из файла, настройки из config.php, результаты в out/
php bin/yandex-sites.php queries.example.txt

# две страницы выдачи на запрос, регион Санкт-Петербург, проверить сайты по HTTP
php bin/yandex-sites.php --queries=queries.txt --pages=2 --region=2 --check-sites

# запросы прямо из командной строки, результаты в другой каталог
php bin/yandex-sites.php -q "пластиковые окна москва" -q "остекление балконов" --out=result

# только первые 3 запроса, подробный вывод, все результаты с причинами отклонения
php bin/yandex-sites.php queries.txt --limit=3 --raw -v
```

По завершении в консоль выводится сводка: сколько запросов обработано, сколько
результатов отклонено и по каким правилам, первые отобранные сайты и пути к файлам.

## Файл запросов

Один запрос на строку, пустые строки и строки с `#` пропускаются, дубли
удаляются. Допустимы операторы Яндекса, например `окна пвх site:msk.ru`.
Максимальная длина запроса — 400 символов.

## Настройка (`config.php`)

Файл возвращает массив; все ключи необязательны, пример с комментариями —
`config.example.php`. Основные разделы:

| Раздел | Что настраивает |
|--------|-----------------|
| `api` | версия API (`rest`/`xml`), доступ, пауза между запросами (`delay_ms`), повторы при временных ошибках (`retries`) |
| `search` | регион (`region`, 213 — Москва, 2 — Санкт-Петербург, 225 — Россия), число страниц (`pages`), сайтов на странице (`groups_on_page`, до 100), группировка по домену, сортировка, свежесть (`period`) |
| `cache` | каталог и время жизни кэша ответов API |
| `filters` | правила отбора результатов (см. ниже) |
| `site_check` | HTTP-проверка отобранных сайтов |
| `output` | каталог и имена файлов, разделитель CSV, BOM для Excel |

Параметры `--pages`, `--region`, `--groups`, `--delay`, `--out` в командной
строке переопределяют значения из файла.

## Правила отбора

Правила из раздела `filters` применяются к каждому результату выдачи;
результат отклоняется первым сработавшим правилом, причина попадает в сводку
и в `results.csv` (при `--raw`).

| Правило | Описание |
|---------|----------|
| `max_position` | учитывать только первые N результатов каждого запроса |
| `allowed_tlds` | разрешённые зоны, например `['ru', 'рф', 'su']`; пусто — любые |
| `include_domains` | если задано — берутся только эти домены (например, свои сайты для проверки позиций) |
| `exclude_domains` | исключения; по умолчанию — список агрегаторов, маркетплейсов, соцсетей, СМИ (`DefaultExclusions::LIST`) |
| `url_must_match`, `url_must_not_match` | регулярные выражения по URL страницы |
| `title_any`, `title_all`, `title_none` | хотя бы одно / все / ни одно из слов в заголовке |
| `snippet_any`, `snippet_none` | то же по заголовку, описанию и пассажам вместе |
| `unique_by` | считать сайтом хост (`host`, поддомены отдельно) или домен (`domain`) |
| `min_queries` | сайт должен встретиться минимум в N разных запросах — отсекает случайные сайты |
| `min_hits` | минимальное число попаданий в выдачу |

Шаблоны доменов: `example.ru` — домен и поддомены, `*.example.ru` — только
поддомены, `=example.ru` — точное совпадение, `/^shop\d+\./i` — регулярное
выражение. Шаблоны текста — подстрока без учёта регистра или регулярное
выражение в разделителях (`'~окн[аы]~iu'`, для кириллицы нужен флаг `u`).
Шаблоны URL — только регулярные выражения.

Пример: найти сайты производителей, отбросив агрегаторы и форумы, и оставить
только те, что попали в выдачу минимум по двум запросам:

```php
'filters' => [
    'allowed_tlds' => ['ru', 'рф'],
    'exclude_domains' => [...DefaultExclusions::LIST, 'competitor.ru'],
    'url_must_not_match' => ['~/(forum|blog|news)/~i'],
    'title_none' => ['форум', 'отзывы', 'вакансии'],
    'min_queries' => 2,
],
```

## Проверка сайтов

Включается флагом `--check-sites` или `site_check.enabled = true`. Отобранные
сайты запрашиваются параллельно (`concurrency`), проверяются:

- код ответа (`require_status`, по умолчанию только 200; https, затем http);
- редирект на другой домен (`reject_offsite_redirect`);
- наличие всех шаблонов на странице (`page_must_match`), например телефона
  `'~\+7[\s\-(]*\d{3}~u'` или ссылки `mailto:`;
- отсутствие шаблонов (`page_must_not_match`): «домен продаётся», «сайт заблокирован».

Страницы в windows-1251 и других кодировках перекодируются в UTF-8 перед
проверкой. Результат проверки попадает в колонки `check_*` CSV и в JSON.

## Кэш и повторные запуски

Ответы API сохраняются в `cache/` (по умолчанию на 7 дней). Повторный запуск
с теми же запросами и параметрами поиска не обращается к API, поэтому фильтры
можно подбирать без затрат. `--offline` запрещает обращения к API (запросы вне
кэша пропускаются с предупреждением), `--no-cache` отключает кэш, `--dry-run`
показывает список запросов и сколько обращений к API потребуется.

## Результаты

`sites.csv` / `sites.json` — по одной строке на сайт, отсортированы по числу
запросов, в которых сайт встретился, затем по лучшей позиции:

| Колонка | Содержимое |
|---------|------------|
| `host`, `host_unicode`, `domain` | хост, он же в Unicode для кириллических доменов, регистрируемый домен |
| `url`, `title` | страница и заголовок с лучшей позицией |
| `best_position`, `best_query` | лучшая позиция и запрос, в котором она достигнута |
| `queries_count`, `hits`, `queries` | число запросов, число попаданий, список «запрос (позиция)» |
| `check_status`, `check_final_url`, `check_title`, `check_result` | итог HTTP-проверки, если она включена |

`domains.txt` — просто список хостов для передачи в другие инструменты.
`results.csv` (флаг `--raw`) — все результаты выдачи с причиной отклонения.
В `sites.json` также сохраняются статистика прогона, ошибки и использованные настройки.

## Параметры командной строки

```
php bin/yandex-sites.php [опции] [queries.txt ...]

--queries=FILE      файл с запросами (можно несколько раз); файлы можно передавать и без опции
-q, --query="…"     запрос из командной строки (можно несколько раз)
--limit=N           обработать только первые N запросов
-c, --config=FILE   файл конфигурации (по умолчанию ./config.php, если есть)
-o, --out=DIR       каталог результатов (по умолчанию out/)
--pages=N           страниц выдачи на запрос
--groups=N          сайтов на странице, 1–100
--region=ID         регион поиска
--delay=MS          пауза между обращениями к API
--check-sites       HTTP-проверка отобранных сайтов
--raw               записать все результаты с причинами отклонения
--no-cache          не использовать кэш
--offline           работать только по кэшу
--dry-run           показать запросы и настройки, ничего не запрашивать
-v, --verbose       подробный вывод;  --quiet — только ошибки
-h, --help          справка;  --version — версия
```

Коды выхода: 0 — успех, 1 — прогон прерван фатальной ошибкой API
(результаты по обработанным запросам всё равно сохраняются), 2 — ошибка в
аргументах или конфигурации.

## Пробный запуск без ключа

В комплекте есть фейковый сервер API, который отдаёт правдоподобную выдачу:

```bash
php -S 127.0.0.1:8089 tests/fake-api-server.php &
YANDEX_FOLDER_ID=demo YANDEX_API_KEY=demo \
YANDEX_REST_ENDPOINT=http://127.0.0.1:8089/v2/web/search \
php bin/yandex-sites.php -q "пластиковые окна" -q "остекление балконов" --no-cache --raw -v
```

Переменные `YANDEX_REST_ENDPOINT` и `YANDEX_XML_ENDPOINT` переопределяют адреса
API (пригодятся и для прокси).

## Обработка ошибок и лимитов

- Временные ошибки (HTTP 429, 5xx, сетевые, код 55 «превышена частота»)
  повторяются с нарастающей задержкой (`api.retries`, `api.retry_delay_ms`).
- Фатальные ошибки (неверный ключ, HTTP 401/403, исчерпан лимит — код 32)
  останавливают прогон; уже собранные результаты сохраняются.
- Ошибка по отдельному запросу (например, некорректный текст) пропускает
  только этот запрос и записывается в `sites.json`.

## Разработка

```bash
php tests/lint.php   # проверка синтаксиса
php tests/run.php    # тесты (юнит + сквозные через фейковый сервер API)
```

Структура:

```
bin/yandex-sites.php        точка входа CLI
src/Cli/Application.php     разбор аргументов, сборка зависимостей, сводка
src/Config.php              значения по умолчанию, config.php, .env, проверка
src/Runner.php              конвейер: запросы → выдача → фильтры → сайты → проверка
src/Search/                 клиенты API v2 (REST) и v1 (XML), парсер XML, кэш, ошибки
src/Filter/                 правила отбора, шаблоны доменов и текста, список исключений
src/Check/                  параллельная HTTP-проверка сайтов
src/Output/ReportWriter.php CSV, JSON, список доменов
tests/                      тесты, фикстуры, фейковый сервер API
```

Чтобы подключить другой источник выдачи, реализуйте `XmlFetcherInterface`
(метод `fetch(string $query, int $page): string`, возвращающий XML в формате
Яндекса) и передайте его в `Runner`.
