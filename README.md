# Site Migrator — переезды сайтов в один интерфейс

Локальное веб-приложение, которое автоматизирует переезд бренда на новый домен:
создаёт сайт на сервере, переносит файлы, поднимает домен в Cloudflare, прописывает
NS у регистратора, выпускает SSL, привязывает воркер, ставит 301-редиректы со старых
зеркал и подтверждает права в Яндекс.Вебмастере.

Запускается локально (`python app.py`) и открывается в браузере. Управление — вкладки-проекты
и кнопки. Единственный шаг, который остаётся руками — клик **«Переезд»** в Яндекс.Вебмастере
(его нет в API).

---

## Что делает (полный пайплайн)

Кнопка **«Поднять новый домен»** выполняет по порядку:

| # | Шаг | Где |
|---|-----|-----|
| 1 | Создаёт сайт (webdomain, PHP CGI 7.4, без серверного SSL) | ISPmanager (SSH) |
| 2 | Копирует файлы из папки донора и меняет домен в `robots.txt` / `sitemap.xml` / `.htaccess` | сервер (SSH) |
| 3 | Создаёт зону, A-записи `@`/`www`, SSL=Full, Always HTTPS, NS → регистратор | Cloudflare + Spaceship |
| 4 | Выпускает Let's Encrypt-сертификат | ISPmanager (SSH) |
| 5 | Привязывает существующий воркер к новому домену (`домен/*`) | Cloudflare |

Кнопка **«Переезд зеркал»** ставит на каждом старом зеркале 301-редирект `всё → https://новый-домен`
(с сохранением query-строки), заменяя прежние правила.

Кнопка **«Яндекс: подтвердить»** добавляет новый домен в Вебмастер и подтверждает права
(по DNS — автоматически через Cloudflare; HTML/мета — показывает, что разместить).

Кнопка **«Проверить статус»** показывает по каждому зеркалу: есть ли зона в Cloudflare и куда
сейчас ведёт редирект.

Любой шаг можно запустить отдельно (блок «Отдельные шаги») — удобно для повторов и отладки.
Галочка **«тест (dry-run)»** показывает, что будет сделано, без реальных изменений.

> **Остаётся вручную:** клик «Переезд» (смена главного зеркала) в Яндекс.Вебмастере — в API его нет.
> Яндекс определяет зеркала по 301-редиректу, так что основную работу делает приложение.

## Установка и запуск

```bash
git clone https://github.com/alexnefera-dot/cladue.git
cd cladue
pip install -r requirements.txt     # единственная зависимость — paramiko (SSH)
python app.py                       # откроет http://127.0.0.1:8765
```

Нужен Python 3.8+. Остановить — Ctrl+C. Опции: `python app.py --port 9000 --no-browser`.

## Настройки (кнопка ⚙)

Хранятся локально в `data/settings.json` (каталог `data/` в `.gitignore`, в репозиторий не
попадает). Секреты в браузер не отдаются; при сохранении пустые поля **не затирают** уже
сохранённые значения — можно менять один параметр, не вводя остальные заново.

### Cloudflare-аккаунты

Добавьте оба аккаунта (со старыми зеркалами и с новыми доменами). Для каждого:

- **API-токен** — Cloudflare Dashboard → My Profile → API Tokens → Create Custom Token. Права:
  `Zone:Read`, `Zone:Edit`, `DNS:Edit`, `Zone Settings:Edit`, `Single Redirect (Dynamic Redirect):Edit`,
  `Workers Routes:Edit`, `Bot Management:Edit`. Zone Resources → All zones.
- **account_id** — Dashboard → выбрать аккаунт → Account ID в правом сайдбаре.
- **Spaceship key/secret** — [spaceship.com → API Manager](https://www.spaceship.com/application/api-manager/)
  (нужны только для аккаунта, где поднимаются новые домены, чтобы прописать NS).

### Сервер (SSH + ISPmanager)

SSH host/порт/логин/пароль, отдельно логин/пароль ISPmanager (если отличаются), host панели
(обычно тот же IP), email для Let's Encrypt и IP сервера для A-записей (по умолчанию `5.45.75.15`).

### Яндекс.Вебмастер — OAuth-токен

1. [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) → создать приложение.
   Платформа: **Веб-сервисы**, Redirect URI: `https://oauth.yandex.ru/verification_code`.
   Доступы: **«Добавление сайтов и управление ими»** и **«Подтверждение прав владельца»**
   (`webmaster:hostadd`, `webmaster:verify`).
2. Возьмите `ClientID` и откройте в браузере:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID`
3. Подтвердите доступ — в адресной строке появится `access_token=…`. Это и есть токен.
4. Вставьте его в Настройки → Яндекс.

## Проект (вкладка) и рабочий процесс

В проекте указываются:

- **Новый (целевой) домен** — куда переезжаем.
- **CF-аккаунт нового домена** — где создаётся зона, воркер и TXT для Яндекса.
- **Воркер** — имя уже существующего воркера в Cloudflare (создавать заново не нужно).
- **Домен-донор** — рабочее зеркало бренда, из папки которого копируются файлы;
  его домен и заменяется на новый в `robots.txt`/`sitemap.xml`/`.htaccess`.
- **Старые зеркала** — список доменов, у каждого свой CF-аккаунт (как колонка «Профиль» в CSV).
- **Способ подтверждения в Яндексе** — DNS (рекомендуется) / HTML / мета.

Типичный порядок:

1. **«Поднять новый домен»** (сначала можно с галочкой dry-run для проверки).
2. **«Яндекс: подтвердить»** — добавит домен и подтвердит права.
3. Вручную: клик **«Переезд»** в Яндекс.Вебмастере.
4. **«Переезд зеркал»** — 301 со всех старых доменов на новый.
5. **«Проверить статус»** — убедиться, что редиректы встали.

## Заметки

- **SSL (Let's Encrypt)** настроен под ISPmanager 6 и помечен как экспериментальный: точный набор
  полей API LE зависит от версии панели. Первый живой запуск стоит сделать с `-v`/dry-run — если
  шаг вернёт ошибку, по тексту ответа панели его легко доточить. HTTPS для посетителей при этом уже
  обеспечивает Cloudflare (SSL=Full), так что переезд не блокируется.
- **Повторный запуск безопасен:** зона создаётся идемпотентно, воркер-роут обновляется по pattern,
  правило редиректа перезаписывается.
- **Два аккаунта:** один — только редиректы старых зеркал, второй — новые домены (зона, воркер,
  Яндекс) и тоже редиректы. В приложении аккаунт нового домена задаётся на проект, аккаунт зеркала — у каждого зеркала.

## Структура

```
cladue/
├── app.py                  # запуск приложения (локальный веб-сервер)
├── requirements.txt        # paramiko (остальное — стандартная библиотека)
├── migrator/               # интеграции (общие для приложения и CLI migrate.py)
│   ├── http.py             # HTTP-клиент на urllib
│   ├── domains.py          # нормализация доменов
│   ├── cloudflare.py       # зоны, DNS, настройки, воркер-роуты, редиректы
│   ├── spaceship.py        # NS у регистратора
│   ├── ispmanager.py       # SSH + ISPmanager: сайт, файлы, замена домена, LE
│   └── yandex.py           # Вебмастер: добавление хоста и подтверждение прав
├── webapp/                 # веб-приложение
│   ├── server.py           # HTTP-сервер: статика + JSON-API
│   ├── store.py            # проекты и настройки в data/*.json (с маскированием секретов)
│   ├── service.py          # оркестрация шагов переезда
│   └── static/             # index.html, style.css, app.js
└── data/                   # проекты и настройки (создаётся при работе; в .gitignore)
```

`migrate.py` — прежний CLI для одиночных/пакетных редиректов из CSV — остаётся рабочим
(см. историю файла), но основной интерфейс теперь приложение.
